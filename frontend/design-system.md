# dart-insight 디자인 시스템 및 UI 디자인 가이드

dart-insight의 정기공시 비교 서비스를 위한 UI 구성과 디자인 시스템 기준을 정의한다.

> 화면 구성과 흐름은 노션 [사용자 흐름·화면 와이어프레임](https://app.notion.com/p/c0f540f74d92496c9c20f23867afc15a)을 따른다. 이 문서는 그 화면을 만들 때 쓰는 글꼴·간격·컴포넌트·상태 기준을 정한다.
>
> 시각 디자인의 기준은 이해진 님의 Figma 파일 [신한 2차 프로젝트 › 디자인](https://www.figma.com/design/1LurlBehXtoSjipfsAAsUv/%EC%8B%A0%ED%95%9C-2%EC%B0%A8-%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8?node-id=5-2)이다. 값은 Figma와 코드(`frontend/src/shared/styles/tokens.css`) 두 곳에만 두고, 이 문서에는 무엇을 왜 그렇게 정했는지와 화면이 지켜야 할 규칙만 적는다. 범위는 노션 [기능 명세·WBS](https://app.notion.com/p/3ffb6afffc6f80179ffbfd4817a5aaa0), 작업은 [GitHub Issues](https://github.com/ShinhanDSProject/dart-insight/issues)를 기준으로 한다.

# 1. 디자인 시스템 목적

dart-insight는 **같은 기업의 두 정기보고서**를 비교해, 바뀐 재무 수치와 문장을 DART 원문 근거와 함께 보여 준다. 여러 기업을 나란히 비교하는 서비스가 아니다.

디자인 시스템은 다음을 기준으로 한다.

- 전체 화면의 디자인 일관성 유지
- 이전 보고서와 현재 보고서의 차이가 한눈에 보이는 구성
- 모든 수치·문장에서 원문 근거로 바로 이동할 수 있는 정보 구조
- 증가·감소 표시와 좋음·나쁨 평가를 섞지 않는 표현
- 로딩·실패·계산 불가·검토 필요 같은 상태를 숨기지 않는 표시
- Figma 디자인과 실제 개발 화면의 일관성 유지

# 2. 화면 구성

MVP는 개인 사용자가 로그인 없이 쓰는 흐름이다. 화면 번호는 와이어프레임과 GitHub 이슈의 '관련 화면'과 같다.

```text
W-01 ① 기업 검색
 ↓
W-01 ② 보고서 선택
 ↓
W-01 ③ 비교 검증 ── 비교할 수 없으면 사유 표시 후 ②로
 ↓
W-02 분석 진행 ── 실패하면 사유와 다시 요청
 ↓
W-03 ①~③ 분석 결과 (요약·설명 / 재무 수치 변화 / 문장·내용 변화)
 ↓
W-03 ④ 원문 확인
```

## 2-1. W-01 ① 기업 검색

- 회사명 또는 종목코드 검색
- 검색 결과 목록: 회사명, 종목코드, 시장 구분
- 검색 결과 없음 상태와 다시 검색하는 방법
- 검색 전 첫 화면은 큰 로고(`BrandLogo size="lg"`, 화면 제목 h1)와 둥근 검색창(오른쪽 남색 '검색')만 화면 가운데에 둔다(#549, #560, FS-67). 900px 이하에서는 펼침 상자와 화면 키보드가 함께 보이도록 위쪽에 둔다. 입력 안내 글은 화면 읽기 도구에만 읽힌다.
- 빈 검색창에 초점이 있으면 바로 아래 펼침 상자(`.search-drop`, 흰 바탕·1px 테두리·모서리 12·`--shadow-md`, 본문을 밀지 않고 떠 있음, `.search-form:focus-within`으로 보임, Esc로 닫고 다시 누르거나 입력하면 열림)가 열린다(#560, FS-67): 최근 본 분석(5개, '더 보기'), 자주 찾는 기업 칩(로그인 전에는 '관심 기업의 새 공시는 로그인하면 여기에 모여요 · 로그인' 한 줄), '이렇게 찾아보세요' 예시 칩 3개, 구분선 아래 '둘러보기 · 새 공시·시즌 변화·대표 기업 →'와 '처음이신가요? 사용법 보기'. 상자 안을 눌러도 입력창 초점을 지킨다(`mousedown` 막음). 글자를 입력하면 그리지 않는다.
- 둘러보기(`/explore`, `Page`·`PageHeader`): '★ 자주 찾는 기업 (즐겨찾기) N' 카드(관심 기업 칩·×·'나란히 보기'·'+ 기업 추가'는 첫 화면으로, 로그인 전엔 로그인 안내 한 줄)와 탭 보드(관심 기업 새 공시·이번 시즌 변화·대표 기업, `?tab=`). 예전 첫 화면 주소 `/?tab=`는 여기로 보낸다. 이용 안내는 하단 바에서 연다.
- 검색 결과는 '검색 결과 N곳' 카드 안에 둔다(결과 없음도 같은 카드). 카드 아래 정보 안내 상자로 다음 단계를 알린다.
- 결과 한 행은 행 전체가 링크다: 왼쪽에 회사명(검색어 강조)·관심 기업 별·상장 배지·같은 이름 안내와 그 아래 종목코드·고유번호, 오른쪽에 '기업 선택 →'(글자). 업종·한 줄 설명은 검색 API에 없어 두지 않는다. 처음엔 10곳만 보이고 아래에 '더 보기 (N개)'를 둔다(4-15). 접힌 행은 그리지 않아 ↓·End로도 가지 않는다.

## 2-2. W-01 ② 보고서 선택

- 기업 화면 '보고서 비교' 탭. 제목 '비교할 보고서 두 건을 선택하세요'와 오른쪽 '기업 변경'(보조 버튼, 첫 화면)(#549)
- 비교 기준 선택: 전년 동기 / 직전 기간 / 직접 선택
- 이전 보고서(왼쪽)와 현재 보고서(오른쪽, 기본은 최신) 카드 두 장(`ReportCard`). 카드 안에 고르기 칸과 '보고서 자세히'
- '정기보고서 목록' 패널(개수 배지) 안 표, 아래 주의 안내 상자, 오른쪽 아래 주 버튼 '선택한 보고서 비교 확인 →'
- 보고서 목록: 보고서 유형, 대상 기간, 제출일, 정정 여부, 자료 상태
- 정정 여부를 확인하지 못하면 '확인 안 됨', 자료가 없으면 '자료 준비 중'

## 2-3. W-01 ③ 비교 검증

- 화면 머리 오른쪽 위 상태 배지: '분석 준비'(보라) / '비교 불가'(분홍)(#549). 그 아래 이전·현재 보고서 카드 두 장
- 확인 항목: 기업, 보고서 종류·기간, 수치 기준(연결·단위), 정정 여부, 자료 준비. '비교 조건' 패널의 표이고 결과는 행 오른쪽 배지(확인됨 회색, 주의 노랑, 비교 불가 분홍)
- 비교 가능 안내(정보 상자)와 '보고서 다시 선택'(왼쪽) / '분석 실행'(오른쪽)
- 비교할 수 없을 때: 진행 불가 안내 상자에 사유와 다음 행동, '분석 실행'은 보이되 비활성. 분석을 시작하지 않는다.

## 2-3-1. 여러 기업 나란히 보기 (FS-56, #412)

- 경로 `/compare/companies?corps=고유번호,…&type=ANNUAL&fs=CFS`. 고른 기업·순서·보고서 종류·재무제표 기준을 주소에 두어 같은 주소로 같은 비교를 다시 연다. 왼쪽 메뉴 '기업 나란히 보기'와 기업 개요 탭 위 '다른 기업과 나란히 보기'(그 기업을 미리 고름)로 들어온다.
- 위 패널 '비교할 기업': 고른 기업(고른 순서, 알약 모양 + 빼기 아이콘 버튼), 작은 검색 칸(2자 이상, 입력을 멈추면 찾음, 결과 8곳까지 '더하기'), 로그인했으면 관심 기업 칩(누르면 더하거나 뺌). 4곳이 차 있을 때 더하면 아무것도 바꾸지 않고 검색 칸 아래에 '최대 4곳까지 비교할 수 있어요.'(주의 색 글자, `role="status"`)를 보인다.
- 아래 패널 '주요 수치': 2곳보다 적으면 표 대신 고르는 방법 안내(EmptyState). 표(DataTable dense)는 행이 주요계정 6개(매출액·영업이익·당기순이익·자산총계·부채총계·자본총계, 원 · 조·억으로 줄여 표시) → 비율 4개(`shared/lib/financialRatios.ts`, 소수 첫째 자리 %), 열은 고른 순서의 기업이다. **정렬 버튼·순위·최고·최저 강조·좋음·나쁨 문구를 두지 않는다**(결정 로그 '열 정렬 허용 여부', 잠정). 값은 모두 같은 글자색이다.
- 열 머리글: 기업 이름, 보고서 이름, 대상 기간(`periodLabel`), 근거 접수번호(정정 공시 값이면 그 번호)와 DART 원문 링크(`DartLinkInline`). 기업마다 대상 기간 끝이 다르면 표 위에 주의 안내 '대상 기간이 달라요 · 기업마다 표시한 기간을 확인해 주세요'를 두고 열마다 기간을 그대로 보인다.
- 열 하나의 상태는 그 열 전체(첫 행에서 아래로 합친 칸)에 적고 다른 열은 그대로 둔다: 불러오는 중, '불러오지 못했어요' + '다시 시도'(그 기업만 다시 부름), '고른 종류의 보고서가 없어요' + 다른 종류를 고르라는 안내, 값이 모두 없으면 '고른 종류 보고서의 주요계정 값이 없어요'. 없는 계정은 0이 아니라 '자료 없음', 계산하지 못한 비율은 '계산 불가 · 사유'(흐린 글자).

- 화면이 흔들리지 않게(#424): 검색 결과는 입력칸 아래에 떠서 보이고(더하면 비우고 닫음, Esc·바깥 누르면 닫음), 표는 늘 항목 + 기업 4칸의 고정 폭(`table-layout: fixed`)이며 고르지 않은 자리는 빈 열로 둔다. 머리글은 높이를 정해 불러오는 중과 다 받은 뒤가 같고, 안내·기간 다름 경고는 두 줄 높이의 같은 자리에 둔다.
- 키보드로 고르기(#426): 입력칸에서 ↓로 결과의 '더하기'에 가고 ↑↓·Home·End로 옮기며 Enter로 더한다(첫 화면 검색과 같은 방식). 첫 결과에서 ↑와 Esc는 입력칸으로 돌아오고, 더한 뒤에도 초점은 입력칸에 남아 이어서 찾는다. 이미 고른 기업은 건너뛴다.

## 2-4. W-02 분석 진행

- 화면 머리 상태 배지: '대기 중'·'분석 중'(보라) / '완료'(회색) / '분석 실패'(분홍)(#549). 그 아래 이전·현재 보고서 카드 두 장
- 단계 카드: 요청 접수 → 보고서 비교 → 근거 확인 → 완료(서버가 주는 단계 그대로, 5-4)와 진행 막대(`ProgressBar`)
- 실패 시 진행 불가 안내 상자에 사유·사유 코드, 아래 '보고서 다시 선택'(왼쪽) / '↻ 분석 실행'(오른쪽, 다시 시도할 수 있을 때만). 완료 시 '결과 보기'

## 2-5. W-03 분석 결과

결과 머리(#550): 브레드크럼 '분석 결과 / 기업명' → 큰 기업명 → 한 줄 '이전 보고서 → 현재 보고서 · 비교 기준 · 연결(별도)재무제표 · 보고서 바꾸기(보고서 선택 화면 링크)', 오른쪽 위 '내보내기'(`MenuButton`: 브리프 내려받기·인쇄). 그 아래 접힌 '비교 기준 바꾸기 · 보고서 자세히'에 비교 기준 전환(전년 동기·직전 기간·직접 선택), 이 기업의 다른 분석, 보고서별 상세(접수번호·종류·대상 기간·제출일·정정 여부·원문)와 분석 한계를 둔다. 비교 기준을 바꾸면 요약·수치·문장·근거가 같은 보고서 쌍으로 함께 바뀐다. 탭은 요약 · 재무 수치 · 문장 변화 · AI 질문 · 원문 다섯 개다(주소 `tab` 값은 그대로).

### ① 요약·설명
- '주요 변화 요약' 묶음(제목 | '정기보고서 · 주된 근거' 배지, #550 시안 09) 안에 항목마다 옅은 바탕 카드(`Card tone="subtle"`): 사실 문장, 재무 항목은 '이전 → 현재' 큰 숫자와 중립색 증감 배지(▲▼·부호), 오른쪽 '수치 근거 →'·'문장 근거 →'. 설명이 없으면 카드 안 주의 안내('확인된 설명 없음'). 관점별 묶음·노트 담기·AI에 질문·커뮤니티 인용은 그대로
- 주요 변화 요약(중요한 순서, 원문 근거가 있는 변화만)
- 회사가 공시에서 밝힌 설명. 없으면 '확인된 설명 없음'
- '검토 필요' 건수와 문장·내용 변화로 가는 링크
- 수치 근거 상세: 이전·현재 값, 기준일, 단위, 계산식, 원문 위치
- 오른쪽 곁 정보(300px, 1100px 이상에서 두 열, #560): '변경이 많은 섹션' 막대 아래 '이 기간 수시공시 N건'(`PeriodDisclosures`, '보조 근거' 배지). 이전 보고서 제출 다음 날 ~ 현재 보고서 제출일에 낸 공시 중 지분 변동·정기보고서를 빼고 세어, 많이 낸 제목 3개(DART 원문 링크)와 건수, 기간·뺀 지분 변동 건수·'인과관계는 확인되지 않았어요'를 한 줄로 적는다. 기업 공시 목록(최근 365일)을 받아 화면이 거르며, 기간이 그보다 길면 '최근 1년만 셌어요'. 아래 '기업 개요에서 공시 타임라인 보기'

### ② 재무 수치 변화
- 맨 위 '핵심 숫자' 카드 다섯 칸(매출액·영업이익·순이익·자산총계·영업활동현금흐름, #550): 큰 현재 값, '이전 X', ▲▼·부호 증감률(중립색), '근거 보기'. 같은 재무 변화 목록 API의 전체 계정에서 계정명으로 찾고(매출액·자산총계는 서버가 크기 맥락에서 표준계정 ID로 찾은 기준 계정 이름을 먼저 씀), 못 찾으면 '자료 없음'

## 3-4-1. 움직임 (#198, FS-58)

움직임은 상태가 바뀐 곳을 눈으로 따라가게 하는 데만 쓴다. 시간·곡선은 아래 토큰만 쓰고, 운영체제 '동작 줄이기'(`prefers-reduced-motion: reduce`)면 `global.css`가 애니메이션·전환을 끄고 count-up은 바로 최종 값을 보인다.

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `--motion-fast` / `--motion-base` / `--motion-slow` | 120 / 200 / 360ms | 글자색 hover / 나타남·카드 들림·탭 줄 접힘 / 탭 밑줄 옮김 |
| `--motion-stagger` | 30ms | 막대가 차례로 자랄 때의 간격 |
| `--motion-count` | 600ms | 큰 숫자 count-up(`useCountUp`이 읽음). 곡선은 코드의 3차 ease-out(`shared/lib/countUp.ts`) |
| `--motion-shimmer` | 1400ms | 스켈레톤이 한 번 반짝이는 시간 |
| `--motion-lift` | −2px | 고를 수 있는 카드 hover 들림 거리 |
| `--ease-out` | `cubic-bezier(0.2, 0, 0, 1)` | 모든 전환의 곡선 |

이슈의 `--motion-duration-*`·`--motion-ease-*` 이름 대신, 이미 쓰던 `--motion-*`·`--ease-*` 이름에 맞춰 더했다(같은 뜻의 토큰을 두 벌 두지 않기 위해).

# 4. 공통 컴포넌트

화면은 아래 컴포넌트를 `@/shared/ui`에서 가져다 쓰고, 같은 모양을 `className`으로 새로 만들지 않는다(conventions.yaml UI-1). 모양(CSS)은 `frontend/src/shared/ui/ui.css` 한 곳에 있다. 모든 컴포넌트는 같은 태그의 기본 속성(`onClick`, `aria-*`, `id` 등)을 그대로 받고, `className`은 바깥 배치(여백·정렬)에만 쓴다. 새 모양이 필요하면 Figma를 먼저 보고 variant를 더한다(UI-3).

| 컴포넌트 | 주요 props | 쓰는 곳 |
| --- | --- | --- |
| `Button` | `variant`: `primary`·`secondary`(기본)·`link`·`icon`, `size`: `md`·`lg` | 모든 버튼. 켜고 끄는 버튼은 `aria-pressed`. `icon`은 아이콘만 있는 작은 버튼(카드 안 지우기)으로 `aria-label`을 꼭 넘긴다 |
| `ButtonLink` / `ButtonAnchor` | `Button`과 같은 `variant`·`size` + `to`(앱 안) / `href`(바깥) | 버튼 모양의 링크 |
| `Badge` | `tone`: `neutral`·`accent`·`attention`·`danger` | 현재·비교, 변경 유형, 진행 상태('분석 준비'), AI 생성, 검토 필요, 비교 불가·분석 실패 |
| `Notice` | `tone`: `info`·`attention`·`blocked`, `title`, `as`: `div`·`p`·`aside` | 안내 상자 세 가지(정보·주의·진행 불가). `title`이 있으면 아이콘 + 굵은 제목 + 설명 |
| `Page` / `PageHeader` | `as`, `width`: `narrow`(기본, 940)·`wide`(1060) / `breadcrumb`, `title`, `titleId`, `lead`, `aside` | 화면 본문 폭과 화면 머리(4-25) |
| `Tabs` | `label`, `items`, `value`, `onChange` | 결과 탭(주소가 바뀌므로 `nav` + `aria-current="page"`) |
| `MenuButton` / `MenuItem` | `label`, `trigger`: `button`(보조 버튼)·`chip`, `selected`(chip), `align`: `start`·`end`, `children`(함수면 닫는 함수를 받음) / 버튼 속성, 고른 값은 `aria-pressed` | 자주 쓰지 않는 동작을 묶는 펼침 상자(4-29): 결과 머리 '내보내기', 재무제표 '그 밖의 표', 이 기업의 다른 분석 |
| `SegmentedControl` | `options`(`icon`은 선택), `value`, `onChange`, `disabled`, `variant`: `text`(기본)·`icon`, `aria-label`·`aria-labelledby` | 비교 기준, 전체·변경 항목, 정렬, 비교·현재 보고서. `icon`은 아이콘만 있는 작은 알약 모양(각 `label`이 접근 가능한 이름·툴팁). 상단 바 화면 테마는 `ThemeMenu`가 아이콘 버튼 아래 펼침 상자에 글자 칸으로 둔다(#548) |
| `Chip` | `pressed`, `tone`: `neutral`·`attention`, `count` | 변경 유형 거르기 |
| `Panel` / `PanelTitle` | `as`: `section`·`div` / `as`: `h2`·`h3`·`h4` | 화면의 큰 묶음 상자와 제목 |
| `Card` | `as`, `tone`: `default`·`attention`·`subtle`, `selected`, `interactive` | 보고서·요약·변경 카드. `interactive`는 카드 전체를 눌러 고르는 카드(안에 링크·버튼)에만 붙여 hover·초점에 옅게 들린다 |
| `StatNumber` | `label`, `value`(null이면 '-'·'자료 없음'), `format`, `unit`, `previousText`, `change`(`direction`·`amount`·`rate`), `changeNote`, `changeLabel`(빈 문자열이면 앞말 없음), `source` | 큰 숫자 지표(4-21) |
| `Skeleton` | `label`(보이지 않는 '불러오는 중' 문구), `shape`: `line`·`block`·`card`, `count`, `height` | 화면의 주된 로딩 자리(4-22) |
| `DataTable` / `DataTableRow` / `SortableHeader` | `caption`(보이지 않음), `density`: `default`·`dense`·`compact`, `stickyHeader` / `selected` / `sort`(aria-sort 값), `onSort`, `numeric` | 보고서 목록, 재무 계정 표(낮은 행·머리글 고정·증감 정렬), 원문 표 |
| `FieldLabel` / `FieldHint` / `Input` / `Select` | `as`: `label`·`span` / — / `invalid` / — | 입력·선택창과 그 이름·도움말 |
| `BrandLogo` | `size`: `md`(상단 바)·`lg`(첫 화면) | 로고(4-26) |
| `ReportCard` / `ReportCardPair` | `side`: `previous`·`current`, `report`(null이면 `emptyText`), `children` | 이전·현재 보고서 카드 두 장(4-27) |
| `ProgressBar` | `value`(0~1), `label` | 분석 진행 막대(4-28) |
| `DotTimeline` | `rows`(`key`·`label`·`count`), `points`(`id`·`row`·`date`·`title`·`href`·`emphasis`·`action`), `from`·`to`, `label`, `emphasisLabel`·`otherLabel`, `onShowTable` | 기업 개요 공시 타임라인(4-20) |

로딩·빈 결과·오류는 `StateView`(`LoadingState`, `EmptyState`, `ErrorState`, `AlertState`), 원문 링크는 `DartLink`, 출처 줄은 `DartSource`, 아이콘은 `Icon`을 쓴다.

## 4-1. 버튼

모두 알약 모양(`--radius-pill`), 높이 `--button-height`(40px)다(#548). 주 버튼은 남색 바탕 흰 글자, 보조 버튼은 흰 바탕 1px 테두리, 비활성은 흐리게(0.5).

- 주요 버튼
- 보조 버튼

- 비활성화
- 로딩

주요 사용:

- 다시 요청
- 결과 보기
- 원문 확인 / DART 원문 열기

## 4-6. 탭

- 요약
- 재무 수치
- 문장 변화
- AI 질문
- 원문
- 900px 이하에서는 줄을 바꾸지 않고 한 줄 가로 스크롤로 둔다. 양 끝을 흐리게 해 옆에 탭이 더 있음을 알리고, 고른 탭이 보이도록 줄을 옮긴다(FS-11).
- 글자 탭이고, 고른 탭은 굵은 남색 글자와 2px 남색 밑줄이다(#548). 탭 사이 24px.
- 고른 탭의 밑줄은 하나(`tabs__indicator`)를 고른 탭 아래로 옮긴다(FS-58, `--motion-slow`). 처음 자리 잡을 때는 움직이지 않고, 탭 위치를 재지 못하면(글꼴 전 등) 고른 탭의 자기 밑줄을 그대로 쓴다. API(`label`·`items`·`value`·`onChange`)는 그대로다.

## 4-7. 배지

작은 알약(12px 굵게, 옅은 바탕). 회색(`neutral`) / 보라(`accent`, '분석 준비'·현재·AI 생성) / 노랑(`attention`, 검토 필요) / 분홍(`danger`, 비교 불가·분석 실패). 화면 머리 오른쪽 위 상태 배지로도 쓴다.

- 변경 유형: 추가, 삭제, 수정
- 검토 필요
- 중요도: 높음, 중간
- 보고서 표시: 현재, 비교, 정정
- AI 생성

## 4-8. 카드

흰 바탕, 1px `--color-border` 테두리, 모서리 12, 안쪽 20px(#548). 옅은 바탕 카드 안의 회색 배지는 흰 바탕으로 띄운다(#550). 그림자는 없고, 고를 수 있는 카드만 hover에 들린다. '현재 보고서'처럼 짝 중 기준이 되는 카드는 `tone="subtle"`(옅은 회보라 바탕). 표는 카드 안에 두고 머리줄은 옅은 회색 바탕, 행 사이 1px.

- 검색 결과 카드
- 변경 카드(문장·내용 변화)
- 근거 카드(이전·현재 보고서의 값과 위치)

## 4-9. 알림 문구

`Notice` 세 가지(#548). 모두 모서리 12, 테두리 없음. `title`이 있으면 왼쪽에 아이콘(보조기기에는 숨김), 오른쪽에 굵은 제목과 설명.

| tone | 모양 | 쓰는 곳 |
| --- | --- | --- |
| `info` | 옅은 보라 바탕, 보라 ⓘ, 제목은 본문 글자색 | 분석 기준과 한계, 비교 조건 확인 |
| `attention` | 옅은 노랑 바탕, 갈색 ⚠ 제목·글자 | 검토 필요, 미확정 기준 같은 예외 |
| `blocked` | 옅은 분홍 바탕, 빨간 ⓘ 제목 | 비교 불가, 분석 실패(사유와 다음 행동) |

- 성공(비교할 수 있음)
- 오류(분석 실패, 원문 열기 실패)
- 안내(분석 한계, 결정 전 영역)

## 4-14. 글자 링크 (#374)

| 종류 | 모양 | 쓰는 곳 |
| --- | --- | --- |
| 기본(`a`) | 링크색 글자 + 연한 밑줄(1px, 3px 띄움). hover에서 진한 색·글자색 밑줄. 방문해도 색이 바뀌지 않는다 | 문장 속 링크, 출처 줄의 '열기 ↗', 빵 부스러기, '돌아가기' |
| 목록 링크(`.list-link`) | 평소 본문 글자색·중간 굵기·밑줄 없음. hover·초점에서 링크색과 밑줄 | 행마다 링크가 하나씩 있는 목록(관심 기업 새 공시, 최근 공시, 이미 분석한 비교) |
| 버튼 모양(`ButtonLink`·`ButtonAnchor`) | 4-1 버튼과 같다 | 화면을 옮기는 주요 동작 |
| 카드 전체(`.recent-card__link` 등) | 글자색 그대로, 카드 hover로 눌리는 곳을 보인다 | 카드 하나가 링크 하나인 곳 |

- 기본 모양은 `global.css`의 `:where(a)`에 두어 특이도가 0이다. 클래스로 모양을 정한 링크(버튼·카드·메뉴)는 그 클래스가 이긴다.
- 링크색과 본문 글자의 대비가 3:1에 못 미치므로(2.6) 문장 속 링크는 밑줄을 없애지 않는다(WCAG 1.4.1). 밑줄을 없애는 목록 링크는 행 안에 링크가 하나뿐이고 ↗ 같은 표식이 있는 곳에서만 쓴다.
- 바깥 링크는 새 창으로 열고 글자 뒤에 `↗`(`aria-hidden`)와 '(새 창)' 숨김 글을 둔다.
- 키보드 초점은 모든 링크에 공통 초점 테두리(`--focus-ring`)가 보인다.

## 4-15. 더 보기 (#374)

- 첫 화면처럼 여러 영역이 쌓이는 곳의 목록은 처음에 몇 개만 보이고 아래에 '더 보기 (N건)'를 둔다(관심 기업 새 공시 5건, 최근 본 분석 5개, 기업 검색 결과 10곳). 펼치면 '접기'로 바뀐다.
- `Button variant="link"`로 만들고 `aria-expanded`와 목록 id를 가리키는 `aria-controls`를 붙인다. 숨길 것이 없으면 버튼을 두지 않는다.


## 4-16. 첫 화면 두 열 (#374, #378)

> #538·#549부터 두 열 대신 탭 카드 하나를 쓰고, #560부터 최근 본 분석은 검색창 펼침 상자에, FS-67부터 탭 카드(관심 기업 새 공시·이번 시즌 변화·대표 기업)는 둘러보기 화면(`/explore`)에 있다(2-1). 아래 행 모양(`.home-list`)은 탭 안 목록에 그대로 쓰고, 카드 안이라 목록 상자 테두리는 그리지 않는다.

- 검색어가 없을 때 검색창 아래에 '관심 기업' 칩을 전체 폭으로 두고, 그 아래를 **같은 폭** 두 열로 둔다: 왼쪽 '최근 본 분석', 오른쪽 '관심 기업 새 공시'.
- 두 열은 같은 틀(`.home-list`)이다: 제목 줄(높이 32px, 오른쪽에 동작) · 행 목록 상자 · 아래 줄('더 보기', 출처). 부모 격자의 행을 subgrid로 나눠 써서 세 칸의 위·아래 끝이 두 열에서 같은 높이에 온다. 한쪽 행이 적거나 한쪽만 펼쳐도 목록 상자는 같은 높이로 늘어난다.
- 행은 고정 높이(82px)다: 윗줄(22px)은 이름(굵게)·배지와 오른쪽 끝의 보조 정보(날짜, 비교 기준·본 시각), 그 아래 본문(공시 이름, 비교한 두 보고서)은 두 줄까지 줄바꿈한다(#381). 글은 행 위에서부터 놓아 한 줄짜리 행과 두 줄짜리 행의 윗줄이 같은 높이에 온다. 두 줄을 넘는 드문 글만 말줄임표로 줄이고 전체 글은 `title`과 링크 글자에 남긴다. 그래서 두 열의 행 경계가 나란히 맞는다.
- 처음 보이는 행 수는 두 열 모두 5다.
- 두 열이 들어갈 폭(열마다 최소 380px)이 안 되면 같은 순서로 위아래에 쌓이고 그때만 두 영역 사이를 띄운다. 최근 본 분석이 없으면 새 공시가 폭을 다 쓴다.

## 4-17. 영역 바로 가기 (#385)

- 영역이 여럿 쌓이는 긴 화면(기업 개요 탭)은 위쪽에 영역 이름 바로 가기 바를 두고 스크롤해도 위에 붙어 있게 한다.
- 링크는 주소를 바꾸지 않고 그 영역으로 옮겨(동작 줄이기면 바로) 영역에 초점을 둔다. 지금 보고 있는 영역은 `aria-current="location"`과 강조색 알약 모양으로 표시한다.
- 좁으면 바가 한 줄 가로 스크롤이 된다.
- 기업 개요는 넓은 화면(1,200px 이상)에서 AI 브리핑(폭 3)과 기업 개황(폭 2)을 한 줄에 둔다. 나머지 영역은 전체 폭이다.
- 긴 목록은 처음에 일부만 보인다: AI에게 묻기는 최근 답 1개, 주주·임원·배당은 고른 묶음 하나와 바뀐 항목 5개, 최근 공시는 10건.
- 재무 비율(FS-54, #410): '주요 재무 흐름' 안의 '금액 | 비율' 세그먼트로 바꾼다. 비율은 같은 응답의 주요계정 금액으로 코드가 계산하고(`shared/lib/financialRatios.ts`), 보고서 종류·손익 기준(누적·3개월)은 금액 보기와 같이 쓰며 연환산하지 않는다. 차트 없이 표 하나(행은 부채비율·유동비율·영업이익률·순이익률, 열은 값을 받은 기간을 오래된 순서로)이고 값은 소수 첫째 자리 %다. 값마다 버튼이고 누르면 표 아래에 계산식·두 금액(백만원)·근거 보고서 DART 링크를 연다. 계산하지 못한 칸은 0이나 '—'가 아니라 '계산 불가 · 매출액 미기재'처럼 이유를 흐린 글자로 적는다. 좋음·나쁨 색·문구나 업종·기준값 비교는 두지 않고, 'AI' 표시도 붙이지 않는다(코드 계산).

## 4-18. 분석 결과 화면 길이 (#390)

## 4-21. 큰 숫자 지표 (FS-58)

토스증권처럼 숫자를 크게, 나머지는 작고 옅게 둔다. 주가·시가총액·등락률은 보이지 않는다(ADR-0033).

- `StatNumber` 한 칸: 이름(작은 보조 글자) → 값(`--font-size-xl`, 굵게, 숫자 글꼴·고정폭 숫자)과 단위 → 보조 줄(증감) → 근거.
- 값은 `--motion-count` 동안 0에서 최종 값으로 올라간다(`useCountUp`, requestAnimationFrame·ease-out). 동작 줄이기면 바로 최종 값이다. 움직이는 숫자는 `aria-hidden`이고 화면 읽기 도구에는 최종 값만 읽어 준다.
- 값이 없으면 0이 아니라 '-'와 '자료 없음'이다.
- 보조 줄은 중립색(3-3 적용 기준): '전기 대비 ▲ 7조원 (+4.8%)'. 화살표와 함께 '증가·감소'를 보이지 않는 글자로 읽어 준다. 증감률을 계산하지 않았으면(전기 값 0·음수·부호 바뀜) 사유나 흑자전환·적자전환 같은 사실 표현만 적는다.
- 근거 칸에는 계정·기간·접수번호를 적는다(분석 결과 핵심 숫자는 그 계정의 근거를 여는 '근거 보기').
- `previousText`가 있으면 값 아래에 작은 회색 줄('이전 153.7조')을 두고, `changeLabel=""`이면 증감 줄에 앞말 없이 ▲▼·증감액·증감률만 둔다(#550 핵심 숫자).
- 숫자 문구는 lib의 format 함수로 만든다(기업 개요 지표 줄은 `formatCompactAmount`, 억·조).
- 기업 개요 상단 지표 줄(`OverviewMetricsRow`): 가장 최근 사업보고서의 매출액·영업이익·당기순이익 세 칸과 한 해 전 사업보고서 대비 증감. 주요 재무 흐름 API를 그대로 읽고(연결 값이 없으면 별도), 줄 아래에 현재·전기 보고서 원문 링크를 둔다. 넓으면 세 칸을 한 줄에 세로 구분선으로, 900px 이하는 위아래로 쌓는다.

## 4-22. 스켈레톤 (FS-58)

- 화면의 주된 로딩(기업 화면·기업 개황·주요 재무 흐름·지표 줄, 분석 결과 화면·요약·재무·문장 탭)은 빙글 도는 표시(`LoadingState`) 대신 채워질 자리의 모양을 같은 크기로 둔다. 작은 부분 로딩(패널 안 근거, 질문 기록 등)은 `LoadingState`를 그대로 쓴다.
- 모양: `line`(글줄, 첫 줄 40%·끝 줄 70%), `block`(차트·표 자리), `card`(카드 여러 개를 한 줄에). 높이는 `height`나 CSS 변수 `--skeleton-height`로 채울 내용과 맞춘다.
- 묶음은 `role="status"`·`aria-busy="true"`이고 '불러오는 중' 문구는 보이지 않게 읽어 준다. 모양은 `aria-hidden`.
- 바탕은 `--color-bg-subtle`, 반짝임은 `--color-border`를 옅게 섞은 띠가 `--motion-shimmer` 동안 지나간다. 동작 줄이기면 멈춘다.

## 4-23. 위에 붙는 기업 화면 헤더 (FS-58)

- 기업 화면의 '기업 개요 | 보고서 비교' 탭 줄(`company-bar`)은 스크롤해도 화면 위에 붙는다.
- 탭 줄 바로 위의 센티넬(높이 0)이 화면 위로 나가면(IntersectionObserver, 스크롤 이벤트 없음) `data-compact`가 켜져 탭 줄 오른쪽에 작은 회사명과 `--shadow-sm`이 나타난다. 큰 회사명은 본문과 함께 올라간다.
- 접혀도 탭 줄 높이는 그대로라 아래 내용이 튀지 않는다. 탭 줄 높이는 `--company-bar-height`로 넘겨 기업 개요 바로 가기 바가 그 밑에 붙고, 바로 가기로 옮긴 영역이 가리지 않는다.

- **상단 바**(높이 80, 아래 1px 테두리, 좌우 40, 흰 바탕): 왼쪽 로고(남색 사각 + 'DART Insight', 첫 화면 링크), 첫 화면이 아닌 화면에서는 둥근 기업 검색(`HeaderSearch`, Enter로 `/?q=`), 오른쪽 '기업 나란히 보기'·'내 판단 노트'(`nav` '주 메뉴'), 화면 테마(`ThemeMenu`: 아이콘 버튼 → 시스템·밝게·어둡게), 로그인 전 '알림'·'회원가입'·'로그인'(주 버튼) / 로그인 후 알림·로그아웃.
- **'지금 보는 기업' 줄**: 마지막으로 연 기업이 있으면 상단 바 아래 옅은 회색 줄에 기업 이름·종목코드와 기업 개요·공시 비교·원문 확인(분석이 있을 때만)을 둔다(`nav` '지금 보는 기업', 현재 화면은 `aria-current="page"`). 기업을 연 적이 없으면 줄이 없다.
- **하단 바**(높이 56 이상, 위 1px 테두리, `--color-bg-subtle`, 좌우 40): 왼쪽 출처·AI 안내 문구, 오른쪽 '이용 안내'(대화상자로 SERVICE_NOTICE 세 문장)·'단축키'(도움말 대화상자, `?`)·'AI 사용 현황'(링크).
- 900px 이하: 상단 바는 로고 + 메뉴 버튼(`aria-expanded`·`aria-controls`)만 두고, 검색·주 메뉴·테마·로그인은 버튼을 누르면 상단 바 아래로 펼친다. Esc나 화면 이동으로 접힌다. 하단 바의 '단축키'는 숨긴다(터치).
- 근거 보기 패널(`SidePanel`)이 열리면 작업 영역(기업 줄·본문·하단 바)만 패널 폭만큼 비운다. 상단 바는 그대로 둔다.

## 4-25. 화면 머리 (#548)

- `Page`: 화면 본문. 가운데 정렬, 폭은 `narrow`(940, 기본)·`wide`(1060, 분석 결과처럼 표·차트가 넓은 화면).
- `PageHeader`: 작은 회색 브레드크럼(`nav` '현재 위치') → 큰 굵은 제목(h1, 30px) → 회색 부제. 오른쪽 위 `aside`에 상태 배지(`Badge`)나 보조 버튼을 둔다. 좁은 화면에서는 `aside`가 제목 아래로 내려간다.
- 기존 화면의 `page__title`·`page__lead`·`breadcrumb` 클래스와 같은 모양이라, 화면을 옮겨도(#549·#550) 모양이 바뀌지 않는다.

## 4-26. 로고 (#549)

- `BrandLogo`: 남색 둥근 사각 마크(흰 막대 두 개) + 'DART Insight'(Inter 굵게). 마크는 `aria-hidden`이고 글자가 이름이다.
- `md`는 상단 바(마크 32px, 링크로 감쌈), `lg`는 첫 화면 가운데(마크 48px, 글자 30px, h1로 감싸고 보이지 않는 '기업 검색'을 덧붙임).

## 4-27. 보고서 카드 (#549)

- `ReportCard`: `Card` 위에 왼쪽 위 배지('이전 보고서' 회색 / '현재 보고서' 보라), 18px 굵은 보고서 이름, '대상 기간 · 제출 날짜', 정정 여부. 현재 보고서는 `tone="subtle"` 옅은 바탕이다. 카드 자체가 `aria-label`이 붙은 영역이다.
- 고르지 않았으면 이름 대신 `emptyText`(예: '비교 기준에 맞는 이전 보고서가 없어요.'). 고르기 칸·'보고서 자세히'는 `children`으로 넣고 `.report-card__extra`로 감싸면 카드 폭을 다 쓴다.
- `ReportCardPair`: 두 장을 같은 폭으로 나란히, 카드마다 320px이 안 되면 위아래로. 보고서 선택·비교 확인·분석 진행 화면이 같이 쓴다.

## 4-28. 진행 막대 (#549)

- `ProgressBar`: 높이 4px 알약, 옅은 회색 길 위에 남색 막대. `role="progressbar"`와 0~100 값, `label`이 이름이다. 값이 바뀌면 `--motion-slow`로 늘어나고 동작 줄이기면 바로 바뀐다.

## 4-29. 펼침 버튼 (#550)

- `MenuButton`: 보조 버튼(또는 `trigger="chip"`이면 거르기 칩) 뒤에 ▾를 붙이고, 누르면 아래로 떠 있는 작은 상자(흰 바탕, 1px 테두리, 모서리 9, `--shadow-md`)를 연다. 펼친 상자 안 값이 지금 골라져 있으면 칩을 채운다(`selected`, `chip--selected`).
- `aria-expanded`·`aria-controls`로 펼침을 알린다. Esc로 닫으면 초점을 버튼으로 돌려주고(뒤 근거 패널은 닫지 않음), 바깥을 누르면 닫는다. 항목을 고른 뒤 닫으려면 `children`을 함수로 넘겨 닫는 함수를 받는다.
- 항목은 `MenuItem`(글자 버튼, hover·고른 항목은 옅은 바탕). 링크 항목은 `className="menu-button__item"`. 인쇄에서는 숨긴다.

# 5. 공시 비교 컴포넌트

## 5-1. 비교 기준 선택

- 세그먼트 버튼(전년 동기 / 직전 기간 / 직접 선택)
- 선택에 따라 정해진 비교 보고서와 현재 보고서 표시
- 기본값은 결정 로그의 '기본 비교 기준'을 따른다.

## 5-2. 보고서 목록

- 보고서, 대상 기간, 제출일, 정정 여부, 자료 상태, 선택, 원문
- 대상 기간과 제출일을 별도 열로 둔다.
- '선택' 칸에 '현재'(보라) / '이전'(회색) 배지, 고르지 않은 보고서는 '미선택'(회색 글자)(#549).

## 5-3. 비교 검증표

- 항목별 확인 결과(확인됨 / 주의 / 비교 불가 / 확인 안 함)를 행 오른쪽 `Badge`로(회색 / 노랑 / 분홍 / 회색)
- 비교할 수 없을 때 사유와 다음 행동(`Notice tone="blocked"`)

## 5-4. 진행 단계

- 요청 접수 → 보고서 비교 → 근거 확인 → 완료
- 단계마다 옅은 회색 카드(진행 중은 옅은 보라, 실패는 옅은 분홍), 완료는 ✓와 '완료', 그 아래 `ProgressBar`(끝난 단계 + 진행 중 단계의 절반, 실패하면 그 앞에서 멈춤)
- 결과를 저장하기 전에는 '완료'로 표시하지 않는다.

## 5-5. 변화 요약

- 원문 근거가 있는 변화만 중요한 순서로 나열
- 항목마다 '수치 근거' 또는 '문장 근거' 링크
- '확인된 설명 없음', '검토 필요 [n]건' 표시

## 5-6. 재무 계정 비교 표

- 합계와 세부 계정의 계층(들여쓰기)
- 이전 값(왼쪽), 현재 값(오른쪽), 증감액, 증감률
- 증감은 `▲`·`▼`와 부호로 표시
- 이전 값이 0이거나 미기재면 계산하지 않고 '계산 불가 · 사유'를 표시한다. 없는 값을 0으로 보이게 하지 않는다.

## 5-7. 문장 변경 카드

- 위치(목차 / 항목), 변경 유형 배지, 중요도
- 이전 문장과 현재 문장을 나란히
- 추가는 강조 배경, 삭제는 취소선
- 삭제는 '문서에서 빠졌다'는 뜻이다. 사업·계약이 끝났다고 표현하지 않는다.
- 항목을 짝짓지 못하면 숨기지 않고 '검토 필요'로 표시한다.

## 5-8. 근거 패널

- 이전·현재 보고서의 값, 기준일, 연결·별도, 단위
- 원문 위치(목차 경로)와 '원문 위치 보기'
- 계산식(증감액, 증감률)
- 수치 근거(#550, 시안 11): 제목 | '× 닫기' → '주된 근거 · 정기보고서' 배지(보라)와 출처(기업 · DART · 재무제표) → 옅은 바탕 계산식 상자('이전 X / 현재 Y · 연결', '증감액 = …', '증감률 = …', 고정폭 글꼴) | 오른쪽 '원문 위치'(재무제표 → 재무제표 이름 → 계정, 기준일)와 주 버튼 '원문 위치 보기'(현재 보고서 표, 없으면 이전 보고서 표). 그 아래 보고서별 값 카드(1px 테두리)·비교 막대·크기 맥락·설명. 설명이 없으면 주의 안내 '확인된 설명 없음'.
- 수시공시 보조 근거(#550, 시안 12): '보조 근거 · 수시공시' 회색 배지로 정기보고서(주된 근거)와 나누고, 주의 안내 '인과관계는 확인되지 않았습니다.'를 늘 둔다. 공시마다 접수일·연결 규칙·DART 원문 링크.

## 5-9. 원문 뷰어

- 문서 목차와 현재 위치
- 선택한 근거 문단 강조
- 출처·제출일·정정 여부, DART 원문 링크
- 배치(#550, 시안 13): 제목 '관련 원문 위치' | '← 분석 결과로 돌아가기'(원문을 열기 전에 본 탭으로. 주소에 새 값을 두지 않음) → 위아래 구분선 사이 보고서 이름 줄(기업 · 대상 기간 · 제출일 · 정정 여부 · 접수번호)과 근거 위치에서 왔으면 '주된 근거' 배지, 비교·현재 보고서 고르기 → 왼쪽 문서 목차(세로 구분선, 고른 항목은 옅은 바탕·굵게) | 오른쪽 본문(근거 블록은 왼쪽 3px 주색 선 + 옅은 바탕) → 아래 출처 정보 안내(`Notice info`).

## 5-10. AI 생성 표시

- AI가 만든 요약·설명 옆에 'AI 생성' 표시를 붙인다.
- 매수·매도 추천, 목표주가, 주가 예측, '저평가' 같은 가치판단 문구는 화면에 쓰지 않는다.

# 6. 차트 및 데이터 시각화

MVP는 **표 중심**이다. 이전 값과 현재 값, 증감액, 증감률을 표로 정확히 보여 주는 것을 우선한다.

## 6-1. 차트 종류

### 막대그래프
선택한 계정의 이전 값과 현재 값을 나란히 보여줄 때 선택적으로 쓴다.

## 6-2. 데이터 시각화 기준

| 데이터 | 시각화 |
|---|---|
| 계정별 이전·현재 값과 증감 | 테이블 |
| 선택한 계정의 이전·현재 비교 | 막대그래프(선택) |
| 문장 변화 | 변경 카드 |
| 보고서 정보 | 테이블 |
| 기업의 최근 1년 공시 흐름 | 점 타임라인 + 같은 자료의 표(4-20) |

### 적용 기준

- 차트와 실제 데이터 수치를 일치시킨다.
- 차트에는 실제 수치를 함께 표시한다.
- 값이 없거나 계산할 수 없으면 차트 대신 상태 문구를 표시한다.
- 여러 기업을 비교하는 차트(방사형·비중 그래프 등)는 MVP 범위가 아니다.

# 7. 레이아웃

심플 통일 시안(#548)의 화면 골격을 모든 화면에 쓴다(`frontend/src/app/Layout.tsx`, 자세한 내용은 4-24).

- **상단 바(80px)**: 로고, 기업 검색(첫 화면 밖), 기업 나란히 보기·내 판단 노트, 화면 테마, 로그인/알림. 왼쪽 메뉴는 없다.
- **'지금 보는 기업' 줄**: 기업 개요·공시 비교·원문 확인. 원문 확인은 분석 결과가 있을 때만 보인다.
- **본문**: 여백 40px, 최대 1060px 가운데 정렬. 보통 화면은 `Page`로 940px. 화면 제목 위에 작은 회색 브레드크럼(`PageHeader`)을 둔다.
- **하단 바(56px)**: 출처(DART)·AI 생성 안내·투자 조언 아님, 이용 안내·단축키·AI 사용 현황
- **결과 화면**: 상단 비교 보고서 영역 → 비교 기준 → 탭 → 내용 순서
- **원문 화면**: 왼쪽 목차, 오른쪽 원문
- 900px보다 좁으면 상단 바의 검색·메뉴·테마·로그인을 메뉴 버튼으로 접는다.
- 900px 이하에서 누르는 것은 높이 32px(`--touch-target-min`) 이상이다. 글자 링크·링크 버튼은 글자 크기와 자리를 두고 위아래 여백만 넓히고, 모양이 있는 작은 표식(답의 인용 번호)은 보이지 않는 누르는 영역을 넓힌다(FS-11).

시안에만 있고 넣지 않은 것: '가상 데이터 체험' 배지, 프로필, 하단 바 '아래로 이어지는 내용 ↓'(시안 캡처용 표시).

# 12. 최종 UI 적용 기준

- 화면 흐름과 화면 번호는 와이어프레임을 따른다.
- 동일한 컴포넌트를 반복해서 재사용한다.
- 이전 보고서는 왼쪽, 현재 보고서는 오른쪽에 둔다.
- 재무 수치와 문장 변화를 구분한다.
- 모든 수치와 문장에서 원문 근거로 이동할 수 있게 한다.
- 증가·감소 표현을 일관되게 쓰고 좋음·나쁨 평가와 섞지 않는다.
- 로딩·실패·계산 불가·검토 필요·데이터 없음 상태를 숨기지 않는다.
- AI가 만든 문장에는 'AI 생성' 표시를 붙인다.
- Figma와 실제 개발 화면의 컴포넌트 구조와 토큰 값을 일치시킨다.
