## 1. [Executive Summary] 30초 엘리베이터 피치 & 핵심 철학

> *"공시 분석하느라 300페이지짜리 사업보고서 두 개를 모니터에 나란히 띄워놓고 새벽까지 Ctrl+F 누르며 주석을 대조해 보신 적 있으십니까?  
> 기존 생성형 AI에게 물어보면 숫자를 지어내는 치명적인 '환각(Hallucination)' 때문에 결국 사람이 다시 검증해야 했습니다.  
> **DART Insight는 수작업에 4시간 걸리던 전자공시 정기보고서 대조를 단 5초 만에, 100% 원문 근거와 환각 0%로 완벽히 자동화한 신뢰 기반 금융 인텔리전스 시스템입니다.**  
> 저희의 철학은 명확합니다. **'AI는 최고의 비서지, 대표가 아닙니다.'** 코드가 계산하고, AI는 검증된 원문 근거만 꿰뚫습니다."*

문학이나 코딩에서는 95%의 정확도가 훌륭할지 몰라도, **단 1원의 오차로 수억 원의 손실이 발생하는 금융 시장에서는 1%의 환각도 치명적인 독**이 됩니다."

## 4. [Q&A Defense] 심사위원 기술 Q&A 방어 대본 (Top 5)

### Q1. "기존 LangChain이나 벡터 DB(Chroma 등)를 쓰지 않고 왜 굳이 BM25를 직접 만들었습니까?"
- **답변 핵심**: **결정론적 정확성, 밀리초 단위 응답 속도, 제로 인프라 비용**
- **대본**:  
  "매우 중요한 질문입니다. 금융 공시 분석에서 범용 벡터 임베딩은 '코사인 유사도는 높은데 엉뚱한 계정과목을 가져오는' 시맨틱 왜곡이 종종 발생합니다.  
  반면 금융 공시의 용어는 금융감독원 표준 표기법에 맞춰 극도로 정형화되어 있습니다.  
  저희는 금융 도메인 특성에 맞춘 `2-gram 인메모리 BM25`를 직접 구축하여, 외부 벡터 DB 통신 지연 없이 단 45ms 만에 정확한 근거를 찾아냈습니다. 서버 비용 0원과 밀리초 속도, 두 마리 토끼를 모두 잡은 최적의 엔지니어링 선택이었습니다. (ADR-0036)"

### Q2. "LLM이 생성한 텍스트가 진짜 거짓말(환각)을 하지 않는다고 어떻게 100% 확신합니까?"
- **답변 핵심**: **코드 계산 100%, 사실 추출 정규식 가드레일, 2회 재생성 후 자동 격리**
- **대본**:  
  "저희는 LLM의 말솜씨를 믿지 않고 시스템의 규칙을 믿습니다.  
  첫째, 모든 숫자 연산은 Java 백엔드 코드가 1원 단위까지 계산하며 프롬프트에 계산을 단 한 줄도 맡기지 않습니다.  
  둘째, LLM이 생성한 문장마다 `{접수번호}#B{블록번호}`가 존재하는지 정규식으로 검증하고, 해당 블록이 실제 로컬 DB 원문에 실존하는지 백엔드가 대조합니다.  
  근거가 없거나 원문과 일치하지 않으면 최대 2회 재생성 후 즉시 탈락시켜 '검토 필요'로 안전하게 격리합니다. (ADR-0008, ADR-0062)"

### Q3. "OpenDART의 일일 2만 회 API 호출 제한은 대규모 트래픽에서 어떻게 방어합니까?"
- **답변 핵심**: **접수번호(rcept_no) 기준 불변성 영구 캐시 전략**
- **대본**:  
  "공시 보고서는 제출된 이후 내용이 절대 바뀌지 않는 '불변 데이터'입니다.  
  저희는 이를 활용해 '접수번호 기준 영구 캐시 전략'을 세웠습니다. 최초 1회만 파싱하여 DB에 영구 적재해 두면, 이후 10만 명의 사용자가 동일 보고서를 조회해도 외부 OpenDART 호출 횟수는 정확히 0회입니다.  
  트래픽이 폭증해도 외부 API 쿼터 고갈 위험이 원천적으로 없습니다."

### Q4. "3주라는 짧은 시간 안에 어떻게 2,626개 테스트와 421개 PR을 완성할 수 있었습니까?"

  기획 단계에서 검증 가능한 수용 기준(AC)과 66개 ADR을 선행 작성하고, 이를 WBS 이슈로 쪼갰습니다.
