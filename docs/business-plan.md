## 1. 사업 개요

**한 줄 정의**: DART 정기보고서의 **전년 동기 대비 수치·서술 변경점**을 탐지하고, 변경 원인을 **원문 문단 인용**과 함께 설명하며, **사람 검토 후 게시**하는 공시 변화 레이더(가칭 "공시레이더"). 차별점은 "DART + AI"가 아니라 이 세 가지의 조합이다.

- **아키텍처 기준**: 서민구 강사의 「금융 AI 에이전트 설계 및 구현」(Quant-X) 강의 구조를 그대로 따른다. 3-Zone 분리, Spring Boot + FastAPI, Tool Gateway, Manager-Worker 멀티 에이전트, 가드레일, 감사 로그가 그 뼈대다.
- **강의와 다른 점**: 강의는 LLM을 "보조"로 좁게 쓴다. 우리는 그 통제 구조를 유지하면서 공시 본문 비교·원인 설명·근거 검증까지 LLM 활용 범위를 넓힌다.
- **팀과 기간**: 6명(백엔드 2, 프론트 1, AI 2, 인프라 1), 주 5일, 하루 7\~8시간. 개발 마감은 11월 17일, 발표는 11월 18일이다.
- **기술 스택**: React, Spring Boot, Python(FastAPI·LangChain·LangGraph), MariaDB, 외부 API(OpenDART).

**목표**: 발표일에 "분기 공시 하나를 넣으면 무엇이 왜 바뀌었는지 근거와 함께 3분 안에 보여 주는" 동작 데모와, 그 결과의 정확도를 숫자로 보여 주는 평가 결과를 함께 낸다.

## 2. 문제 정의와 대상 사용자

분기 공시 비교의 병목은 숫자가 아니라 본문이다. 재무 수치는 OpenDART의 재무제표 API로 이미 정형 데이터로 받을 수 있지만, 사업의 내용·위험요인·소송·특수관계자 거래처럼 텍스트로만 바뀌는 정보는 사람이 두 문서를 나란히 놓고 읽어야 찾을 수 있다.

**지금 방식의 문제**

- **변화는 정보인데 아무도 읽지 않는다**: 미국 정기보고서 연구 [Lazy Prices](https://www.nber.org/papers/w25084)에서 리스크 요인 섹션의 문구 변화는 월 188bp의 초과수익을 예측했지만, 시장은 공시 시점에 반응하지 않았다. 저자들은 이를 투자자 무관심으로 해석했다.
- **물량이 한꺼번에 몰린다**: 2025년 3분기보고서 마감일(11/14) 하루에 코스닥 공시 1,554건(전날의 약 4배), 유가증권 864건이 접수됐다([한국경제](https://www.hankyung.com/article/2025111790771)). 분기·반기보고서는 분기 말 후 45일, 사업보고서는 90일 안에 낸다.
- **문서가 너무 길다**: 삼성전자 2024 사업보고서 원문은 평문 약 578만 자다. 두 해 문서를 나란히 읽는 것은 사람에게도 LLM에게도 비현실적이다.
- **수치와 원인이 따로 논다**: 영업이익 감소는 재무 API로 바로 보이지만, 회사가 밝힌 원인 문단을 찾는 일은 수작업이다.
- **요약 도구는 근거가 없다**: 일반 LLM 요약은 어느 문장에서 나온 내용인지 보여 주지 않는다. 금융 RAG 벤치마크 [FinanceBench](https://arxiv.org/abs/2311.11944)에서 GPT-4-Turbo+검색은 질문의 81%를 오답 또는 답변 거부로 처리했다.

**시장 규모**: 2025년 결산 상장법인 2,727개사(코스피 812, 코스닥 1,802), 주주 약 1,456만 명 중 개인이 약 1,442만 명(99.1%)이다([헤럴드경제](https://www.heraldk.com/article/2026031718251934888)). 2025년 상장법인 공시 위반은 35건으로 전년보다 84.2% 늘었다([매일신문](https://www.imaeil.com/page/view/2026021910300032543)).

**대상 사용자**

| 사용자 | 하고 싶은 일 | 우리가 주는 것 |
| --- | --- | --- |
| 개인 투자자 | 보유·관심 종목의 이번 분기 변화를 빠르게 파악 | 변화 요약 + 원문 근거 링크 |
| 주니어 애널리스트(강의의 Junior Analyst 역할) | 커버리지 기업 공시를 빠짐없이 검토 | 변경 문단 목록 + 중요도 순 정렬 |
| 시니어·검토자(강의의 Senior Manager 역할) | AI가 만든 분석을 승인한 뒤 공유 | 검토·승인 화면(HITL) |

**이 프로젝트를 하는 이유(멘토 질문에 대한 답)**: "숫자 비교는 누구나 한다. 우리는 숫자가 바뀐 이유를 본문에서 찾아 근거와 함께 보여 주고, 그 결과를 금융권 기준의 통제 안에서 낸다."

## 3. 솔루션과 핵심 기능

기능마다 담당 기술을 하나로 정한다. 숫자 계산은 코드, "평소와 다른 변화" 판단은 ML, 본문 해석과 설명은 LLM이 맡는다. 이 분담이 "왜 여기에 AI를 썼는가"에 대한 답이다.

| 우선순위 | 기능 | 담당 | 결과물 |
| --- | --- | --- | --- |
| MVP | 수치 비교(YoY·QoQ) | 코드 (OpenDART 재무제표 API) | 계정별 증감표 |
| MVP | 이례적 변화 탐지 | ML (이상 탐지) | 설명이 필요한 계정 목록 |
| MVP | 본문 변경점 탐지(섹션 diff) | 임베딩 + LLM | 추가·삭제·변경 문단과 변경 유형 |
| MVP | 변화 원인 설명 | LLM + RAG | 수치 변화마다 원인 문장 + 원문 인용 |
| MVP | 근거 검증 | 코드 + LLM 판정 | 인용이 실제 원문과 맞는지 표시 |
| MVP | 분석 보고서 + 검토·승인 | 멀티 에이전트 + HITL | 승인된 리포트 |
| 확장 | 자연어 질의("이번 분기 리스크 바뀐 거 있어?") | LLM Tool Calling | 대화형 답변 |
| 확장 | 관심 종목 알림 | 스케줄러 + LLM 요약 | 새 공시 접수 시 변경 요약 |

**분석 대상 섹션과 근거**: Lazy Prices에서 정보력이 가장 컸던 리스크·소송 관련 변화를 중심으로 고른다.

| 대상 | 원문 위치 | 비고 |
| --- | --- | --- |
| 사업의 내용(위험 관련 기술 포함) | II. 사업의 내용 | 신규 위험·사업 변화 |
| 소송·우발부채 | 기타 투자자 보호 사항, 재무제표 주석 | 주요사항보고서 `lwstLg`(소송 등의 제기)로 교차 확인 |
| 특수관계자 거래 | 대주주 등과의 거래 내용, 주석 | 거래 상대·금액 변화 |
| 핵심 손익 계정 | `fnlttSinglAcntAll` | 매출·영업이익·순이익 등 |

**변경 유형 4분류**: 신규 위험 / 삭제 / 수치 변경 / 표현 변경. 후속 연구에서 "어떤 종류의 언어가 바뀌었나"에 따라 의미가 달랐기 때문에 유형을 스키마에 넣는다.

**ML의 역할 정의**: "분식 탐지"가 아니라 "추가 확인이 필요한 변화"를 고른다. 업종 내 YoY 변화율의 robust z(중앙값·MAD 기준, |z|>3), Isolation Forest, Beneish M-score 분위수를 함께 쓴다. 플래그가 뜬 계정은 관련 서술 문단의 변화와 연결해 회사가 밝힌 이유를 인용한다. 은행·보험·증권은 손익 구조가 달라 시연 대상에서 뺀다.

**사용 흐름**: 종목 선택 → 비교할 분기 선택 → 분석 실행 → 진행 상황(에이전트 타임라인) → 변경점 리포트(수치·본문·원인·근거) → 검토자 승인 → 공유.

**포트폴리오 트래커 병합에 대한 PM 의견**: 기간이 약 5주이므로 MVP에는 "관심 종목 목록"까지만 넣고, 보유 수량·평가손익 같은 트래커 기능은 확장으로 미룬다. 보유 정보가 들어오면 개인 금융정보가 되어 가드레일 범위가 커지고, 공시 분석이라는 핵심 차별점이 흐려진다.

## 4. 강의자료(Quant-X) 분석과 적용 범위

강의 전체를 관통하는 원칙은 "프롬프트는 지시이지 보장이 아니다"이다. 중요한 통제는 프롬프트가 아니라 Tool 미부여, 키 분리, 게이트웨이, 필터, DB 권한 같은 코드와 인프라에 둔다(부록 D). 우리 프로젝트도 이 원칙을 그대로 가져가고, LLM은 그 경계 안에서 더 많이 쓴다.

| 장 | 강의의 핵심 설계 | 우리 프로젝트 적용 |
| --- | --- | --- |
| 1 | Agent를 "내부자"로 보고 id·role·scope·tools·audit 5요소를 부여 | 에이전트별 권한 표를 기획서 단계에서 확정 |
| 2 | 데이터 4분류와 3-Zone, "무엇을 시키지 않을지" 먼저 정의 | 공시는 공개 데이터, 사용자 관심 종목만 개인 데이터로 분류 |
| 3 | Spring Boot(인증·DB·감사)와 FastAPI(AI) 분리, 비동기 Job + 폴링 | 그대로 사용. 공시 분석은 수십 초 이상 걸리므로 비동기 필수 |
| 4 | RAG, 청킹 전략, trust\_level, `<document>` 격리, 무결성 해시 | 공시 섹션 단위 청킹(Header-aware), 원문 접수번호를 인용 ID로 사용 |
| 5 | "텍스트는 벡터DB, 숫자는 정형DB", 단위 정규화, Tool Gateway | 재무 수치는 OpenDART API → MariaDB, 본문은 Chroma |
| 6 | LLM Adapter, 권한 인자를 LLM 스키마에서 제외, 반복·시간 상한 | 그대로 사용. 모델 교체·비용 비교의 기반 |
| 7 | LangGraph Manager-Worker, Risk Reviewer 반려 루프, 실행 이력 DB화 | 워커를 공시 분석용 4종으로 재정의(§5) |
| 8 | Core Zone 별도 프로세스, HITL 결재, 멱등성 | 주문이 없으므로 "리포트 게시 승인"으로 HITL 축소 적용 |
| 9 | Input/Output 필터, append-only 감사 로그, request\_uid, Kill Switch, Red Team | 투자 권유 표현 차단, 감사 로그, Kill Switch 유지. Red Team 셋은 공시 문서 인젝션 위주로 재작성 |
| 10 | Ollama·Qwen 폐쇄망 전환, `llm_invocation_log` | 선택. 비용·속도 비교 실험용으로만 사용 |
| 11 | React는 Spring 하나만 호출, 화면 분기는 보안이 아님 | 그대로 사용 |

**강의가 남겨 둔 빈칸(우리가 채울 차별점)**: 9장은 "본문 인용이 실제 근거와 맞는지 검증"을 미해결로 남겼고, 출력 재작성(shouldRewrite)도 표시만 한다. 이 두 가지를 LLM으로 구현하면 강의를 그대로 따라 한 팀과 확실히 구분된다(§6).

## 5. 시스템 아키텍처

강의의 계층 구조를 그대로 쓰고, AI Layer의 워커만 공시 분석용 4종으로 바꾼다. 강의의 Core Zone(가상 원장)은 주문 기능이 없어 빼고, 그 자리를 OpenDART 수집으로 채운다.

&#91;embedded content: 시스템 아키텍처 · 강의 3-Zone 구조를 공시 분석용으로 재구성\]

Manager가 질문에 필요한 워커만 골라 실행하고, 검증 워커가 반려하면 해당 워커를 다시 돌린다(강의 7장 반려 루프, 재실행 상한 적용). 워커는 Tool Gateway·LLM Adapter·Chroma 세 통로로만 외부에 닿으므로, 권한 검사와 호출 기록이 한 곳에 모인다.

| 워커 | 사용하는 Tool | 필요 권한(Scope) |
| --- | --- | --- |
| 수치 분석 | 재무제표 조회, 이상 탐지 모델 | FIN\_DATA\_READ |
| 본문 비교 | 섹션 조회, 임베딩 유사도 | FILING\_READ |
| 원인 설명 | 공시 본문 RAG 검색 | FILING\_READ |
| 검증·검토 | 인용 대조, 규칙 검사 | FILING\_READ, FIN\_DATA\_READ |
| Report Writer | 없음(상태만 읽음) | — |

**분석 1건의 처리 순서**

1. `corpCode.xml`로 종목코드를 8자리 `corp_code`로 바꾼다.
2. `list.json`(`pblntf_detail_ty` A001\~A003, `last_reprt_at=Y`)으로 당기 보고서의 접수번호(`rcept_no`)를 얻는다. 정정 공시는 `rm`의 "정"으로 판별한다.
3. 수치: `fnlttSinglAcntAll.json`을 연결(CFS)로 부르고, 없으면 별도(OFS)로 폴백한다.
4. 본문: `document.xml`로 원문 ZIP을 받아 파싱하고, `rcept_no` 키로 영구 캐시한다.
5. 섹션을 제목으로 맞추고, 섹션 안 문단을 정렬해 변경 후보만 고른다.
6. LangGraph 워커가 분류·원인 설명·검증을 하고, 결과는 "검토 대기" 상태로 Spring Boot에 넘어간다.
7. 검토자가 승인하면 게시된다.

비교 1건에 OpenDART 호출은 약 6회다. 시연 규모(10\~30개사)는 일 한도 안에 들어가지만, 전 상장사 일괄 수집은 한도를 넘는다.

## 6. LLM 활용 고도화 방안

강의에서 LLM은 "검색된 근거로 문장을 쓰는 일"만 한다. 우리는 아래 7가지로 범위를 넓힌다. 승부처는 프롬프트가 아니라 "무엇을 LLM에 넣지 않을지"를 정하는 정렬 계층이다. 단, LLM은 숫자를 계산하지 않고, 최종 판정이 필요한 곳에는 항상 코드 검증을 뒤에 둔다.

1. **섹션·문단 정렬(Semantic Diff) — 무엇을 LLM에 넣지 않을지 정하는 계층**
   - 섹션은 제목으로 맞춘다. 같은 회사의 연도 간 비교라 제목 퍼지 매칭으로 대부분 맞는다.
   - 문단 안의 숫자를 `<NUM>`으로 가린 뒤 임베딩하고, 코사인 유사도 행렬에서 Hungarian(`linear_sum_assignment`)으로 1:1 매칭한다. 숫자 변경은 규칙으로 따로 잡는다.
   - 유사도로 동일·수정·신설·삭제를 나누고, 수정 후보에는 `difflib` 문자 diff를 붙여 LLM에 보낸다. 임계값(예: 0.95/0.80)은 문헌상 표준값이 없어 평가셋으로 튜닝한다.
   - 비슷한 설계(LLM은 추출, 임베딩은 변화 측정)를 쓴 2025년 연구 [From Text to Alpha](https://arxiv.org/abs/2510.03195)가 있다.
2. **한국어 임베딩 — 로컬 모델을 기본으로**
   - [KURE-v1](https://huggingface.co/nlpai-lab/KURE-v1)(고려대, BGE-M3 파인튜닝, MIT)은 한국어 검색 8종 평균 Recall@5가 0.7385로, OpenAI text-embedding-3-large(0.6637)보다 높다. 비용도 0이다.
   - 비교 후보는 [Qwen3-Embedding-0.6B](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)다. 평가셋에서 두 모델을 비교한 결과를 발표에 넣는다.
3. **구조화 추출(Structured Output)**
   - 스키마: `change_type`, `summary`, `evidence_paragraph_ids[]`, `numeric_claims[{account, value, unit}]`, `confidence`. 근거가 없으면 null을 허용한다.
   - OpenAI strict 모드는 스키마 준수 평가에서 100%였지만, 거부·출력 절단·값 오류는 남는다([OpenAI](https://openai.com/index/introducing-structured-outputs-in-the-api/)). Pydantic 검증 후 1\~2회 재시도하고, "스키마 실패율"과 "값 오류율"을 따로 집계한다.
4. **수치 변화 원인 설명(Explain)**
   - ML이 고른 계정마다 질의를 만들어 해당 분기 본문을 RAG로 검색하고, 원인 문장을 `[rcept_no:섹션:문단ID]` 인용과 함께 붙인다.
   - 원인 문장을 못 찾으면 "본문에서 원인 확인 불가"로 쓴다.
5. **인용 검증 — 강의의 미해결 과제**
   - 1단(코드): 인용 ID가 실제로 있는지 확인하고, 문장 속 수치·단위를 정규식으로 뽑아 재무 API 값과 대조하며 증감률을 재계산한다.
   - 2단(LLM 판정): 인용 원문이 주장을 "지지/불충분/모순" 중 어디에 해당하는지 판정한다. 공개 판정 모델의 정확도는 Bespoke-MiniCheck-7B 77.4%, HHEM-2.1 71.8%로 높지 않고 영어 중심이다([Bespoke Labs](https://bespokelabs.ai/bespoke-minicheck)). 그래서 저가 LLM을 판정기로 쓰고, 판정기 정확도도 평가셋으로 잰다.
6. **출력 재작성 — 강의의 미해결 과제**
   - Output Filter가 단정 표현을 잡으면 LLM에 완화 표현으로 고쳐 쓰게 하고, 고친 결과를 같은 필터로 다시 검사한다.
7. **문서 인젝션 방어**: 공시 원문도 외부 데이터다. 문서를 태그로 감싸고 데이터임을 표시하는 Spotlighting은 간접 인젝션 성공률을 50% 초과에서 2% 미만으로 낮췄다([arXiv:2403.14720](https://arxiv.org/abs/2403.14720)). 에이전트 도구는 읽기 전용으로만 둔다.

### 평가 계획(파일럿)

평가셋은 40건이다. 회사 8곳 × 연도쌍 2개에서 섹션 변화 20건(신설·삭제·수정·동일 균형), 수치 설명 10건, "근거 없음"이 정답인 함정 질문 5\~10건, 인젝션 사례 3\~5건을 넣는다. 라벨러 2명이 따로 라벨링하고 일치도(Cohen's κ)를 보고한다. 표본이 작으므로 신뢰구간과 함께 "파일럿 평가"로 명시한다.

| 지표 | 측정 대상 |
| --- | --- |
| 변화 탐지 F1 | 섹션 변화 20건 |
| 인용 정밀도·재현율 | 원인 설명 10건 |
| 수치 일치율 | 생성문 속 수치 vs 재무 API |
| 판정기 정확도 | 2단 LLM 판정 |
| 함정 질문 정답률("근거 없음") | 함정 5\~10건 |
| 건당 비용·지연 | 전체 실행 로그 |

비교 실험(ablation): `difflib` 단독 vs 임베딩 정렬, KURE-v1 vs Qwen3-Embedding-0.6B.

### 비용 추정

변경 후보 문단 50개 × 1.5K 토큰을 저가 모델로 분류하면 약 $0.015, 최종 보고서(입력 20K + 출력 3K)를 상위 모델로 쓰면 약 $0.095다. 비교 1건당 약 $0.1이고 임베딩은 0원이다. 단가는 2차 출처(2026-08) 기준이며 공식 가격 페이지와 모델 라인업이 달라, 제출 직전에 공식 페이지로 갱신하고 기준일을 표기한다.

**하지 않는 것**: LLM에 매수·매도 판단을 시키지 않는다. 숫자 계산, 증감률, 순위는 모두 코드가 한다. LLM이 SQL을 직접 만들지 않고, 정해진 Tool만 호출한다.

## 7. 데이터 전략과 보안·거버넌스

데이터는 전부 OpenDART에서 가져오고, 숫자와 본문을 다른 저장소에 둔다(강의 5장 원칙).

| 데이터 | 출처 | 저장소 | 비고 |
| --- | --- | --- | --- |
| 회사 고유번호 | OpenDART `corpCode.xml` | MariaDB | 종목코드 → 8자리 corp\_code 변환 |
| 공시 목록·접수일 | OpenDART `list.json` | MariaDB | 접수일(rcept\_dt) 기준으로 분석 시점 판단 |
| 재무제표 수치 | OpenDART `fnlttSinglAcntAll.json` | MariaDB | 2015년 이후 사업연도만 제공 |
| 공시 본문 | OpenDART 원문 | Chroma(섹션 단위 청크) | 접수번호 + 섹션 + 문단 번호를 인용 ID로 사용 |

- **보고서 코드**: 1분기 11013, 반기 11012, 3분기 11014, 사업보고서 11011. "전년 동기 비교"는 같은 보고서 코드의 전년도 데이터를 쓴다.
- **호출 한도**: 일 20,000건을 넘으면 오류 코드 020이 반환된다. 시연 대상 종목을 10\~30개로 정하고, 받은 데이터는 DB에 캐시해 같은 요청을 다시 보내지 않는다. 한도 수치는 개발 시작 시 OpenDART 공식 안내에서 재확인한다.

**원문 파싱이 가장 큰 기술 위험이다**: `document.xml`은 정상적인 XML이 아니다. 삼성전자 2024 사업보고서 실측 사례 기준이다([GitHub PR](https://github.com/sykang169/google-python-sample/pull/17)).

- ZIP 안에 본문 `{rcept_no}.xml`과 감사보고서 XML이 함께 있다. 첫 파일을 고르면 감사보고서를 읽는다.
- 이스케이프 안 된 `&`가 649개라 표준 XML 파서가 첫 지점에서 멈춘다. lxml `recover=True`는 텍스트를 조용히 버린다.
- 표 셀이 `TD/TH`가 아니라 `TE/TU` 태그여서, `TD/TH`만 읽으면 셀 225개가 오류 없이 빠진다.
- utf-8로 선언됐지만 실제로 cp949인 파일, 본문 속 가짜 태그(`<시장 동향>`)가 있다.
- 소송·우발부채·특수관계자 거래는 API가 없어 원문 파싱으로만 얻는다([DS002 목록](https://opendart.fss.or.kr/guide/main.do?apiGrpCd=DS002)).

권장 파서: 본문 파일명으로 선택 → utf-8 시도 후 cp949 → `&` 최소 수리 → `TITLE` 기준 섹션 분할 → BeautifulSoup으로 `P`·`TD/TH/TE/TU` 모두 수집. 원문 섹션 파싱을 끝까지 해 주는 라이브러리는 없고, dart-fss `extract`는 기본값이 오류를 숨기므로(`skip_error=True`) `requests` 기반 얇은 자체 래퍼를 쓴다.

**숫자 비교는 당기 보고서 한 건으로 끝낸다**: 당기 보고서 안의 `thstrm_*`와 `frmtrm_q_amount`(3개월)·`frmtrm_add_amount`(누적)를 비교하면 회사가 재작성한 전기 수치를 그대로 쓸 수 있다. 단, 재무상태표의 `frmtrm_amount`는 분기보고서에서 전기말 기준이므로 "전년 동기말"이 필요하면 전년 보고서를 따로 부른다. 매칭 키는 `sj_div + account_id`이고, `account_id`가 "-표준계정코드 미사용-"이면 정규화한 계정명으로 폴백한다. 오류 코드 013(데이터 없음)도 HTTP 200으로 오므로 응답 본문의 `status`를 검사한다.

**약관**: [OpenDART 이용약관](https://opendart.fss.or.kr/intro/terms.do)에 상업 이용 금지나 출처 표시 의무 조항은 없다. 다만 API 저작권은 금감원에 있고(제16조), 정확성은 보증되지 않으며(제23조), 인증키 제3자 공유는 금지다(제19조②). 키는 서버 환경변수 1개로만 관리하고, 화면에 "출처: DART"와 원문 링크를 붙인다.

**보안·거버넌스**: 공시는 공개 데이터라 강의의 PII 통제 중 상당 부분은 우선순위가 낮다. 대신 아래는 반드시 유지한다.

| 통제 | 이유 | 강의 근거 |
| --- | --- | --- |
| Output Filter(투자 권유·수익 보장 표현 차단) | 분석 결과가 매매 권유로 읽히면 안 됨 | 9장, 부록 A §6 |
| 문서 격리(`<document>` 태그) + 문서 인젝션 Red Team | 공시 본문도 외부 문서이므로 간접 인젝션 대상 | 4장, 9장 |
| AI 생성 결과 고지 문구(코드로 삽입) | 환각 위험 고지 | 부록 A §6 |
| append-only 감사 로그 + request\_uid | 리포트별로 근거·모델·프롬프트를 추적 | 9장, 10장 |
| Kill Switch | 오작동 시 즉시 중단 | 9장 |
| HITL: 리포트 게시 승인 | AI 결과가 검토 없이 공유되지 않음 | 8장 (주문 → 게시로 대체) |
| 관심 종목 등 사용자 데이터 최소 수집 | 개인 데이터 범위 축소 | 2장 |

강의의 Core Zone(가상 원장·주문)은 우리 서비스에 주문 기능이 없으므로 구현하지 않는다. 대신 그 자리에서 배운 "AI에게 쓰기 권한을 주지 않는다" 원칙을 리포트 게시 권한에 적용한다.

### 규제: 법적 의무와 설계상 선택을 나눈다

**법적 의무**

- **AI 기본법(2026-01-22 시행)**: 생성형 AI로 서비스를 제공하므로 약관·첫 화면의 사전 고지와 생성물 표시가 의무다. 사전 고지 위반은 3천만원 이하 과태료 대상이고, 과태료는 최소 1년 계도기간 동안 유예된다([세종](https://shinkim.com/kor/media/newsletter/pdf/3114), [뉴시스](https://mobile.newsis.com/view/NISX20260121_0003484769)). 리포트마다 "AI 생성·사람 검토" 배지를 단다. 공시 요약은 고영향 AI 10개 영역에 들 가능성이 낮다.
- **개인정보**: 관심 종목 기능은 이메일과 종목코드만 받고, 보유 수량·금액은 받지 않으며, 이용자 정보를 LLM 프롬프트에 넣지 않는다. 공시에 실린 임원 정보는 공시 목적 안에서만 다루고, 인물을 평가하는 문장이나 인물 중심 페이지는 만들지 않는다.

**규제 밖에 머무르기 위한 설계**

- **자본시장법**: 2024-08-14 개정법상 불특정 다수에게 같은 내용을 일방향으로 주는 조언은 투자자문업이 아니다. 대가를 받으면 유사투자자문업 신고, 유료 회원과 양방향 소통을 하면 투자자문업 등록 대상이다([법무법인 대륜](https://www.daeryunlaw.com/newsletter/news/53)). 그래서 **무료, 모든 이용자에게 같은 내용, 매수·매도·목표가·"저평가" 같은 가치판단 없음**을 유지한다.
- **표현 기준**: 유사투자자문업 금지 광고 목록(제101조의2)과 금감원 적발 사례(2025년 105개사 133건, [경향신문](https://www.khan.co.kr/article/202604201200001/))를 금지어 필터의 기준으로 쓴다.
- **확장 시 위험**: "AI 공시 요약이 투자 조언인가"에 대한 금융위 법령해석은 찾지 못했다. 대화형 Q&A는 공시 사실 질의로 제한하고 투자 판단 질문은 거절 템플릿으로 처리한다. 유료화나 Q&A 확대 전에 금융규제민원포털에 법령해석을 신청한다.

**자율 준수(금융회사 대상 기준을 벤치마크)**: 금융위 「금융분야 AI 가이드라인」 개정안(2026-06-18 발표)의 사람 최종 결정, 설명가능성, 킬스위치 원칙과 금융보안원 「금융 AI 안전성·신뢰성 평가 프레임워크」(2026-08)를 기능별로 매핑해 부록에 넣는다. 공시레이더는 금융회사가 아니어서 직접 적용 대상은 아니다.

조문은 2차 출처로 확인했으므로 제출 전에 law.go.kr 원문과 대조한다.

## 8. 개발 일정과 팀 역할

남은 기간은 약 5주다. LLM 핵심 기능을 3주차에 끝내야 4주차에 통합하고 5주차에 평가할 수 있다.

&#91;embedded content: 개발 로드맵 · 5주, 관문 3개\]

- **1주차를 파싱 스파이크로 쓴다**: 삼성전자와 중견기업 2\~3곳의 원문으로 본문 파일 선택, `&` 수리, `TE/TU` 셀 수집을 먼저 검증한다. 같은 주에 평가셋 라벨링 가이드를 쓴다.
- **11월 12일에 데모 데이터 캐시를 고정한다**: 2026년 3분기보고서 법정 기한(11/14)이 토요일이라 제출이 11/13\~16에 몰릴 가능성이 크고, 마감 시즌에는 API 지연 경험담도 있다. 주 시연은 2026 반기 vs 2025 반기로 하고, 3분기 실시간 비교는 보너스로 둔다.
- **11월 11일 기능 동결**: 완성되지 않은 "확장" 기능은 발표 범위에서 뺀다.

## 9. 기대효과, 리스크, 어필 포인트

**기대효과**: 분기 공시 한 건을 비교하는 일이 "두 문서를 나란히 읽기"에서 "변경점 리포트를 검토·승인하기"로 바뀐다. 시간 단축 폭은 지금 말할 근거가 없으므로, 발표 전에 팀원이 직접 수작업 비교 시간과 시스템 사용 시간을 재서 숫자로 제시한다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 원문 XML 파싱 실패·셀 누락 | 섹션 diff가 오류 없이 틀림 | 1주차 스파이크, 파싱 결과 셀 수 검증, 실패 문서는 시연 제외 |
| LLM 환각·가짜 인용 | 리포트 신뢰도 붕괴 | 인용 ID 스키마 강제, 코드 수치 대조, LLM 판정 2단, "확인 불가" 표기 |
| 3분기 제출 몰림·API 지연 | 시연 데이터 미확보 | 11/12 캐시 동결, 반기 비교를 주 시연으로 |
| 일정(약 5주) | 기능 미완성 | 11/11 기능 동결, 확장 기능 제외 |
| 범위 확대(포트폴리오 트래커 병합) | 차별점 희석, 개인정보 범위 확대 | MVP는 관심 종목 목록까지만 |
| 규제 경계 | 투자자문 해당 소지 | 무료·일방향·가치판단 없음 유지, Q&A는 공시 사실로 제한 |
| 대형 증권사 진입 | 차별점 약화 | 섹션 diff + 인용 검증 + 정량 평가를 앞세움 |
| LLM 비용·단가 변동 | 실험 비용 증가 | 변경 후보만 전송, 결과 캐시, 경량 모델 라우팅, 제출 직전 단가 재확인 |
| OpenDART 호출 한도(일 약 20,000건) | 수집 중단 | 시연 종목 제한, `rcept_no` 영구 캐시 |

**나중에 다시 검토할 계기**: 유료 구독 도입 시 유사투자자문업 신고, 챗봇 Q&A 확대 시 투자자문업 등록, 포트폴리오 연동 시 개별 자문·개인정보, 증권사 배너 광고 시 금융소비자보호법상 광고 주체 여부, 금융회사 대상 B2B 시 망분리·금보원 평가를 각각 검토한다.

**포트폴리오·면접 어필 포인트**

- **차별성**: "수치 비교"가 아니라 "수치가 바뀐 이유를 본문에서 찾아 근거와 함께 제시". 강의가 미해결로 남긴 인용 검증과 출력 재작성을 구현했다.
- **학술 정합성**: Lazy Prices와 From Text to Alpha의 설계(변화 측정 대상 섹션, LLM은 추출·임베딩은 측정)와 일치한다. 국내 사업보고서에 적용한 소규모 사례 자체가 기여가 될 수 있다(KCI·RISS 선행연구 검색 후 주장).
- **실측 근거**: 원문 XML 함정(셀 225개 무음 누락 등)을 해결한 파서와 그 검증 지표.
- **정량 평가**: 평가셋 40건 기반 변화 탐지 F1, 인용 정밀도, 수치 일치율, 건당 비용. 대부분의 팀은 데모만 보여 준다.
- **금융권 통제 구조**: 감사 로그, Kill Switch, HITL, 투자 권유 차단, 금융 AI 가이드라인 원칙과 기능의 1:1 매핑표.
- **발표의 핵심 장면**: 실제 기업 한 곳의 리스크·소송 섹션에서 새로 생긴 문단을 원문 위치와 함께 짚고, 같은 분기 재무 수치 변화와 연결한 한 화면.
