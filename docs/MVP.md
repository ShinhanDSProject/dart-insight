# DART Insight MVP

- 작성일: 2026년 10월 19일
- 개발 마감일: 2026년 11월 18일
- 문서 상태: 대화에서 합의한 요구사항을 정리한 MVP 초안
- 목적: 개발 범위를 공유하고 후속 PRD·ERD 작성의 기준으로 사용한다.
- 화면 설계 기준: 이 문서의 합의된 MVP를 기준으로 한다. 대화에서 공유한 이미지는 참고 예시이며 기능 범위나 화면 배치를 제한하지 않는다.

## 1. 서비스 목적과 핵심 사용자

기업의 정기공시 분석을 필요로 하는 모든 사람이 긴 보고서를 직접 대조하지 않고도 기업의 사업과 재무 상태, 기간별 변화를 이해하도록 돕는다. 사용자를 주식 초보자에 한정하지 않으며, 공시에 익숙하지 않은 사람도 이해할 수 있는 설명을 제공한다.

| 대표 사용자 | 이용 목적 | 제공 가치 |
| --- | --- | --- |
| 주식 초보자를 포함한 투자자 | 관심 기업의 사업·재무 변화 이해 | 변경 내용과 수치 증감을 원문 근거와 함께 확인 |
| 취업준비생 | 면접 전에 지원 기업의 사업과 최근 변화 파악 | 주요 사업·제품·서비스 및 기간별 변화 이해 |
| 거래를 검토하는 다른 기업의 담당자 | 거래 후보 기업의 추세를 살펴 거래 판단에 참고 | 사업·재무 추세와 관련 원문을 비교해 판단 근거 확보 |
| 그 외 기업 분석이 필요한 사용자 | 조사·연구 등 다양한 목적의 기업 이해 | 동일한 공시 비교·요약·근거 확인 기능 활용 |

위 구분은 대표 이용 사례이며 가입 자격이나 별도 권한 역할이 아니다. MVP는 공통 분석 화면을 제공하며, 사용자 유형별 전용 화면이나 채용·거래 여부의 자동 판정 기능을 추가하는 것은 아니다.

사용자는 기업을 즐겨찾기하고, 새 정기공시의 분석 완료 알림을 받은 뒤 이전·현재 보고서를 나란히 확인한다. 변경 사항, 수치 증감, 쉬운 요약과 공시 변화 평가를 원문 근거와 함께 제공한다.

## 2. 확정한 범위

| 항목 | 요구사항                                                                                                               |
| --- |------------------------------------------------------------------------------------------------------------------------|
| 데이터 출처 | DART 공시 자료만 사용한다. OpenDART를 공식 수집 경로로 활용한다.                                                       |
| 분석 대상 기업 | 한 명 이상의 사용자가 즐겨찾기한 기업                                                                                  |
| 지원 공시 | 아래 정기공시 5종                                                                                                      |
| 비교 범위 | 보고서 전체 본문과 표의 추가·삭제·수정 및 수치 증감                                                                    |
| 재무제표 비교 | 재무제표 종류별·계정별 이전 값, 현재 값, 증감액, 증감률 및 원문 근거                                                   |
| 비교 방식 | 오른쪽 현재 보고서를 유지한 채 왼쪽을 전년 동기 또는 직전 분기(직전 기간)로 전환. 과거 보고서 직접 선택도 제공         |
| AI 비교 기준 추천 | DART 원문과 확보된 기간별 수치에 근거해 전년 동기·직전 분기 중 적합한 비교 기준 및 이유 제시                           |
| 로그인 | 소셜 로그인. 제공자는 추후 결정                                                                                        |
| 알림 | 웹사이트 내부 알림함. 새 정기공시 분석 완료 후 생성                                                                    |
| 사용자 화면 | 왼쪽: 전년 동기 또는 직전 분기 보고서를 선택해 표시, 오른쪽: 현재 보고서 유지, 아래: 선택한 비교 기준에 따른 요약·평가 |

### 지원 정기공시

| OpenDART 상세 유형 | 공시 종류 |
| --- | --- |
| A001 | 사업보고서 |
| A002 | 반기보고서 |
| A003 | 분기보고서 |
| A004 | 등록법인결산서류(자본시장법 이전) |
| A005 | 소액공모법인결산서류 |

정기공시 5종 모두가 목표 범위다. 서류별 원문 확보 가능 여부, 구조 및 비교 가능한 기간은 실제 자료로 검증한다. 특히 과거 제도에 따른 결산서류에 사업·반기·분기보고서의 주기를 일괄 적용하지 않는다.

## 3. 핵심 사용자 흐름

1. 소셜 로그인한다.
2. 기업을 검색하고 즐겨찾기에 등록한다.
3. 해당 기업의 보고서 및 분석 결과를 확인한다. 최초 등록 기업의 자료가 준비되지 않았다면 준비 상태를 확인한다.
4. 서버가 새로운 정기공시를 발견하면 수집·비교 분석한다.
5. 분석 완료 후 결과를 게시하고 즐겨찾기 사용자에게 웹 알림을 생성한다.
6. 사용자는 알림을 클릭해 변경 전후 보고서와 요약·평가를 확인한다.
7. 오른쪽 현재 보고서를 유지한 채 왼쪽 보고서를 전년 동기 또는 직전 분기로 전환한다. AI의 비교 기준 추천과 근거를 참고하되 사용자가 직접 선택한다.
8. 필요하면 과거 보고서 두 개를 직접 선택해 비교한다.

## 4. MVP 기능

### 4.1 소셜 로그인과 즐겨찾기

- 소셜 로그인으로 사용자를 식별한다.
- 기업을 검색하고 즐겨찾기에 등록·해제한다.
- 개인별 즐겨찾기 목록을 제공한다.
- 같은 기업·보고서 조합의 분석 결과는 사용자 간 공유한다.
- 최초 즐겨찾기 등록 시 해당 기업의 비교에 필요한 과거 자료를 준비한다. 과거 자료의 초기 일괄 수집 범위는 PRD에서 결정한다.

### 4.2 정기공시 자동 수집

- OpenDART 공시검색 API에서 정기공시 유형 `A`를 지정해 기업 전체 목록을 묶어서 조회한다.
- 목록에서 즐겨찾기 대상 기업을 식별해 원문 수집·분석을 진행한다.
- 접수번호로 새 공시와 기존 공시를 구분한다.
- 페이지가 여러 개이면 필요한 페이지를 조회해 누락을 방지한다.
- 원문과 분석 결과를 저장해 동일 자료의 반복 다운로드·분석을 줄인다.
- 폴링 주기는 미확정이다. 앞서 논의한 5분·10초는 확정 요구사항이 아니며, 정기공시 중심의 운영 조건과 실제 API 한도로 결정한다.
- DART 공개 즉시 수집 또는 특정 초 이내 반영을 보장하는 요구사항은 두지 않는다.

### 4.3 전체 보고서 비교

일부 주요 항목만 선별하지 않고 보고서 전체 본문과 표를 비교 대상으로 삼는다.

- 같은 의미의 목차·항목을 대응시켜 변경 전후를 보여준다.
- 추가된 내용, 이전에 있었지만 현재 확인되지 않는 내용, 수정된 내용을 구분한다.
- 같은 항목의 수치가 커지거나 작아진 경우 이전 값·현재 값·차이를 보여준다.
- 전년 동기와 직전 분기(직전 기간) 비교를 선택할 수 있다. 오른쪽 현재 보고서는 유지하고 왼쪽 비교 보고서만 바꾼다. 두 과거 보고서를 동시에 세 칸으로 펼치는 구성이 아니라 두 기준을 선택·전환하는 방식이다.
- 비교 기준 전환 시 본문·수치·증감·요약·평가·원문 근거를 선택한 보고서 쌍에 맞춰 함께 갱신한다. 준비되지 않은 결과는 분석 대기 상태로 표시하고 이전 비교 결과를 혼합하지 않는다.
- 같은 기업의 과거 보고서 두 개를 선택해 비교할 수 있다.
- 과거 비교는 최신 보고서에만 한정하지 않는다. 실제 제공 가능한 자료와 비교가 어려운 항목은 화면에서 명시한다.
- 전체 비교를 목표로 하되, 대응 실패나 추출 실패를 숨기거나 모든 변경을 완벽하게 탐지했다고 표시하지 않는다.

### 4.4 재무제표 종류별·계정별 수치 비교

재무제표 비교를 독립된 핵심 기능으로 제공한다. 매출·영업이익 등 일부 대표 지표나 문장 요약에 한정하지 않고, 보고서에서 확인되는 재무제표의 세부 계정까지 비교한다.

- 재무상태표, 손익계산서·포괄손익계산서, 현금흐름표, 자본변동표를 종류별로 선택한다. 해당 보고서에 없는 표는 미제공 상태를 표시한다.
- `자산 → 유동자산 → 현금 및 현금성자산`처럼 원문의 계정 계층과 합계·세부 항목 관계를 유지한다.
- 대응 계정마다 이전 값·현재 값·증감액·증감률을 나란히 표시한다.
- 증가·감소는 색상뿐 아니라 `▲`·`▼`, 부호, 증감액과 텍스트로 강조한다. 증가·감소 표시와 긍정·부정 평가는 구분한다.
- 전체 계정 보기와 변경 항목만 보기를 제공한다. 변경 항목만 볼 때도 상위 계정의 맥락을 유지한다.
- 연결·별도 기준, 통화·단위, 각 값의 기준일 또는 대상 기간, 누적·단일 기간 여부를 표시한다.
- 계정 행을 선택하면 이전·현재 보고서의 해당 원문 근거와 설명을 확인할 수 있다.
- 한쪽에만 있는 계정, 계정명 변경, 비교 기준 불일치와 추출 실패를 구분한다. 없는 값을 0으로 간주하지 않는다.
- 수치의 추출·대응 근거를 보존하고 증감 계산은 검증 가능한 산식으로 처리한다. AI는 그 결과를 설명한다.

### 4.5 AI 요약과 공시 변화 평가

- 투자자·취업준비생·기업 담당자 등 다양한 사용자가 활용하도록 변경 내용을 요약하며, 공시 초보자도 이해할 수 있는 표현을 사용한다.
- 각 설명에 해당하는 이전·현재 원문 근거를 연결한다.
- 공시에 없는 원인·전망을 사실처럼 덧붙이지 않는다.
- 사용자가 요청한 평가 단계는 다음과 같다.

| 단계 | 사용자 요청 의미 |
| --- | --- |
| 강한 긍정 | 매우 호재로 해석되는 변화 |
| 긍정 | 호재로 해석되는 변화 |
| 부정 | 악재로 해석되는 변화 |
| 강한 부정 | 매우 악재로 해석되는 변화 |

평가 기준과 종합 방식은 아직 확정하지 않았다. 위 단계는 기능 요구사항이며, 실제 공시를 분류하는 판정 규칙은 PRD와 AI 검증 단계에서 정의한다.

**설계 제안(미확정):** `중립`과 `판단 유보`를 추가하고 화면 명칭을 `공시 변화 평가`로 사용한다. 상반된 근거, 미미한 변화, 자료 부족을 억지로 긍정·부정으로 분류하지 않기 위한 제안이다. 평가를 매수·매도 지시나 주가 예측으로 표현하지 않고 원문 사실과 AI 해석을 구분한다.

### 4.6 AI 비교 기준 추천

- 기업의 공시 내용과 확보된 기간별 수치를 바탕으로 전년 동기 또는 직전 분기 비교를 추천하고 이유를 설명한다.
- 계절성에 관한 공시 서술이나 충분한 기간의 수치 패턴이 근거로 확인되는 경우 전년 동기 비교를 추천할 수 있다.
- 예시 문구: “공시에서 계절적 수요의 영향을 설명하고 있어, 작년 같은 기간과 비교하는 것을 추천드립니다.” 실제 표시 시 해당 원문·대상 기간·관련 수치를 함께 제시한다. 이 문구는 기능 예시이며 특정 기업에 대한 판단이 아니다.
- 최근 변화 확인에 직전 분기 비교가 적합하다고 판단하면 그 이유와 비교 기간을 제시한다.
- 보고서 두 건의 증감만으로 계절성이 강하다고 단정하지 않는다. 근거가 부족하거나 서로 충돌하면 추천을 유보하고 이유를 표시한다.
- 추천은 비교 기준 선택을 돕는 기능이며, 사용자의 선택을 자동으로 덮어쓰지 않는다. 사용자는 추천 적용 또는 다른 기준 선택을 할 수 있다.
- 추천 적용 시 왼쪽 보고서와 관련 결과를 갱신하고 오른쪽 현재 보고서는 유지한다. 추천 대상 보고서가 없으면 자료 없음 상태를 표시한다.
- DART 자료만 사용한다는 원칙을 유지한다. 필요한 관측 기간, 계절성 판단 기준, 추천 정확도 검증 방법은 PRD에서 정한다.

### 4.7 웹 알림함

- 즐겨찾기 기업의 새 정기공시 분석이 완료되면 알림을 생성한다.
- 분석 결과로 이동할 수 있는 링크를 제공한다.
- 종 아이콘, 읽지 않은 알림 표시, 읽음 상태 관리를 제공하는 구성을 제안한다.
- 공시 접수 직후가 아닌 분석 완료 시점에 알림을 보낸다.
- 실패·대기 상태에서는 분석 완료 알림을 생성하지 않는다.
- 재시도로 동일 분석 완료 알림이 중복 생성되지 않도록 한다.

## 5. 비교 화면 구성

같은 비교 화면에서 **본문 변경**과 **재무제표 비교** 탭을 제공한다. 두 탭은 선택한 기업과 이전·현재 보고서를 공유한다.

| 위치 | 구성 |
| --- | --- |
| 공통 상단 | 기업명, 오른쪽 현재 보고서 선택(기본 최신), 왼쪽 전년 동기 / 직전 분기 전환 및 과거 보고서 직접 선택 |
| AI 비교 기준 추천 | 추천 기준·이유·DART 근거·추천 적용 버튼. 근거 부족 시 추천 유보 표시 |
| 본문 변경 탭 | 왼쪽 이전 보고서, 오른쪽 최신 또는 선택 보고서. 대응 항목의 추가·삭제·수정을 강조 |
| 재무제표 비교 탭 상단 | 재무제표 종류 선택, 연결·별도 기준, 단위·기준일·대상 기간 표시 |
| 재무제표 비교 탭 본문 | 계정 계층을 유지한 표에 이전 값·현재 값·증감액·증감률 표시. 이전 값은 왼쪽, 현재 값은 오른쪽에 배치 |
| 재무제표 비교 필터 | 전체 계정 보기 / 변경 항목만 보기 |
| 아래 | 변경 사항 요약, 쉬운 설명, 평가 단계 및 근거 |
| 원문 접근 | 문장·계정별 이전·현재 근거와 양쪽 보고서의 DART 원문 링크 |

전년 동기·직전 분기 전환은 본문 변경과 재무제표 비교 탭에 공통 적용한다. 오른쪽 현재 보고서는 고정하고 왼쪽만 바꾸며, 요약·평가도 해당 비교 쌍에 맞춘다. 사용자가 오른쪽 보고서를 직접 바꾸면 그 보고서를 기준으로 비교 대상을 다시 정한다.

전체 변경 내용을 확인할 수 있어야 하며 요약만 제공하는 화면으로 범위를 축소하지 않는다. 긴 보고서의 세부 탐색 방식은 후속 화면 설계에서 정한다.

## 6. 비교 기준과 데이터 해석 원칙

### 비교 예시

최신 보고서가 2026년 반기보고서인 경우:

| 방식 | 이전 보고서 | 현재 보고서 |
| --- | --- | --- |
| 직전 분기(직전 기간) | 2026년 1분기보고서 | 2026년 반기보고서 |
| 전년 동기 | 2025년 반기보고서 | 2026년 반기보고서 |
| 사용자 선택 | 사용자가 선택한 과거 보고서 | 사용자가 선택한 다른 보고서 |

- 보고서의 대상 기간과 실제 접수일을 구분한다.
- 화면의 직전 분기 비교는 직전 기간의 정기보고서를 대응시키며 같은 보고서 종류끼리만 제한하지 않는다. 반기보고서와 1분기보고서를 비교할 수 있으나, 보고서 선택만으로 누적 수치가 단일 분기 수치로 변환되는 것은 아니다.
- 연간 사업보고서·과거 결산서류 등에서 직전 분기 기준을 적용하기 어렵거나 자료가 없으면 그 이유를 표시하며 잘못된 비교를 강제로 구성하지 않는다.
- 문서에서 수치가 바뀐 것과 같은 기준으로 계산한 실적 증감을 구분한다.
- 누적·단일 분기, 연결·별도, 통화·단위, 기준일을 확인한다.
- 반기 누적 매출과 1분기 매출을 직접 비교해 분기 성장률로 표시하지 않는다.
- 문서상 삭제·누락과 실제 사업·계약 종료를 구분한다. 단순 미기재를 기업 활동의 소멸로 단정하지 않는다.
- 비교 자료가 없거나 항목 대응이 어려우면 그 상태를 명시한다.
- 재무상태표는 각 기준일의 잔액을, 손익·현금흐름 등 기간 수치는 대상 기간을 확인해 비교한다. 기간이 다른 원문 값은 그 사실을 표시하고 같은 기간의 성장률처럼 해석하지 않는다.
- 동일 기준에서 증감액은 `현재 값 − 이전 값`으로 계산한다. 이전 값이 양수인 일반적인 경우 증감률은 `(현재 값 − 이전 값) / 이전 값 × 100`으로 계산한다.
- 이전 값이 0이거나 음수인 경우 일반 증감률을 무리하게 적용하지 않는다. 결측·비교 불가 상태를 포함한 표시 규칙과 반올림 기준은 PRD에서 정의한다.
- 정정공시의 버전 선택, 재분석, 알림 기준은 PRD에서 별도로 확정한다.

## 7. 완료 조건 초안

다음은 구현 검증을 위한 제안이며, 성능·정확도 수치는 실제 자료 검증 후 PRD에서 정한다.

- [ ] 소셜 로그인 후 기업을 검색하고 즐겨찾기를 저장·해제할 수 있다.
- [ ] 새 정기공시를 자동 발견하고 즐겨찾기 대상 기업의 원문을 수집할 수 있다.
- [ ] 동일 접수번호를 중복 수집·분석하지 않는다.
- [ ] 보고서 전체를 비교 대상으로 처리하고 추출·대응 실패 구간을 표시한다.
- [ ] 직전 기간·전년 동기·사용자 선택 과거 보고서 비교를 제공한다.
- [ ] 왼쪽 이전 보고서와 오른쪽 현재 보고서에서 변경 전후를 확인할 수 있다.
- [ ] 본문 변경·재무제표 비교 탭에서 선택한 기업과 보고서 조합이 유지된다.
- [ ] 오른쪽 현재 보고서를 유지하며 왼쪽을 전년 동기·직전 분기로 전환할 수 있다.
- [ ] 비교 기준 전환 시 수치·증감·본문·요약·평가·근거가 같은 보고서 쌍으로 갱신되며 결과 대기 상태를 구분한다.
- [ ] AI 비교 기준 추천에 이유와 DART 근거가 표시되고 사용자가 적용하거나 다른 기준을 선택할 수 있다.
- [ ] 계절성 판단 근거가 부족하면 추천을 유보하고, 추천 대상 자료가 없으면 그 상태를 표시한다.
- [ ] 투자자·취업준비생·거래 검토 담당자의 대표 사용 시나리오에서 공통 화면으로 사업·재무 변화와 근거를 확인할 수 있다.
- [ ] 제공된 재무제표 종류별로 합계와 세부 계정의 계층을 유지하며 비교할 수 있다.
- [ ] `유동자산 → 현금 및 현금성자산` 계정의 이전 값·현재 값·증감액·증감률과 양쪽 원문 근거를 확인할 수 있다.
- [ ] 가상 예시의 현금 200억 원 → 150억 원을 감소 50억 원·25%로 표시하며, 유동자산 합계 증가와 구분한다.
- [ ] 변경 항목만 보기에서도 상위 계정의 맥락을 확인할 수 있다.
- [ ] 수치 변화가 색상 외 화살표·부호·텍스트로도 구분된다.
- [ ] 수치 증감의 기간·단위·연결 또는 별도 기준이 표시된다.
- [ ] 0·음수·결측·한쪽에만 있는 계정·기준 불일치를 처리하며 허위 증감률을 생성하지 않는다.
- [ ] 요약과 평가에 원문 근거가 연결된다.
- [ ] 분석 완료 후 즐겨찾기 사용자에게 웹 알림이 생성된다.
- [ ] 수집·분석 실패를 완료로 표시하지 않고 상태를 구분한다.
- [ ] 정기공시 5종 각각의 지원 여부와 제한을 실제 자료로 검증한다.

## 10. 구현 순서 제안

요청 범위는 전체 정기공시 비교로 유지하되, 다음 순서로 검증 범위를 넓힌다. 이는 구현 순서이며 나머지 지원 공시를 임의로 제외하는 결정이 아니다.

1. 대표 기업의 사업·반기·분기보고서로 수집 → 본문·재무제표 전체 비교 → 두 비교 탭의 핵심 흐름을 연결한다.
2. 소셜 로그인·즐겨찾기·자동 분석·웹 알림을 연결한다.
3. 전년 동기·직전 분기 전환, AI 비교 기준 추천, 과거 보고서 선택 비교와 다양한 기업·서식, 나머지 결산서류까지 검증을 확장한다.
4. 정정·누락·실패·동시 요청과 배포 환경을 검증한다.

전체 본문·표 비교와 5종 서류, 과거 자유 비교는 약 한 달 일정에 큰 범위다. 지원 범위 변경이 필요하면 검증 결과와 함께 PM이 결정하며, 이 문서만으로 축소를 확정하지 않는다.
