## 3. 시연 중 외부 장애(OpenDART·LLM) 대비 절차 (Fallback 가이드)

### 3.1 캐시·재사용 동작 원리와 주의사항

1. **결과 조회 URL 직접 진입 시 외부 호출 0회**:
   - `/analyses/11`, `/analyses/10`, `/analyses/8`, `/analyses/9`, `/analyses/6`, `/analyses/4`, `/analyses/1` 및 하위 API(`/summary`, `/financial-changes`, `/text-changes`, `/related-disclosures`, `/documents/{side}`, `/questions`)는 **MariaDB에 저장된 결과만 읽으며 OpenDART나 LLM을 전혀 호출하지 않습니다.**
2. **`POST /api/analyses` 재사용(`reused: true`) 조건과 `outdated` 배지 주의사항**:
   - `AnalysisService.create()`는 같은`(corpCode, currentRceptNo, previousRceptNo, basis)` 조합에 대해 **`status == COMPLETED`이고 `textStatus != FAILED`이며 `analysisVersion == Analysis.CURRENT_VERSION ("m2-17")`인 행**이 있으면 새 작업을 만들지 않고 즉시 기존 분석(`reused: true`, HTTP 200)을 돌려줍니다.
   - 시연 전에 네트워크·LLM이 정상일 때 **에코프로비엠 반기 `YOY`(`20250814001299` → `20260814002535`)와 필요 시 삼성전자 반기·연간(`분석 10`·`8`)을 최신 서버(`m2-17`)에서 1회 실행해 두면**, 시연 중 **`[분석 실행 →]` 버튼 클릭 시 외부 호출 없이 즉시 `reused: true`가 반환**됩니다.
   - 반면 이전 버전(`m2-9`~`m2-16`)에서 생성된 분석(`1`~`11`)은 화면 상단에 `'이 결과는 이전 분석 방식으로 만들었어요… [새 방식으로 다시 분석]'`(`OutdatedNotice`) 배지가 보입니다. **외부 장애 상황에서는 이 배지의 `[새 방식으로 다시 분석]`이나 미갱신 쌍의 `[분석 실행 →]` 버튼을 누르지 말고, 기업 페이지의 `'이미 분석한 비교'` 목록이나 URL(`/analyses/11`, `/analyses/10`, `/analyses/8` 등)로 바로 열어야** 외부 호출 없이 100% 저장된 결과로 시연을 이어갈 수 있습니다.
3. **기업 개요·보고서 목록의 OpenDART 장애 내성**:
   - `ReportService.list(corpCode)`는 OpenDART 동기화(`ReportSyncService.refreshIfStale`)가 실패해도 예외를 던지지 않고 **DB에 이미 저장된 보고서 목록과 `refreshError` 안내만 함께 반환**합니다(`ReportSyncDegradedTest` 검증 완료).
   - 기업 브리핑(`briefing-1`), 전망·계획(`outlook-1`), 약속 대조(`plan-followup-1`)도 `(corpCode, rceptNo, promptVersion)` 기준으로 DB 캐시 테이블을 먼저 조회하므로, 이미 `GENERATED`된 삼성전자·에코프로비엠·SK하이닉스는 OpenDART·LLM이 모두 끊겨도 즉시 반환됩니다.
