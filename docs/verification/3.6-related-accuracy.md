## 3. 채점 방법

연결이 6,636개라 모두 채점하지 않고 표본을 채점합니다. 표본은 `build_sheets.py`가 시드 345로 뽑아 다시 만들어도 같습니다.

**정밀도 표본** [`precision.csv`](3.6-related-accuracy/precision.csv) 208건

- 내용 일치(`STRONG`) 연결 38건 전부
- 분석·규칙마다 같은 종류(`TYPE_ONLY`) 연결을 무작위 최대 10건(14묶음)
- 내용 일치가 있는 변경에서, 2단계가 없었다면(접수일 최근순) 맨 위에 보였을 공시
- 2단계는 연결을 빼지 않고 앞으로 올리기만 하므로, 전체 연결의 정밀도는 1단계만과 1+2단계가 같습니다. 두 번 측정의 차이는 '화면 맨 위 공시'와 '내용 일치' 표시의 정밀도로 봅니다.

**재현율 표본** [`recall.csv`](3.6-related-accuracy/recall.csv) 80건

- 분석마다 문장 변경 20건을 무작위로 뽑았습니다(찾지 못함 포함).
- 채점자는 두 칸을 채웁니다. '붙인 것 중 관련 있는 접수번호'는 서비스가 붙인 공시 가운데 관련 있는 것, '놓친 관련 접수번호'는 [`window-disclosures.csv`](3.6-related-accuracy/window-disclosures.csv)의 그 분석 기간 공시 전체에서 서비스가 붙이지 않았지만 관련 있는 것입니다. 없으면 '없음'이라고 씁니다.
- 원본과 [기재정정]이 함께 있으면 같은 사건으로 보고 하나만 셉니다. 서비스가 그 사건의 어느 한쪽을 붙였으면 놓친 것이 아닙니다.
- 재현율 = 붙인 것 중 관련 있음 ÷ (붙인 것 중 관련 있음 + 놓친 것)

**판정 기준**

- O(관련 있음): 공시가 다루는 사건·거래가 변경 글이 말하는 것과 같다. 예: 우발부채 문단의 소송과 같은 소송의 '소송등의제기' 공시, 자본금 변동 문단의 유상증자와 같은 유상증자 결정 공시
- X(관련 없음): 종류만 같고 다른 사건이다. 또는 변경 글이 그 주제를 말하지 않는다. 예: 일반 회계정책 문단에 붙은 실적 공시, 다른 회사·다른 계약
- ?(모름): 변경 글 앞부분과 공시 제목만으로 판단할 수 없고, 원문을 열어도 정하기 어렵다. 계산에서 뺍니다.
- '원인인가'는 묻지 않습니다. 같은 사건·거래인지만 봅니다(FS-54, D-06).
- 변경 글은 앞부분만 들어 있습니다. 모자라면 '앱에서 보기'나 DART 링크로 원문을 엽니다.

- 같은 종류만 맞은 연결은 정밀도가 3% 아래입니다. 연결 6,636개 중 99.4%가 같은 종류라 전체 정밀도도 2.8%입니다. 미래산업처럼 공급계약 25건이 문단마다 붙는 경우가 소음의 대부분입니다(공급계약 2,070건).
- 재현율 표본에서 놓친 관련 공시 5건(주주총회결과·주주총회소집결의, 주식분할결정·임시주주총회결과, 주식소각결정 정정)은 모두 서비스 규칙에 없는 공시 종류입니다. 규칙이 다루는 종류만 보면 2/2를 찾았습니다. 표본 80개 중 관련 공시가 있는 변경이 6개뿐이라 이 숫자는 흔들림이 큽니다.
- 문장 변경의 82.5%가 '찾지 못함'인 것은 대부분 회계정책·표 머리·임원 정보처럼 수시공시와 관계없는 변경이라 맞는 결과로 봤습니다(재현율 표본 80개 중 74개가 관련 공시 없음).

## 5. 규칙 조정

아래는 측정 결과에서 나온 제안입니다. 이 측정(#345)에서는 코드를 바꾸지 않았고, 1·2는 #436에서 [ADR-0038](../adr/0038-related-disclosure-rule-tuning-from-m8.md)과 함께 반영했습니다(규칙 버전 `related-3`, 6절). 2는 (나)·(다)를 골랐습니다.

1. **소송 내용 일치에 사건 명칭(또는 사건번호) 일치를 요구한다.** 원고만 맞은 연결 18건이 모두 틀렸고, 원고와 사건 명칭이 함께 맞은 1건은 맞았습니다. 원고만 맞으면 '같은 종류'로 둡니다. ADR-0032의 소송 비교 조건을 바꾸는 것이라 새 ADR이 필요합니다.
2. **같은 종류만 맞은 연결을 화면에서 줄인다.** 정밀도가 0~10%라 지금처럼 모두 보여 주면 사용자가 내용 일치를 찾기 어렵습니다. 방법 후보는 (가) 같은 종류는 기본으로 접고 '같은 종류 n건'만 보이기, (나) 문단에 그 주제어(소송·유상증자·계약 등)가 없으면 붙이지 않기, (다) 실적 규칙은 손익계산서·주당이익 주석에만 붙이기입니다. (가)는 화면만 바꾸고, (나)·(다)는 규칙을 바꾸므로 ADR-0030의 결정 변경입니다.
3. 놓친 공시 종류(주주총회결과, 주식분할결정, 주식소각결정)를 규칙에 더할지는 기획(FS-54 범위) 판단이라 여기서 정하지 않습니다.

## 다시 만드는 법

backend를 띄운 뒤 이 폴더에서 차례로 실행합니다. `window_list.py`는 OpenDART 키를 환경변수 `DART_KEY`로만 받습니다(키를 파일에 쓰지 않음).

```bash
python dump_links.py 1 2 3 4          # 분석마다 모든 문장 변경의 연결을 links-<분석>.json으로
python window_list.py 1:00126380 2:01160363 3:00102858 4:00197759   # 기간 공시 목록 window-<분석>.json
python build_sheets.py                # 채점표 3개
python measure.py                     # 채점한 뒤 지표 계산
python pick_check.py                  # 사람이 확인할 20줄 ai-check.csv(시드 345)
```

6절(규칙을 바꾼 뒤)은 새 규칙의 backend에서 연결을 다른 폴더에 받아 같은 판정으로 다시 잽니다.

```bash
mkdir r3 && cd r3 && RULE_VERSION=related-3 python ../dump_links.py 1 2 3 4 && cd ..
python remeasure.py r3 new-links-related-3.csv   # 판정이 없는 '내용 일치'·맨 위 연결이 있으면 멈춤
```

- `dump_links.py`는 환경변수 `BACKEND_URL`(기본 `http://localhost:8080`)의 backend를 부릅니다. 처음 부르면 그 분석의 연결을 계산해 저장합니다. `UNAVAILABLE`·`partial` 응답이나 `RULE_VERSION`(기본 `related-2`)과 다른 규칙 버전이 섞이면 알리고 실패 코드로 끝납니다. 그 결과로는 채점표를 만들지 말고 다시 실행합니다.
- **주의:** `build_sheets.py`는 `precision.csv`·`recall.csv`를 새로 써서 판정 칸을 비웁니다. 채점하기 전에만 실행하고, 채점한 뒤 다시 만들어야 하면 채점한 파일을 먼저 따로 복사해 둡니다.
- `measure.py`는 같은 종류 묶음 가운데 판정이 하나도 없는 묶음이 있으면 계산하지 않고 멈춥니다.
