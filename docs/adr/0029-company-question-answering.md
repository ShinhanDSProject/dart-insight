# ADR-0029: 기업 단위 질문은 브리핑과 같은 보고서에 묻고, 분석 질문의 후보 찾기·답 API를 그대로 쓰며, 따로 저장한다

- 상태: 채택
- 결정한 날: 2026-10-26
- 관련: #365, 노션 기능 기획서 FS-53, ADR-0008·0013·0023·0025

## 맥락

- 분석 질문(ADR-0023)은 두 보고서를 비교한 분석이 있어야만 쓸 수 있다. 기업 개요 탭에서 '주요 제품은?', '회사가 밝힌 위험은?'처럼 최신 사업보고서에 바로 묻고 싶다(FS-53).
- ADR-0023은 '완료된 분석에만 묻는다', 저장은 `analysis_question`(분석 외래 키, 사실 계정 열, 답 평가)으로 정했다. 기업 질문은 분석도 계정 사실도 없다.
- AI 기업 브리핑(ADR-0025)이 이미 기업 하나의 보고서 하나를 고르고(`BriefingService.sourceReport`), 원문을 준비하고(`DocumentService.ensureStructured`), LLM 호출을 분석 밖 단위로 `llm_call`에 남긴다.
- ai-server `POST /internal/answers`는 후보 문단·사실을 받아 질문 거르기·인용 검증·표현 검사·2회 재생성을 한다. 입력이 두 보고서 이름을 요구하는 것 말고는 보고서 하나에도 그대로 맞는다.

## 결정

- **호출 방식**: `POST /api/companies/{corpCode}/questions`는 ADR-0023처럼 동기 호출이다. `GET` 같은 경로는 지금 대상 보고서의 최근 질문 20개다.
- **대상 보고서**: 브리핑과 같은 규칙(최신 사업보고서, 없으면 최신 정기보고서)을 `BriefingService.sourceReport`로 함께 쓴다. 정기보고서가 없으면 404 `REPORT_NOT_FOUND`다.
- **후보 찾기(backend)**: 분석 질문의 낱말 검색 `QuestionRetriever`를 보고서 하나(이전 보고서 쪽은 빈 목록)로 그대로 쓴다. 최대 6개, 문단만, 질문 낱말 절반 이상이 들어 있어야 한다. 섹션 범위 좁히기(`SectionSources`)는 문장 변경에 기대므로 쓰지 않는다. 사실 문장도 없다.
- **답 만들기(ai-server)**: 새 API를 두지 않고 `/internal/answers`를 쓴다. `previousReport`를 선택으로 바꾸고, 없으면 `<context>`에 이전 보고서를 넣지 않는다. 시스템 프롬프트 첫 줄을 '보고서 하나 또는 두 개'로 고쳐 `PROMPT_VERSION`을 `answer-2`로 올렸다. 질문 답은 분석 결과(ADR-0014 분석 버전)에 들어가지 않고 질문마다 프롬프트 버전을 저장하므로 분석 버전은 올리지 않는다.
- **후보가 없을 때**: 분석 질문과 달리 후보가 없어도 ai-server를 부른다. ai-server가 투자 판단 질문이면 `OUT_OF_SCOPE`, 아니면 `NOT_FOUND`로 LLM 없이 끝낸다. 질문 거르기 규칙을 backend에 두 벌 두지 않기 위해서다.
- **저장**: 새 표 `company_question`(보고서 외래 키, 사실·평가 열 없음)에 둔다. LLM 호출은 `llm_call`에 task `answer` 그대로, 새 열 `company_question_id`로 묶는다(`V27__create_company_question.sql`). AI 사용 현황은 작업·모델별 호출에 그대로 잡히고, 질문 상태별 수에는 두 표를 더해 센다.
- **코드 재사용**: 질문 검사(2~200자), 답의 근거 표시 변환(`AnswerMarkers`), AI 서버 답 해석·호출 기록 변환은 `question` 패키지의 공통 코드(`AnswerResults`)로 뺐고 분석 질문과 기업 질문이 함께 쓴다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| `analysis_question`에 `rcept_no`를 더해 함께 저장 | 분석 외래 키·사실 열·평가 열이 null인 행이 섞이고, 분석별 조회·평가 규칙이 복잡해진다 |
| ai-server에 `/internal/company-answers`를 새로 둠 | 검증·프롬프트·가짜 응답이 거의 같은 코드로 두 벌이 된다 |
| `previousReport`에 빈 글을 넣어 보냄 | 프롬프트에 빈 속성이 남고, 보고서가 하나라는 사실이 API에 드러나지 않는다 |
| 후보가 없으면 backend가 바로 `NOT_FOUND` | 투자 판단 질문이 `OUT_OF_SCOPE`가 아니라 `NOT_FOUND`로 보인다(FS-53 수용 기준) |
| 원문 구조로 '사업의 내용'만 후보로(브리핑처럼) | 질문은 주제가 정해져 있지 않다. 낱말 검색이 질문에 맞는 문단을 고른다 |

## 결과

- 좋아지는 점: 원문 캐시·보고서 고르기·낱말 검색·답 검증·표현 검사를 그대로 쓴다. 비용은 AI 사용 현황 한 곳에서 센다.
- 감수하는 점: 낱말 검색이라 같은 뜻의 다른 낱말(예: '고객' ↔ '매출처')은 찾지 못할 수 있다. 처음 묻는 기업은 원문 받기·구조화로 수 초~수십 초 걸린다. 새 사업보고서가 나오면 이전 보고서의 질문은 기록에서 보이지 않는다.
- 지켜야 할 것: 분석 질문과 기업 질문은 같은 `PROMPT_VERSION`을 쓰므로 프롬프트를 바꿀 때 두 흐름을 함께 확인한다.
