# ADR-0038: 관련 수시공시의 소송 '내용 일치'는 원고와 사건 명칭이 함께 맞을 때만 정하고, '같은 종류'의 변경 쪽 낱말은 M8 측정에 맞춰 좁힌다

- 상태: 채택
- 결정한 날: 2026-10-27
- 관련: #436 (3.6), #345·PR #431([M8 측정](../verification/3.6-related-accuracy.md)), ADR-0030(1단계 변경 쪽 낱말을 이 ADR이 대체), ADR-0032(이 ADR이 대체)

## 맥락

- M8 측정(#345)에서 로컬 분석 4곳의 연결 6,636개를 표본 208건으로 쟀다. 판정은 AI가 하고 사람이 20줄을 확인했다(20/20 일치).
- 소송 '내용 일치'(`STRONG`)는 원고만 맞은 연결 18건이 모두 틀렸다. 고려아연에서 원고(와이피씨·영풍)가 같다는 이유로 2025-12-16 신주발행금지 가처분 공시가 다른 사건 문단(신주발행무효의 소, 주총결의취소 소송)에 붙었다. 원고와 사건 명칭이 함께 맞은 1건은 맞았다. ADR-0032는 원고만 맞아도 `STRONG`으로 정했다.
- ADR-0032는 '원고와 사건 명칭이 모두 맞을 때만' 안을 표기 차이('신주발행무효의 소' ↔ '신주발행무효 소송')로 놓친다는 이유로 고르지 않았다. DS005 소송 응답(`lwstLg`)에는 사건번호 필드가 없다(OpenDART 개발가이드 확인: `icnm`·`ac_ap`·`rq_cn`·`cpct`·`ft_ctp`·`lgd`·`cfd`뿐). 사건을 가리킬 값은 사건 명칭뿐이다.
- '같은 종류'(`TYPE_ONLY`)만 맞은 연결은 규칙별 정밀도가 0~10%였고 연결의 99.4%였다. 변경 쪽 낱말이 너무 넓은 것이 원인이다. 예를 들어 섹션 낱말 `주식의총수`에는 '4. 주식의 총수 등' 아래 자기주식 표가 모두 걸리고, `우발부채`에는 약정·담보 표가 걸린다. 글 낱말 `계약`·`공급`·`취득`·`투자`는 회계정책·자기주식·금융자산 문단에도 걸린다. 실적 낱말(`매출액` 등)은 배당·임원 보수 표에도 걸린다.
- 측정 표본으로 조정안을 견줘 봤다(`docs/verification/3.6-related-accuracy.md` 6절). 관련 있다고 판정한 연결 31건 중 30건이 남고, 연결은 6,636개에서 약 2,500개로 준다.

## 결정

- **소송 '내용 일치'**: 원고(`ac_ap`, ADR-0032와 같이 이름마다 나누고 회사 자신은 뺌)와 사건 명칭이 **함께** 대조할 글에 있을 때만 `STRONG`이다(`matched_fields`가 `PLAINTIFF,CASE_NAME`). 하나만 맞으면 일치 필드가 없고 `TYPE_ONLY`로 남는다.
  - 사건 명칭은 공백을 빼고, 끝에 붙은 흔한 꼬리(`신청서`·`신청`·`사건`·`의소`·`소송`·`청구`)를 반복해서 뗀 '핵심'으로 본다. 예: '신주발행무효의 소' → `신주발행무효`, '신주발행금지가처분신청서' → `신주발행금지가처분`. 핵심이 공백을 뺀 글에 있으면 맞은 것이다. 표기 차이('의 소'·'소송')는 이렇게 흡수한다.
  - 핵심이 4글자보다 짧으면 대조하지 않는다('항소' 같은 일반 용어).
  - 코드: `KeyItemMatcher`의 소송 분기와 `caseNameCore`.
- **1단계 변경 쪽 낱말**(`RelatedDisclosureRules.RULES`): 아래 규칙만 바꾸고 나머지(빚 조달·사업 구조 변경·존속 위험, 제목 패턴, 규칙 순서)는 그대로 둔다.

  | 규칙 | 섹션 낱말 | 글 낱말 |
  | --- | --- | --- |
  | 소송 | `소송` (`우발부채` 뺌) | 그대로 |
  | 공급계약 | `수주` (`주요계약` 뺌) | `공급계약`·`판매계약`·`수주` |
  | 자본 조달 | 없음 (`자본금`·`주식의총수` 뺌) | `유상증자`·`신주` (`자본금` 뺌) |
  | 투자 | 그대로 | `타법인`·`출자`·`양수`·`유형자산취득`·`시설투자`·`관계기업` |
  | 실적 | 없음 | 그대로. 단, 섹션 경로에 `재무제표`가 있을 때만 본다 |

  - 실적처럼 '섹션 경로가 이 낱말을 품을 때만 규칙을 본다'는 조건은 `Rule`의 새 항목(`requiredSectionWords`, 비면 제한 없음)으로 둔다. 잠정실적은 재무제표 수치와 같은 실적이라 재무제표 섹션에서만 같은 일을 말한다.
- 규칙 버전 `RULE_VERSION`을 `related-3`으로 올린다. 다음 요청 때 분석마다 다시 계산된다(ADR-0030).
- ADR-0030의 나머지 결정(계산 시점, 공시 목록·DS005 받기, 저장, 실패 처리, 유상증자·양수 '내용 일치' 조건)은 그대로다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| ADR-0032 그대로(원고만 맞아도 `STRONG`) | 측정에서 원고만 맞은 18건이 모두 다른 사건이었다. 화면 맨 위에 '내용 일치'로 올라가 사용자를 틀린 사건으로 이끈다 |
| 사건번호로 대조 | DS005 소송 응답에 사건번호 필드가 없다. 공시 원문(`document.xml`)에는 있으나 원문을 받아 해석하는 일이 따로 생긴다 |
| 사건 명칭을 꼬리 떼기 없이 공백만 빼고 대조(ADR-0032의 방식) | ADR-0032가 지적한 대로 '신주발행무효의 소'와 '신주발행무효 소송'처럼 표기만 다른 같은 사건을 놓친다 |
| 주요정보를 대조했는데 맞지 않은 '같은 종류' 연결은 빼기 | 측정 표본에서 재현율 표본이 찾은 관련 공시 2건을 모두 잃었다. 아틀라스링크처럼 사명이 바뀐 회사는 문단에 새 사명만 있고 DS005에는 옛 사명이 있어, 맞는 연결인데 대조가 실패한다 |
| 화면에서 '같은 종류'를 기본으로 접기만 하기 | 보이는 양만 줄고 연결은 그대로라 정밀도가 오르지 않는다. 엉뚱한 연결은 펼치면 그대로 보인다 |
| 실적 규칙을 그대로 두기 | 관련 연결 1건('사업의 내용'의 분기 영업이익 문단)을 지키는 대신 실적 연결 약 1,557개(정밀도 약 10%)를 남긴다. 재무제표 섹션으로 좁히면 약 683개, 약 19%가 된다 |
| 글 낱말 `신주`를 빼기(주식매수선택권 '신주교부' 소음) | 고려아연의 '내용 일치' 1건이 `신주`로만 걸려 있어 잃는다 |

## 결과

- 좋아지는 점: 측정 표본 기준으로 '내용 일치' 정밀도는 20/38에서 20/20이 되고, 연결은 6,636개에서 약 2,500개로 준다. 관련 있다고 판정한 연결은 31건 중 30건이 남는다. 1단계에 걸리는 B001 공시가 줄어 DS005 호출도 준다.
- 감수하는 점:
  - 보고서가 사건 명칭을 공시와 다르게 줄여 적으면(예: '가처분'만) 같은 사건이어도 '같은 종류'로만 보인다.
  - 낱말은 측정에 쓴 같은 표본을 보고 골랐다. 다시 잰 숫자는 실제보다 좋게 나올 수 있다.
  - '같은 종류'만 맞은 연결의 정밀도는 여전히 낮다(규칙별 0~19%).
  - 섹션 경로에 `재무제표`가 없는 곳의 실적 이야기는 실적 공시와 연결하지 않는다.
- 지켜야 할 것:
  - 낱말이나 조건을 다시 바꾸면 같은 표본으로 다시 재서 측정 문서에 남기고 `RULE_VERSION`을 올린다.
  - 팀이 평가 기업을 정하면(#56) 새 표본으로 다시 잰다.

## 다시 볼 때

- 평가 기업 확정(#56) 뒤 새 표본에서 정밀도·재현율이 이 측정과 크게 다를 때
- 사건 명칭 꼬리 떼기로도 놓치는 표기가 자주 보일 때(꼬리 목록 더하기)
- 결정 로그 '관련 수시공시 처리 범위와 표시 방식'에서 놓친 공시 종류(주주총회결과·주식분할결정 등)를 규칙에 더하기로 할 때
