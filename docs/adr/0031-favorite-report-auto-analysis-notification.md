# ADR-0031: 즐겨찾기 기업의 새 정기보고서는 전년 동기와 자동 분석하고, 결과가 저장된 뒤에 회원별 알림을 만든다

- 상태: 채택
- 결정한 날: 2026-10-26
- 관련: [#38](https://github.com/ShinhanDSProject/dart-insight/issues/38)(6.4), 선행 #37(6.3)·#36(6.2)·#14(2.3)·#29(4.3), [ADR-0027](0027-favorite-report-polling.md), [ADR-0004](0004-async-analysis-job.md)

## 맥락

- 6.4는 즐겨찾기 기업의 새 정기공시 분석이 완료되면 그 회원에게 웹 알림을 만들고, 대기·진행·실패에는 만들지 않으며, 재시도·중복 이벤트에도 같은 알림을 두 번 만들지 않아야 한다. 알림에서 결과로 가고 읽음 여부를 바꿀 수 있어야 한다.
- 6.3(ADR-0027)은 새 보고서를 찾으면 `FavoriteReportFound` 이벤트만 발행하고, 분석은 하지 않는다. 분석은 사용자가 요청할 때만 생겨, 그대로 두면 알림을 만들 완료 분석이 생기지 않는다.
- 분석 하나는 원문 받기(OpenDART)와 비교·요약(ai-server, LLM)을 거쳐 비용이 든다. 정기보고서는 기업마다 1년에 4번이고, 회원당 즐겨찾기는 최대 12곳이다.
- 분석의 완료는 `AnalysisResultService.saveAndComplete` 한 곳에서만 일어나고, 결과 저장과 같은 트랜잭션이다(ADR-0004, EN-2).
- 서버는 한 대로 띄운다. 화면 설계(와이어프레임)는 없다.

## 결정

- 새 보고서를 찾으면(`FavoriteReportFound`) 같은 종류의 1년 전 보고서(전년 동기, `YOY`)를 `ReportPairService`로 골라 `AnalysisService.request`로 분석을 요청한다. 사용자가 요청하는 분석과 같은 길이라, 같은 쌍의 분석이 이미 있으면 새로 만들지 않고 그것을 쓴다. 전년 동기 보고서가 없거나 비교할 수 없으면 기록만 하고 알림을 만들지 않는다(`notification.service.FavoriteReportAnalyzer`).
- 요청하기 전에 그 보고서를 `watched_report`에 넣는다. 분석이 빨리 끝나도 "알림을 만들 분석인지"를 놓치지 않게 하려는 것이다.
- `AnalysisResultService.saveAndComplete`는 완료 트랜잭션 안에서 `AnalysisCompleted(analysisId)`를 발행한다. 알림은 `@TransactionalEventListener(AFTER_COMMIT)`로 커밋된 뒤에만 만든다. 그래서 결과가 저장되지 않은 분석(대기·진행·실패, 저장 중 되돌림)에는 알림이 없다.
- 완료된 분석의 현재 보고서가 `watched_report`에 있고 비교 기준이 `YOY`일 때만, 그 기업을 지금 즐겨찾기한 회원마다 `notification` 한 줄을 만든다. `(user_id, analysis_id)` UNIQUE라 중복 이벤트·재시도에도 한 번이다. 이미 완료된 분석을 다시 쓴 경우(완료 이벤트가 다시 나지 않음)는 요청 직후 같은 방법으로 만든다.
- 알림 API는 `docs/api-spec.md` `/api/notifications`, 표는 `docs/erd.md` `watched_report`·`notification`에 있다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 자동 분석 없이, 누군가 새 보고서로 분석을 요청해 완료되면 알림 | AI 비용은 늘지 않지만 아무도 분석하지 않으면 알림이 오지 않아, 즐겨찾기한 회원에게 알릴 수 없다 |
| 직전 기간(`PREV`)과 비교 | 가장 최근 변화를 보지만, 사업보고서와 분기보고서는 적는 항목이 달라 문장 변경이 많이 보인다 |
| 분석 행에 "자동 요청" 표시 열을 둔다 | 같은 쌍을 사용자가 먼저 분석했으면 그 분석을 다시 쓰므로 표시가 맞지 않는다. 보고서 기준(`watched_report`)이면 누가 먼저 요청했든 알릴 수 있다 |
| 완료 트랜잭션 안에서 알림을 함께 저장 | 알림 저장이 실패하면 분석 완료까지 되돌아간다. 알림은 분석 결과보다 덜 중요하다 |
| 알림 대신 브라우저 푸시(Notification API) | 브라우저를 닫으면 받을 수 없고 읽음 여부를 서버에 남길 수 없다. 분석 진행 화면의 '끝나면 알림 받기'(4.3)는 그대로 둔다 |

## 결과

- 좋아지는 점: 즐겨찾기한 회원은 새 정기보고서가 나오면 비교 결과를 바로 열 수 있다. 사용자 요청과 같은 분석 경로를 써서 결과·재사용 규칙이 같다.
- 감수하는 점: 새 보고서마다 분석 하나의 AI·OpenDART 비용이 든다. 알림 생성은 커밋 뒤 메모리 이벤트라, 그 사이 서버가 꺼지면 그 분석의 알림은 만들어지지 않는다. 분석이 실패하면 알림도 다시 시도도 없다(사용자가 직접 분석할 수 있다). 즐겨찾기를 나중에 추가한 회원은 그 전에 끝난 분석의 알림을 받지 않는다.
- 지켜야 할 것: 알림은 `AnalysisCompleted`의 커밋 뒤에만 만든다. 분석 완료를 다른 곳에서 바꾸지 않는다(EN-2).

## 다시 볼 때

- 서버를 두 대 이상 띄울 때(폴링·자동 분석이 겹친다)
- 자동 분석 비용이 문제가 될 때, 또는 실패한 자동 분석을 다시 시도해야 할 때
- 알림을 놓치면 안 되는 요구가 생길 때(대기 테이블로 바꾼다)
