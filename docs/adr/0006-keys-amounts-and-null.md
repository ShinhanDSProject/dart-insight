# ADR-0006: 회사·보고서는 고유번호·접수번호로 식별하고, 금액은 원 단위 정수, 없는 값은 null로 둔다

- 상태: 채택
- 결정한 날: 2026-10-21
- 관련: [PR #72](https://github.com/ShinhanDSProject/dart-insight/pull/72)(0.3 ERD), [PR #85](https://github.com/ShinhanDSProject/dart-insight/pull/85)(2.4), `docs/erd.md`, 노션 개발 기준 6·7장, 노션 공시·재무 도메인 가이드

## 맥락

- 종목코드는 상장사에만 있고, 상장폐지·코드 변경이 생깁니다. 정기보고서는 정정 공시로 같은 기간에 여러 접수번호가 생깁니다.
- 공시 표의 금액 단위가 원·천원·백만원으로 섞여 있습니다. 소수점 계산은 오차가 생깁니다.
- 값이 없는 것과 0은 다릅니다. 이전 값이 0이거나 없을 때 증감률을 계산하면 무한대나 잘못된 값이 나옵니다.

## 결정

- 회사의 키는 OpenDART 고유번호(`corp_code`, 8자리), 보고서의 키는 접수번호(`rcept_no`, 14자리)입니다. 종목코드는 표시용으로만 씁니다. 분석은 분석 ID와 요청 ID(추적 ID)로 구분합니다.
- 금액은 DB와 API 모두 원 단위 정수(`BIGINT`, JSON 숫자)로 다룹니다. 천원·백만원 표시는 화면에서 바꿉니다. 원문 표의 단위와 변환 전 값은 근거로 남깁니다.
- 없는 값은 null로 두고 0과 구분합니다. 증감액·증감률은 코드가 계산하고, 계산할 수 없으면 계산하지 않은 이유를 `calc_status`로 남깁니다(`CalcStatus`: 이전 값 0·음수·없음, 한쪽에만 있는 계정, 짝을 정할 수 없음, 기간 기준 다름).
- 외부 API의 JSON 필드는 camelCase, 날짜는 `YYYY-MM-DD`(한국 시간)입니다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 종목코드를 회사 키로 쓰기 | 비상장사를 다룰 수 없고, 코드가 바뀌면 기록이 끊깁니다. |
| 금액을 `DECIMAL`이나 실수로 저장 | 원 단위 정수면 `BIGINT`로 충분하고, 실수는 오차가 생깁니다. 단위를 섞어 저장하면 비교할 때마다 변환해야 합니다. |
| 없는 값을 0으로 채우기 | 증감률이 왜곡되고, '공시에 없음'과 '0원'을 화면에서 구분할 수 없습니다. |

## 결과

- 좋아지는 점: 정정 공시와 비상장사도 같은 규칙으로 다룹니다. 증감 계산이 결정적이고, 계산하지 못한 이유를 화면에 보여 줄 수 있습니다.
- 감수하는 점: 화면이 단위 변환과 null 표시를 직접 처리해야 합니다.
- 지켜야 할 것: 새 테이블·API도 이 키와 금액·null 규칙을 따릅니다. LLM에 계산을 맡기지 않습니다([ADR-0012](0012-grounded-summary.md)).

## 다시 볼 때

- 원 단위로 `BIGINT` 범위를 넘는 값이나 외화 금액을 다뤄야 할 때
