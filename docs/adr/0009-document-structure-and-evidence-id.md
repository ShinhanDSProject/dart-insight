# ADR-0009: 원문은 관대한 파서로 목차·문단·표로 나누고, 근거 ID는 `{접수번호}#B{블록 번호}`로 정한다

- 상태: 채택
- 결정한 날: 2026-10-22
- 관련: [PR #101](https://github.com/ShinhanDSProject/dart-insight/pull/101)(4.2), [PR #105](https://github.com/ShinhanDSProject/dart-insight/pull/105)(3.4), [PR #106](https://github.com/ShinhanDSProject/dart-insight/pull/106)(3.5), `ai-server/app/documents/parser.py`, `ai-server/tests/fixtures/documents/README.md`

## 맥락

- 화면에 보이는 문장·표는 모두 원문 위치를 가져야 하고, 사용자가 그 위치로 이동해 원문을 확인할 수 있어야 합니다.
- OpenDART 원문 XML은 형식이 엄격하지 않습니다. 이스케이프 안 된 `&`, 닫히지 않은 태그가 있고, 인코딩도 UTF-8과 CP949가 섞입니다.
- 같은 원문을 다시 받거나 파서를 고치면 위치가 바뀔 수 있습니다.

## 결정

- ai-server는 Python 표준 `html.parser`로 관대하게 읽습니다. ZIP에서 본문 파일(`{접수번호}.xml`)만 읽고, 인코딩은 XML 선언 → UTF-8 → CP949 순서로 시도하며, 이스케이프 안 된 `&`만 고칩니다.
- `SECTION-n`과 첫 `TITLE`로 목차(섹션)를, `P`로 문단을, `TABLE`로 표(셀 목록)를 만듭니다. 섹션·블록 번호는 문서 순서대로 1부터 매깁니다.
- 원문의 표 셀·문단 태그 수와 읽은 수를 대조해, 빠진 내용이 있으면 `PARTIAL`로 남깁니다. 읽지 못하면 `FAILED`와 사유를 돌려줍니다.
- 근거 ID는 `{접수번호}#B{블록 번호}`입니다. LLM 결과의 근거와 화면의 원문 위치가 모두 이 ID를 씁니다.
- backend는 구조화 결과와 파서 버전(`PARSER_VERSION`, 지금 `dart-xml-1`)을 접수번호별로 저장합니다. ai-server의 파서 버전이 바뀌면 다시 구조화합니다.
- 분석의 문장 변경은 분석할 때의 글을 함께 저장합니다. 나중에 원문을 다시 구조화해 위치가 달라졌으면, 화면은 저장한 글을 보여 주고 위치가 달라졌을 수 있다고 알립니다.
- 파서를 시험한 실제 원문은 접수번호와 기대값(섹션 수, 표 셀 수 등)을 테스트 자료 기록에 남깁니다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 엄격한 XML 파서(lxml 등) | 깨진 원문에서 내용을 조용히 버립니다. 버린 것을 알아낼 방법이 없습니다. |
| 문단 글의 해시를 근거 ID로 | 같은 문단이 여러 번 나오면 겹치고, 사람이 읽고 찾아가기 어렵습니다. |
| 섹션 제목 경로 + 섹션 안 순번을 근거 ID로 | 제목이 조금만 바뀌어도 ID가 깨집니다. 접수번호 안에서 문서 순서 번호 하나가 가장 단순합니다. |

## 결과

- 좋아지는 점: 깨진 원문도 내용을 버리지 않고 읽고, 빠진 것이 있으면 알 수 있습니다. 근거 ID 하나로 저장된 원문과 화면 위치를 잇습니다.
- 감수하는 점: 블록 번호는 파서 버전에 묶입니다. 파서를 고치면 같은 원문의 번호가 바뀔 수 있어, 분석 버전을 올리고 옛 결과는 저장한 글로 보여 줍니다.
- 지켜야 할 것: 파서 결과가 달라지게 고치면 `PARSER_VERSION`과 backend `Analysis.CURRENT_VERSION`을 함께 올립니다([ADR-0014](0014-analysis-reuse-and-version.md)).

## 다시 볼 때
