# ADR-0064: 용어 카드도 보고서 설명도 없는 금융·공시 용어는 AI가 근거 없는 일반 설명을 쓰고, 코드가 'AI 일반 설명 · 공시 근거 아님'을 붙인다

- 상태: 제안
- 결정한 날: 2026-11-10
- 관련: [ADR-0061](0061-glossary-term-cards.md)(카드가 없을 때의 정해진 안내 부분을 대체), [ADR-0044](0044-agent-tools-run-in-backend.md)·[ADR-0045](0045-langgraph-agent-step-graph.md)(에이전트 채팅), [ADR-0063](0063-claude-haiku-default-model.md)(기본 모델), #772·#832(용어 카드 120개), AGENTS.md 'AI 기능 규칙'

## 맥락

- 채팅의 용어 질문(TERM Workflow, ADR-0061)은 ① 용어 카드 → ② 카드가 없으면 이 보고서 원문의 설명(근거 질문) → ③ 둘 다 없으면 LLM 없이 정해진 안내 "'{용어}'는 등록된 용어가 없고, 이 보고서에서도 설명을 찾지 못했어요."와 비슷한 카드 버튼으로 끝납니다(`ai-server/app/agent/workflow.py`의 `term_fixed_final`).
- 카드는 2026-11-10 기준 120개입니다(#832). 그래도 초보자가 묻는 금융·공시 용어(예: 공매도, 시가총액, 배당락)는 카드에도, 비교한 정기보고서에도 없는 경우가 많아 ③으로 끝납니다.
- AGENTS.md는 'LLM이 만든 문장에는 근거 ID가 있어야 하고, 없으면 결과에 쓰지 않는다'고 정합니다. ADR-0061도 '정의는 카드에서만, AI는 정의를 만들지 않는다'고 정했습니다. ③에서 뜻을 풀어 주려면 이 규칙에 예외가 필요합니다.
- 사용자 결정(2026-11-10): 카드에 없는 금융 용어도 뭔가 답해 주면 좋겠다. 카드 확장(#832)과 함께, 마지막 단계로 일반 설명을 둔다.
- 기본 모델은 `claude-haiku-5-5`(ADR-0063)라 한 번 부르는 비용은 약 0.0005달러(입력 약 1,500토큰, 출력 약 500토큰 어림)입니다.

## 결정

- **언제:** ③(카드도 보고서 설명도 없음)일 때만 부릅니다. ①·②가 있으면 지금처럼 그것으로 답하고 일반 설명은 쓰지 않습니다.
- **어디서:** ai-server 에이전트 그래프에서 `term_fixed_final` 대신 새 LLM 작업(task `term_general`, 프롬프트는 `app/agent/prompt.py`, `PROMPT_VERSION` 올림)을 `LlmClient`로 한 번 부릅니다(ADR-0008).
- **넣는 것:** 용어 이름만 넣습니다. 회사 이름, 보고서, Tool 결과, 대화 기록, 사용자 정보는 넣지 않습니다. 그래서 답이 이 회사 사실을 말할 재료가 없습니다.
- **출력:** `{ "inScope": bool, "sentences": [string] }`. 금융·회계·공시 용어가 아니거나 뜻을 확실히 모르면 `inScope: false`로 답하게 합니다.
- **코드 검사(통과하지 못하면 최대 2회 다시 생성):**
  - 문장 1~3개, 문장마다 120자 이하, 첫 문장에 용어가 들어 있음
  - 회사를 가리키는 말('이 회사'·'당사'·회사 이름) 없음(카드 근거 검사의 `_COMPANY_WORDS`와 같은 목록)
  - 숫자는 '예를 들어'로 시작하는 문장에만
  - 투자 권유성 표현 검사(`app.compliance`, AGENTS.md 5.5) 통과. 매수·매도·목표주가·'저평가' 같은 가치판단 금지는 그대로입니다
- **답 모양(코드가 조립):** 첫 문장은 코드가 정한 "'{용어}'는 등록된 용어 카드가 없고 이 보고서에서도 설명을 찾지 못해, 일반적인 뜻을 AI가 풀었어요."이고, 그 뒤에 LLM 문장, 마지막에 코드가 정한 "공시 근거가 아닌 일반 설명이라 틀릴 수 있어요."를 붙입니다. 근거 표시(`[n]`)와 `citations`는 없습니다. 비슷한 카드 버튼(`OPEN_GLOSSARY`)은 지금처럼 붙입니다.
- **표시:** 채팅 응답에 `generalExplanation: true`를 두고, 화면은 답 위에 'AI 일반 설명 · 공시 근거 아님' 표시를 붙입니다(`docs/api-spec.md` 채팅 응답 먼저 고침). `aiGenerated: true`와 `ai`(모델·프롬프트 버전·시각)도 다른 AI 답처럼 둡니다.
- **실패하면:** `inScope: false`이거나 2회 다시 생성해도 검사를 통과하지 못하거나 LLM을 쓸 수 없으면 지금의 정해진 안내(③)로 끝냅니다. 실패를 일반 설명처럼 내보내지 않습니다.
- **AGENTS.md:** 'AI 기능 규칙'에 예외를 한 줄 더합니다. "예외로 용어 카드도 보고서 설명도 없는 금융·공시 용어는 근거 ID 없는 일반 설명을 쓸 수 있습니다(ADR-0064). 회사 자료를 넣지 않고, 'AI 일반 설명 · 공시 근거 아님'을 코드로 붙입니다."
- 일반 설명은 카드로 저장하지 않습니다. 자주 나오는 용어는 호출 기록(`llm_call`의 task `term_general`)으로 세어 카드 후보로 봅니다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 지금처럼 정해진 안내로 끝내기 | 카드를 120개로 늘려도 초보자가 묻는 용어를 다 담지 못해, 질문의 상당수가 '찾지 못했어요'로 끝납니다. |
| 카드만 계속 늘리기(놓친 용어를 모아 주기적으로 카드로) | 정확하지만 사용자는 그 자리에서 답을 못 받습니다. 이 ADR과 함께 계속합니다(카드 후보 집계). |
| 웹 검색 결과를 근거로 풀기 | 외부 검색 연동·출처 검증·저작권 확인이 새로 필요하고, 호출 방향(React → Spring Boot → FastAPI) 밖의 외부 의존이 늘어납니다. |
| 회사 자료(재무 값·보고서)를 함께 넣어 '이 회사에서는'까지 쓰기 | 근거 없는 문장과 회사 사실이 섞여 어디까지가 근거인지 흐려집니다. 회사 값은 카드가 있을 때만 씁니다. |

## 결과

- 좋아지는 점: 카드·보고서에 없는 금융·공시 용어도 그 자리에서 뜻을 알려 줍니다. 회사 자료를 넣지 않아 회사에 대한 잘못된 사실을 만들 길이 좁습니다.
- 감수하는 점: 일반 설명의 뜻이 맞는지는 코드가 확인하지 못합니다(틀릴 수 있음을 표시로 알림). 질문마다 LLM 호출이 한 번 늘어납니다(약 0.0005달러). 근거 ID 규칙에 예외가 생깁니다.
- 지켜야 할 것
  - 일반 설명은 ③에서만 씁니다. 카드나 보고서 설명이 있는 용어를 일반 설명으로 대신하지 않습니다.
  - 표시('AI 일반 설명 · 공시 근거 아님')와 마지막 안내 문장은 코드가 붙이고 LLM에게 맡기지 않습니다.
  - 프롬프트에 회사·보고서·사용자 정보를 넣지 않습니다.

## 다시 볼 때

- 일반 설명이 틀렸다는 답 평가나 신고가 나올 때
- `term_general` 호출이 많은 용어가 쌓여 카드로 옮길 때
- 웹 검색 등 근거를 붙일 방법이 생길 때
