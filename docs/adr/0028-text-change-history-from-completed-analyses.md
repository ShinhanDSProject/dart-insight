# ADR-0028: 문장 변경 이력은 완료된 분석을 이어 붙이고 같은 글로 따라가 만든다

- 상태: 채택
- 결정한 날: 2026-10-26
- 관련: [#26](https://github.com/ShinhanDSProject/dart-insight/issues/26)(3.8), 선행 #16(2.5)·#29(4.3), [ADR-0004](0004-async-analysis-job.md)

## 맥락

- 3.8은 고른 문장이 여러 기간의 보고서에서 언제 추가·삭제·수정됐는지 보여 주고, 빠진 기간(자료 없음·분석 안 됨)을 정상 결과처럼 숨기지 않아야 한다.
- 문장 변경(`text_change`)은 보고서 두 개를 비교한 분석마다 저장된다. 바뀐 문단만 행이 있고, 바뀌지 않은 문단은 행이 없다. 분석은 사용자가 요청한 보고서 쌍만 있다(전년 동기·직전 기간·직접 선택).
- 분석 하나를 새로 만들면 원문 받기(OpenDART), 구조화·비교·요약(ai-server, LLM)을 거쳐 수십 초 이상 걸리고 비용이 든다. 팀 공용 OpenDART 키에는 하루 호출 한도가 있다.
- 3.8은 P2이고 화면 설계가 아직 없다.

## 결정

- 이력은 이미 완료된 분석만 이어 붙여 만든다. 이력을 열 때 새 분석을 만들지 않고 OpenDART·ai-server를 부르지 않는다(`analysis.service.TextChangeHistoryService`).
- 고른 분석에서 과거로는 "그 이전 보고서를 현재 보고서로 둔 완료 분석", 미래로는 "그 현재 보고서를 이전 보고서로 둔 완료 분석"을 하나씩 잇는다. 여럿이면 기간이 가장 가까운 보고서와 짝지은 분석을 고르고, 같은 쌍이면 가장 최근에 완료된 것을 쓴다. 한 방향 최대 20개다.
- 분석과 분석 사이에서 글은 "저장된 글이 똑같은 변경 항목"으로 따라간다. 같은 글의 항목이 있으면 그 변경이고(수정·숫자만 바뀜·위치 이동이면 반대쪽 글로 이어 감), 없으면 그 두 보고서 사이에 바뀌지 않았다고 본다. 추가·삭제를 만나면 멈춘다.
- 다음 경우는 "알 수 없음"으로 표시하고 바뀌지 않았다고 보지 않는다: 이은 분석이 건너뛴 보고서와 양 끝 바로 옆 보고서(`NOT_ANALYZED`), 문장 비교가 실패한 분석(`NOT_ANALYZED`), 일부만 비교했거나 같은 섹션에 짝을 정하지 못한 항목이 있는 분석에서 글을 찾지 못한 경우(`REVIEW_NEEDED`).
- 화면에 보이는 글은 근거 위치를 갖는다. 바뀌지 않은 보고서는 행이 없으므로, 그 보고서의 저장된 원문(`document_block`)에서 글이 똑같은 블록을 찾아 위치로 쓴다. 찾지 못하면 글을 보여 주지 않고 '검토 필요'로 두되, 분석상 바뀌지 않았으므로 계속 따라간다.
- 응답 모양은 `docs/api-spec.md`의 `GET /api/analyses/{analysisId}/text-changes/{changeId}/history`에 있다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 빠진 기간의 분석을 이력을 열 때 새로 만든다 | 이력이 촘촘해지지만, 한 번 열 때마다 분석 여러 개를 기다려야 하고 OpenDART 호출과 LLM 비용이 많이 든다 |
| 분석 없이 보고서마다 저장된 원문(`document_block`)에서 같은 글이 있는지 찾는다 | 추가·삭제는 알 수 있지만 수정은 짝짓기(ai-server의 비교)를 다시 해야 알 수 있고, 원문이 저장되지 않은 보고서는 원문부터 받아야 한다 |
| 이력 전용 표에 문장별 이력을 미리 저장한다 | 분석이 끝날 때마다 표를 고쳐야 하고 DB가 늘어난다. 지금 쓰는 쪽은 이 화면 하나다 |

## 결과

- 좋아지는 점: DB 변경과 외부 호출 없이 저장된 결과(분석, 저장된 원문)만 읽는다. 사용자가 분석을 많이 해 둘수록 이력이 촘촘해진다.
- 감수하는 점: 분석을 해 두지 않은 기간은 '분석 안 됨'으로 비어 보인다. 같은 글이 한 분석이나 원문에 여럿 있으면 문서 순서상 첫 항목·블록으로 따라간다. 원문을 저장하지 않은 보고서는 바뀌지 않았어도 '검토 필요'로 보인다. 원문 파서가 바뀌어 같은 문단의 글이 분석마다 조금 다르게 저장됐으면 바뀌지 않은 것으로 보일 수 있다.
- 지켜야 할 것: 바뀌지 않았다는 판단은 "그 분석에 같은 글의 변경 항목이 없음"으로만 한다. 알 수 없는 기간을 '변경 없음'으로 보여 주지 않는다.

## 다시 볼 때

- 사용자가 이력이 비어 있다는 이유로 이 기능을 쓰지 않을 때(빠진 기간을 백그라운드로 분석하는 방법을 다시 본다)
- 원문 파서 버전이 바뀌어 같은 문단의 글이 분석마다 달라질 때
