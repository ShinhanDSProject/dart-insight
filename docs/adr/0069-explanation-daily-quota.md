# ADR-0069: 문장 변경 한 줄 풀이도 AI 서버로 새로 만들 때만 따로 하루 한도로 센다

- 상태: 채택
- 결정한 날: 2026-11-14
- 관련: [ADR-0054](0054-llm-daily-quota.md)(질문·채팅 하루 한도), [ADR-0056](0056-analysis-daily-quota.md)(새 분석 하루 한도), 노션 결정 로그 [발표 전 전체 점검에서 나온 개선을 팀장 위임으로 진행하기](https://app.notion.com/p/417b6afffc6f812f8553f2a4dc7da8b1), `ExplanationService`, `llmquota/`

## 맥락

- `POST /api/analyses/{analysisId}/text-changes/{changeId}/explanations`(3.11)는 로그인 없이 부를 수 있고, 저장된 풀이가 없으면 LLM을 부릅니다. 변경 ID는 목록 API로 누구나 알 수 있어, 한 사람이 변경마다 차례로 부르면 하루 한도 없이 LLM을 부를 수 있습니다.
- ADR-0054는 '매번 새로 부르는' 질문·채팅만 셌습니다. 한 줄 풀이는 변경마다 한 번만 만들어 저장하지만, 분석·변경 수가 많아 상한이 사실상 없습니다(분석 하나에 변경 수백~수천 건).
- 저장된 풀이를 읽거나, 요약에 있는 문장을 쓰거나, 원문이 없어 `NO_SOURCE`로 끝나는 요청은 LLM을 부르지 않습니다.
- 에이전트 채팅의 Tool(`explain_text_change`)도 같은 서비스를 부르는데, 그 채팅 메시지는 이미 질문 한도로 셌습니다.

## 결정

- 한 줄 풀이는 `ExplanationService`가 AI 서버를 부르기 직전에만 하루 한도로 셉니다(새 분석처럼 서비스 안에서 셈, ADR-0056). 저장된 풀이·요약 문장·`NO_SOURCE`는 세지 않습니다. 컨트롤러는 호출자(회원 ID, 아니면 클라이언트 IP)를 넘깁니다. 경로를 `LlmQuotaInterceptor`에 넣지 않습니다(그러면 저장된 풀이를 읽을 때도 셈).
- 질문·채팅과 따로 셉니다(`QuotaKind.EXPLANATION`, 안내 이름 'AI 한 줄 풀이'). 기본값은 비로그인 IP별 30·회원 150·전체 3,000회이고 `app.llm-quota.explanation-*`로 바꿉니다.
- 에이전트 채팅의 Tool이 부를 때는 세지 않습니다(호출자 `null`).
- 넘으면 AI 서버를 부르지 않고 429 `AI_QUOTA_EXCEEDED`와 `Retry-After`를 줍니다(ADR-0054·0056과 같음). 화면은 이 코드를 이미 공통으로 보입니다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 경로를 `LlmQuotaInterceptor`에 넣기 | 저장된 풀이를 읽기만 해도 세어, 이미 만든 풀이를 보는 사람이 한도에 걸림 |
| 질문 한도(`QUESTION`)와 함께 세기 | 바뀐 곳을 훑으며 풀이를 여러 개 여는 흐름이 비로그인 20회 채팅 한도를 금방 써 버림. 풀이 한 번은 문장 항목 하나라 채팅 한 단계보다 훨씬 쌈 |
| 로그인 필수로 바꾸기 | 비로그인으로 분석·근거를 보는 흐름(SC-1)이 막힘 |

## 결과

- 좋아지는 점: LLM을 부르는 공개 API 모두에 하루 상한이 생김. 이미 만든 풀이는 한도와 상관없이 볼 수 있음.
- 감수하는 점: AI 서버를 부르기 전에 세므로, 그 호출이 실패(503)해도 한 번으로 셈(질문·채팅과 같음). 같은 변경을 동시에 처음 요청하면 둘 다 셀 수 있음(저장은 하나). 재시작하면 0부터 다시 셈(ADR-0054와 같음).
- 지켜야 할 것: LLM을 새로 부르는 경로를 더하면, 매번 부르면 인터셉터 목록에, 저장해 다시 쓰면 서비스 안에서 새로 만들 때만 셉니다.
