# ADR-0033: 대표 기업 목록은 공공데이터포털 주식시세정보로 시가총액 순위를 받아 backend가 월 1회 저장하고, 숫자는 내보내지 않는다

- 상태: 채택
- 결정한 날: 2026-10-27
- 관련: [#399](https://github.com/ShinhanDSProject/dart-insight/issues/399)(1.5), [ADR-0002](0002-monorepo-and-call-direction.md), [ADR-0003](0003-opendart-cache-in-backend-parsing-in-ai-server.md), [ADR-0017](0017-auto-increment-id-primary-key.md)

## 맥락

- 첫 화면에 '크고 잘 알려진 기업' 목록을 두어, 무엇부터 볼지 모르는 사용자에게 시작점을 주기로 했다(#399). 순서는 유가증권시장 시가총액 상위로 정한다.
- 우리 서비스는 주가·투자 판단을 다루지 않는다. 시가총액은 순서를 정하는 데만 쓰고 화면에 숫자로 보이지 않는다.
- OpenDART에는 시세·시가총액이 없다. 공공데이터포털 '금융위원회_주식시세정보'(REST, JSON)에 종목별 일별 시세와 시가총액이 있다.
  - 공공누리 제4유형(출처표시·상업적 이용금지·변경금지), 개발계정 하루 10,000건, 기준일 다음 영업일 오후 1시 이후 하루 한 번 갱신, 실시간이 아님
- 순위는 자주 바뀌지 않고, 목록은 첫 화면마다 읽는다. 외부 API가 멈춰도 첫 화면이 깨지면 안 된다.
- 인증키는 환경변수로만 다룬다. 포털 화면의 키가 URL 인코딩된 모양(`%`)이거나 원래 모양(`+`·`/`·`=`)일 수 있다.

## 결정

- 공공데이터포털은 backend만 부른다(`datagokr.client.StockPriceClient`, 주소는 `DataGoKrPaths` 한 곳). 화면과 ai-server는 부르지 않는다(ADR-0002).
- 어제부터 최대 10일 전까지 하루씩 거슬러 `basDt`(기준일)·`mrktCls=KOSPI`로 묻고, 종목이 나온 첫 날을 기준일로 쓴다. 응답의 `mrktCtg`가 `KOSPI`인 행만 쓴다.
- 종목코드(`srtnCd`)를 우리 `company.stock_code`와 이어 고유번호를 찾고, 하나로 이어진 종목만 시가총액(`mrktTotAmt`) 큰 순으로 100곳을 `featured_company`에 저장하고, 순위는 그 안에서 1부터 다시 매긴다. 우리 기업 목록에 없는 종목(우선주 등)과 같은 종목코드의 기업이 여럿인 종목은 뺀다. 기업 목록 받기(`CorpCodeSyncRunner`)가 먼저 돌도록 시작 순서를 정한다.
- 응답의 `totalCount`·필수 항목(`basDt`·`srtnCd`·`itmsNm`·`mrktCtg`·`mrktTotAmt`)이 없거나 페이지가 중간에 끊기면 일부만 저장하지 않고 실패해, 저장된 목록을 지킨다. 호출·해석 예외는 요청 주소(키 포함)가 섞이지 않게 종류만 남긴 예외로 바꾼다. 저장은 목록 전체를 한 트랜잭션에서 지우고 다시 넣는다.
- 서버를 시작할 때 목록이 비었거나 받은 지 `refresh-after`(기본 30일)가 지났으면 받고, 하루에 한 번 같은 조건을 확인한다(`FeaturedCompanySyncRunner`). 키가 없거나 받기에 실패하면 로그만 남기고 저장된 목록을 그대로 쓴다. 서버는 계속 뜬다.
- `GET /api/featured-companies`는 저장된 목록만 읽는다(순위·고유번호·회사명·종목코드·기준일·출처). 시가총액은 응답에 넣지 않는다. 저장된 값은 순위의 근거로만 DB에 남긴다.
- 화면은 기준일과 "출처: 금융위원회, 공공데이터포털"을 함께 보인다(공공누리 출처표시).
- 키는 `DATA_GO_KR_API_KEY` 환경변수로만 받는다. `%`가 있으면 한 번 디코딩한 뒤, 요청할 때 쿼리 값을 직접 URL 인코딩한다(`+`가 공백으로 읽히지 않게). 키는 로그·에러 메시지에 남기지 않는다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| KRX Open API | 공식 출처지만 사용 신청·승인이 필요하고, 같은 시가총액을 공공데이터포털로도 받을 수 있다 |
| 첫 화면 요청마다 공공데이터포털을 직접 부름 | 실시간이 아닌 데이터라 이득이 없고, 호출 한도와 외부 장애가 첫 화면에 그대로 번진다 |
| 목록을 손으로 만든 파일로 둠 | 빠르지만 순위가 낡아도 알 수 없고, 기준일을 코드가 보장하지 못한다 |
| 시가총액을 화면에 함께 보임 | 서비스가 주가 정보처럼 읽히고, 우리는 주가·투자 판단을 다루지 않는다 |

## 결과

- 좋아지는 점: 첫 화면이 외부 API와 떨어져, 받기에 실패해도 저장된 목록으로 뜬다. 호출은 한 달에 10번 안팎이다.
- 감수하는 점: 순위는 최대 한 달 늦다. 우리 기업 목록에 종목코드가 없는 회사는 상위여도 빠진다.
- 지켜야 할 것: 시가총액·주가 숫자를 API와 화면에 내보내지 않는다. 출처와 기준일을 함께 보인다. 상업적으로 쓰지 않는다.

## 다시 볼 때

- 코스닥이나 업종별 목록을 더할 때, 운영 배포에서 갱신 주기를 바꿔야 할 때, 공공데이터포털의 이용 조건이나 응답 항목이 바뀔 때.
