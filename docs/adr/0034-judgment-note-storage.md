# ADR-0034: 판단 노트는 담을 때의 값·문장을 사본으로 저장하고, 원래 위치는 참조로 함께 남긴다

- 상태: 제안
- 결정한 날: 2026-10-27
- 관련: [#413](https://github.com/ShinhanDSProject/dart-insight/issues/413)(6.5, FS-57 내 판단 노트), 선행 #36(6.2 관심 기업), [ADR-0017](0017-auto-increment-id-primary-key.md), [ADR-0020](0020-jwt-access-and-rotating-refresh-token.md)

## 맥락

- FS-57은 로그인한 회원이 분석 결과의 근거(재무 계정 변화, 문장 변경)를 기업별 노트에 담고 메모를 붙여 다시 보고, 지우고, 출처와 함께 내보내게 한다(AC1~AC6).
- 분석 결과는 분석 버전(`Analysis.CURRENT_VERSION`)마다 다시 만들어질 수 있다. 같은 보고서 쌍이라도 새 버전 분석은 새 `analysis` 행이고, 계정·문장 변경의 ID(`financial_change.id`, `text_change.id`)와 묶음·순서가 달라진다. 옛 버전 분석의 행은 지우지 않지만, 화면은 새 분석으로 안내한다.
- AC4는 "담은 뒤 분석 버전이 바뀌면 '위치가 달라졌을 수 있어요'를 보이고, 담은 값은 그대로"를 요구한다. 참조만 저장하면 담은 값을 그대로 보여 준다는 약속을 분석 결과의 수명에 맡기게 된다.
- 노트는 처음 생기는 사용자 작성 데이터다. 회원별로 갈라야 하고(AC3), 사용자 정보는 LLM 프롬프트에 넣지 않는다(AGENTS.md).

## 결정

- 표 하나(`judgment_note_item`, `V35__create_judgment_note.sql`)에 담은 항목 한 줄씩 저장한다. '기업 노트'는 따로 행을 두지 않고 `(user_id, corp_code)`로 묶어 보인다.
- 한 줄에는 두 가지를 함께 둔다.
  - 사본(snapshot): 담을 때 화면에 보인 이름(`snapshot_label`: 재무제표·계정명, 또는 섹션 경로)과 값·문장(`snapshot_text`). 재무 값 문장은 backend가 저장된 계산 결과로 코드에서 만든다(LLM을 쓰지 않음). 화면과 내보내기는 이 사본을 보여 준다.
  - 참조(reference): 분석 ID·분석 버전, 변경 ID(`change_id`), 재무제표(`sj_div`), 근거 보고서 접수번호(`rcept_no`), 섹션·블록 번호. '원래 위치 보기' 링크와 DART 원문 링크를 만든다.
- 사본은 클라이언트가 보낸 글이 아니라, backend가 요청의 분석 ID·변경 ID로 저장된 분석 결과를 찾아 만든다. 화면은 `kind`·`analysisId`·`changeId`·`memo`만 보낸다. 그래서 사본의 값은 늘 저장된 근거와 같다.
- 분석 버전이 바뀌어도 행을 고치거나 다시 연결하지 않는다. 응답의 `outdated`는 저장한 `analysis_version`이 지금 `Analysis.CURRENT_VERSION`과 다르면 true이고, 화면은 '분석 방식이 바뀌어 위치가 달라졌을 수 있어요'를 보인다. 사본은 그대로 둔다.
- 회원은 언제나 토큰의 `sub`로만 정한다(관심 기업 #36과 같음). `/api/notes`는 `SecurityConfig`에서 인증을 요구하고, 다른 회원의 항목은 없는 것과 같이 404(`COMPANY_NOTE_NOT_FOUND`)다.
- 노트 내용(사본·메모)은 ai-server·LLM에 보내지 않는다. 내보내기 Markdown도 backend가 코드로 만든다.
- API는 `docs/api-spec.md` `/api/notes`, 표는 `docs/erd.md` `judgment_note_item`, 코드는 `backend/.../note/`에 있다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 참조(분석 ID·변경 ID)만 저장하고 볼 때마다 분석 결과를 읽음 | 옛 버전 분석을 정리하거나 다시 만들면 담은 값을 보여 줄 수 없다. 노트 목록 한 번에 여러 분석을 다시 읽어야 한다 |
| 사본만 저장 | '원래 위치 보기'(AC1)와 위치가 바뀌었는지 알리기(AC4)를 할 수 없다 |
| 화면이 보낸 이름·값을 그대로 저장 | 화면이 고친 값이나 다른 값을 근거처럼 저장할 수 있다. 근거 없는 수치를 보이지 않는다는 규칙과 맞지 않는다 |
| 기업 노트(`judgment_note`)와 항목(`judgment_note_item`) 두 표 | 노트 자체에 둘 속성(제목·공유 등)이 아직 없다. 회원·기업으로 묶으면 충분하다 |
| 버전이 바뀌면 새 분석의 같은 계정·문장을 찾아 다시 연결 | 계정 키·문장 짝짓기 규칙이 버전마다 달라 맞는지 보장할 수 없다. 틀리게 연결하면 근거가 어긋난다 |

## 결과

- 좋아지는 점: 담은 값과 문장은 분석이 다시 만들어져도 바뀌지 않는다. 노트 목록은 표 하나만 읽는다. 원래 위치로 돌아가는 링크와 DART 원문 링크가 늘 있다.
- 감수하는 점: 같은 내용이 분석 결과와 노트에 두 번 저장된다. 문장 사본은 4,000자까지만 남긴다(더 길면 끝을 줄임). 버전이 바뀐 항목의 '원래 위치 보기'는 옛 분석을 열고, 새 분석의 같은 자리는 사용자가 찾는다.
- 지켜야 할 것: 사본은 backend가 저장된 근거로만 만든다. 노트 내용을 LLM 프롬프트에 넣지 않는다. 회원은 토큰으로만 정한다. 분석 버전을 올리면 옛 노트는 `outdated`로 보인다.

## 다시 볼 때

- AI 답의 인용(FS-57의 `ANSWER_CITATION`)이나 기업 화면의 근거도 담게 될 때(`kind`·참조 열 추가).
- 옛 버전 분석 행을 지우는 정리 작업을 만들 때(참조가 끊겨도 사본은 남는지 확인).
- 노트를 다른 사람과 공유하거나 노트 단위 속성이 생길 때(노트 표 분리).
