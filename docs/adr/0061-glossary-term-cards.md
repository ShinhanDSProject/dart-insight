# ADR-0061: 공시 용어 카드는 backend 저장소 파일 한 곳에 두고, 화면과 채팅이 함께 읽으며, 채팅은 용어 카드를 근거(G{키})로 쓰고 카드가 없으면 보고서의 설명을 찾는다

- 상태: 제안
- 결정한 날: 2026-11-06
- 관련: 기능 기획서 초안 '채팅에서 초보자용 공시 용어 풀이(용어 카드)'(노션, FS 번호 전), FS-36(결과 화면 용어 풀이), [ADR-0044](0044-agent-tools-run-in-backend.md)(Tool은 backend가 실행), [ADR-0048](0048-agent-evidence-kinds-and-recheck.md)(근거 종류, 이 ADR이 한 종류를 더함), [ADR-0060](0060-event-signal-and-sentences.md)(용어 풀이는 출처를 확인한 것만), #581 Workflow(`app/agent/workflow.py`)

## 맥락

- 용어 사전은 지금 frontend `frontend/src/shared/lib/glossary.ts`에만 있습니다. 9개(정정공시·접수번호·고유번호·연결/별도·당기/전기·3개월/누적·계정과목·재작성·영업이익률)이고, 노션 '공시·재무 도메인 가이드' 6장 용어표의 정의 한 줄만 옮겼습니다. 결과 화면 `Term` 컴포넌트(FS-36)와 채팅 액션 `OPEN_GLOSSARY`가 이 파일을 씁니다.
- 채팅 Tool은 backend가 실행합니다(ADR-0044). 그래서 backend가 읽을 수 없는 frontend 파일로는 채팅 답의 근거를 만들 수 없습니다.
- 기능 기획서 초안은 정의 한 줄이 아니라 카드(한 줄 뜻, 쉬운 예시, 확인할 곳, 판단하지 않는다는 문구, 별칭, 관련 용어, 출처, 검토)와 '이 회사에서는'(이 분석의 문장·값)을 함께 보여 주기를 요구합니다.
- 지켜야 할 규칙: 공시 용어는 추측하지 않습니다(AGENTS.md). LLM이 만든 문장은 근거 ID가 있어야 하고, 숫자는 Tool 결과에 있는 것만 씁니다(검토 노드). 주요 사건 용어 풀이(ADR-0060)도 출처를 확인한 것만 보입니다.

## 결정

- **카드 범위(작게):** 카드는 60개 안팎만 둡니다. 대상은 세 가지입니다.
  - 기초 카드: 자산·부채·자본, 재무제표 종류, 매출·비용, 이익, 주식·주주, 상장, 공시, 증감률처럼 아주 쉬운 질문에 답할 기초 용어. 보고서가 이런 기본 개념은 설명하지 않으므로 카드로 둡니다.
  - 초보자가 꼭 알아야 하는 회계 용어
  - 보고서가 스스로 설명하지 않는 증권·공시 용어(유상증자, 전환사채, 배당, 최대주주, 감사의견, 주요사항보고서 등)
  - 카드마다 수준(`level`: `BASIC` 기초, `CORE` 핵심)을 둡니다. 기초 카드 질문에는 '한 줄 뜻 + 이 회사 값'만 짧게 답하고 예시·확인할 곳은 카드를 펼쳐 보게 합니다. 그 밖의 회계 용어는 카드를 만들지 않고 아래 '카드가 없을 때'처럼 이 보고서의 설명으로 답합니다.
- **한 곳:** 카드는 `backend/src/main/resources/glossary/terms.json` 하나에 둡니다. 카드마다 키(`key`, 지금 `GlossaryKey` 이름을 그대로 씀), 용어, 별칭, 한 줄 뜻, 쉬운 예시, 확인할 곳, 판단하지 않는다는 문구, 관련 용어 키, 이 회사 값을 찾을 곳(선택: 체크포인트 키, 재무 계정 이름), 출처(제목·주소), 검토자·검토일을 둡니다. 카드를 고치는 일은 PR로 하고 리뷰가 곧 검토입니다.
- **내보내기 조건:** 출처와 검토일이 없는 카드는 backend가 읽을 때 빼고 화면·채팅 어디에도 내보내지 않습니다. 키·별칭이 겹치거나 관련 용어가 없는 키를 가리키면 서버를 띄울 때 실패합니다.
- **화면:** backend가 공개 API `GET /api/glossary-terms`로 내보낸 카드를 frontend가 받아 `Term`과 채팅 카드에 씁니다. `glossary.ts`의 정의 문장은 지우고 키 목록만 남깁니다.
- **채팅 Tool:** `lookup_terms`(용어·별칭 1~3개)를 더합니다. 찾은 카드는 근거 종류 `GLOSSARY`, 근거 ID `G{key}`로 보냅니다. 줄 글에는 카드 칸을 모두 넣어 숫자 검사가 예시 속 숫자도 확인할 수 있게 합니다. 찾지 못하면 근거 없는 줄로 '등록된 용어가 없어요'와 비슷한 카드 키(코드가 별칭·글자로 고름)를 돌려줍니다. 정의는 만들지 않습니다.
- **카드 예시와 회사 근거를 나눔:** 카드(`G`)는 용어의 뜻과 가정한 예시의 근거일 뿐 회사에 관한 사실의 근거가 아닙니다. `G`만 인용한 문장은 회사 이름이나 '이 회사' 같은 회사 지칭을 쓰지 않고, 그 문장의 숫자는 카드 예시에 있는 것만 씁니다. 회사의 값·문장을 말하는 문장은 회사 근거(`F`·`T`·`#B`·`#V` 등)를 인용해야 합니다. 이 규칙은 검토 노드에 새 반려 규칙으로 더합니다(지금 숫자 검사는 인용한 줄에 숫자가 있는지만 봄).
- **카드가 없을 때(보고서의 설명):** 찾은 카드가 없으면 근거 질문 Tool `answer_with_evidence`로 이 분석 보고서의 원문(주로 주석의 회계정책 문단)에서 회사가 그 용어를 설명한 문단을 찾습니다(ADR-0023의 근거 질문).
  - **검색어는 용어만** 씁니다(질문: "{용어}"). 근거 질문의 문단 찾기(`QuestionRetriever`)는 질문 낱말이 문단에 몇 번 나오는지로 고르므로, '보고서'·'설명' 같은 낱말을 붙이면 그 낱말만 든 문단이 같은 점수로 올라와 정작 설명 문단이 빠질 수 있습니다.
  - **보고서 설명으로 인정하는 조건:** 근거 질문 결과에 원문 문단(`#B`) 인용이 있고, 그 인용 글에 용어가 그대로 들어 있을 때만입니다. 질문 상태(`ANSWERED`)만으로 정하지 않습니다. 재무 계정 사실(`F`)만 있거나 `#B` 인용에 용어가 없으면 '보고서에서 설명을 찾지 못함'으로 봅니다.
  - **답 모양:** 그 문단에서 용어가 든 문장을 원문 그대로 인용해 "이 회사 보고서에 적힌 설명"이라고 밝히고(근거 칩의 인용), AI의 쉬운 말 풀이는 한 문장까지만 붙입니다. 근거 등급은 붙이지 않습니다.
  - **풀이 문장 검사(새 반려 규칙):** 지금 검토 노드는 근거 ID·숫자·원인 표현만 보고 풀이가 인용에서 나왔는지는 보지 않습니다. 그래서 풀이 문장의 내용 낱말(두 글자 이상, 정해 둔 틀 낱말 '쉽게·말하면·회사·보고서·설명·뜻·의미' 등 제외)이 모두 인용 문단에 있어야 통과시킵니다. 재생성 2회 뒤에도 통과하지 못하면 풀이를 빼고 원문 인용과 "이 회사 보고서에 적힌 설명이에요"만 보입니다. 정의를 지어내지 않는 쪽으로 끝납니다.
  - **못 찾으면:** ai-server는 LLM 없이 `FINAL`(`ANSWERED`)로 정해진 안내 "'{용어}'는 등록된 용어가 없고, 이 보고서에서도 설명을 찾지 못했어요."를 돌려주고(정해진 요청과 같은 길, #631: 이 단계의 `model`·`calls` 없음, 근거 표시 없음), 비슷한 카드가 있으면 카드마다 `OPEN_GLOSSARY` 액션(최대 3개)을 붙이고, 비슷한 카드가 없으면 기초 카드(자산·매출·주식) 버튼을 붙여 다음에 물을 것을 안내합니다.
  - **backend 예외:** 지금 backend는 정해진 안내의 버튼이 값 확인에서 모두 빠지면 안내를 버리고 `NOT_FOUND`로 바꿉니다(`ChatResults`, 안내가 버튼을 가리키는 경우를 위해). 용어 안내는 버튼이 없어도 뜻이 통하므로, 이 채팅에서 `lookup_terms`가 실행돼 그 용어의 카드가 없었으면 버튼이 모두 빠져도 안내를 그대로 `ANSWERED`(`aiGenerated: false`)로 내보냅니다.
  - 근거 질문은 LLM(task `answer`)을 한 번 더 부릅니다. 이 작업의 모델(작업별 모델, ADR-0059)은 측정한 뒤 정합니다.
- **근거 종류:** ADR-0048의 7가지에 `GLOSSARY`를 더해 8가지로 둡니다. backend의 다시 확인은 같은 방법(이 채팅의 Tool 결과로 만든 근거 표에 있는가)입니다.
- **용어 질문 Workflow:** ai-server Workflow에 `TERM`을 더합니다(첫 Tool 고르기에서 LLM이 고르고 순서는 코드가 정함, #581과 같은 방식). 순서는 `lookup_terms` → 카드에 '이 회사 값을 찾을 곳'이 있으면 그 값 → 이 분석의 **문장 변경**에서 그 용어가 나온 문장을 찾는 `search_text_changes`(q=용어)입니다. 답은 '한 줄 뜻 → 쉬운 예시 → 이 회사에서는 → 확인할 곳' 순서로 씁니다.
  - 카드가 있는 용어의 사용 예는 문장 변경에서만 찾습니다(호출을 늘리지 않으려고). 못 찾으면 "이번에 바뀐 문장에서는 찾지 못했어요"라고 쓰고 원문 전체에 없다고 말하지 않습니다. 원문 전체 검색(근거 질문)은 카드가 없는 용어에만 씁니다.
  - 이 분석 기간의 값은 재무 계정 변화(`get_financial_changes`, 이 분석의 두 보고서)를 먼저 씁니다. 체크포인트(`get_checkpoints`)는 최근·전년 **사업보고서** 기준이라 이 분석의 보고서(예: 반기보고서)와 기간이 다를 수 있으므로, 쓸 때는 그 값의 보고서(`#V` 근거의 보고서 이름)를 문장에 함께 밝히고 이 분석 보고서의 값처럼 쓰지 않습니다.
  - 이 회사 근거가 하나도 없으면 '이 회사에서는' 칸을 빼고 그렇게 알립니다.
- 프롬프트를 고치므로 ai-server `PROMPT_VERSION`을 올립니다. 카드 내용을 바꾸는 것은 프롬프트 버전과 상관없습니다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 지금처럼 frontend `glossary.ts`에 두기 | Tool을 실행하는 backend가 읽을 수 없어 채팅 근거가 될 수 없습니다. 화면과 채팅에 사전이 둘로 갈립니다. |
| ai-server에 두기(주요 사건 기준표처럼) | Tool과 근거 표는 backend가 만듭니다(ADR-0044·0048). ai-server에 두면 backend가 다시 받아 와야 합니다. |
| DB 표로 두기 | 카드 수십 개를 고칠 관리 화면이 없고, 검토 기록을 PR로 남기는 편이 단순합니다. 많아지거나 운영 중 고쳐야 할 때 다시 봅니다. |
| LLM이 용어 뜻을 직접 쓰기 | 공시 용어를 추측하지 않는다는 규칙과 근거 규칙을 어깁니다. 틀린 정의를 막을 방법이 없습니다. |
| 카드만으로 공시 용어 대부분(150~200개)을 덮기 | 카드 작성과 사람 승인 부담이 크고, 회계 용어는 보고서 주석이 이미 회사 기준으로 설명하는 경우가 많습니다. 공식 자료를 자동으로 대조할 수 있는 것도 회계 용어(IFRS)뿐이었습니다(2026-11-06 확인). |
| 모든 용어를 보고서 설명으로만 답하기(카드 없음) | 유상증자·감사의견 같은 증권·공시 용어는 주석에 정의가 없고, 원문 문장이 어려워 초보자 풀이 품질이 들쭉날쭉합니다. 질문마다 LLM 호출이 하나 더 듭니다. |
| 외부 용어 사전 API·문장 그대로 쓰기 | 저작권과 이용 조건을 확인하지 않았고, 서비스 원칙(근거를 우리가 확인)에 맞추기 어렵습니다. |

## 결과

- 좋아지는 점: 화면과 채팅이 같은 카드를 씁니다. 초보자 답이 정의 한 줄이 아니라 예시와 이 회사 문장·값으로 이어집니다. 모든 문장에 근거가 남습니다.
- 감수하는 점: 핵심 카드 작성과 검토에 사람 시간이 듭니다. 카드가 없는 용어는 보고서 설명의 품질에 기대므로 풀이가 들쭉날쭉할 수 있고, 풀이 문장 검사는 낱말 대조라 뜻이 맞는지까지 보지 못해 원문 인용만 보이는 경우가 생기며, 근거 질문 LLM 호출이 하나 더 듭니다. 보고서에도 설명이 없으면 '등록된 용어가 없고 이 보고서에서도 찾지 못했어요'로 끝납니다. 화면이 카드를 받으려면 API 호출이 하나 늘어납니다.
- 지켜야 할 것
  - 카드에는 출처와 검토일이 있어야 내보냅니다.
  - 정의를 LLM이 만들지 않습니다.
  - 근거 종류를 더하거나 바꾸면 새 ADR로 정하고(채택된 ADR-0048의 결정 내용은 고치지 않고 README 목록의 상태만 '일부 보탬' 등으로 적음), api-spec `citations` 표를 함께 고칩니다. 이 ADR이 채택되면 ADR-0048 목록 줄에 'GLOSSARY는 ADR-0061'을 적습니다.

## 다시 볼 때

- 카드가 수백 개로 늘거나, 운영 중에 배포 없이 카드를 고쳐야 할 때(DB로 옮기기)
- 주요 사건 용어 풀이(ADR-0060)와 카드를 합칠 때
- 공식 용어 사전의 이용 조건이 확인돼 원문을 그대로 쓸 수 있을 때
