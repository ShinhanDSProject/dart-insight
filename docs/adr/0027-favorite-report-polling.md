# ADR-0027: 즐겨찾기 기업의 정기보고서 목록은 정해진 주기로 다시 받고, 새 보고서는 서버 안의 이벤트로 알린다

- 상태: 채택
- 결정한 날: 2026-10-26
- 관련: [#37](https://github.com/ShinhanDSProject/dart-insight/issues/37)(6.3), 선행 #27(4.1)·#36(6.2), [ADR-0003](0003-opendart-cache-in-backend-parsing-in-ai-server.md), 노션 결정 로그 [OpenDART 호출 한도 대응과 폴링 주기](https://app.notion.com/p/400b6afffc6f81528ad3da9eeafc0388)

## 맥락

- 6.3은 즐겨찾기 기업의 새 정기공시를 주기적으로 찾아, 이미 처리한 공시는 빼고 후속 작업(원문 수집·분석, 6.4 알림)에 넘겨야 한다. 받아 쓸 후속 기능은 아직 없다.
- ADR-0003은 기업별 정기보고서 목록을 저장한 지 `refresh-after`(기본 24시간, `ReportProperties.refreshAfter`)가 지나야 다시 받게 정했다. 이 규칙만 따르면 폴링 주기를 24시간보다 짧게 둘 수 없다.
- OpenDART 키는 팀이 함께 쓰고 하루 호출 한도가 있다(초과 시 `020`, `DART_RATE_LIMITED`). 폴링 한 번에 즐겨찾기된 기업 수만큼 목록 API를 부른다. 회원당 즐겨찾기는 최대 12곳이다(`FavoriteCompanyService.LIMIT`).
- 이미 받은 보고서는 `report.rcept_no` UNIQUE로 한 번만 저장되고, `ReportSyncService`가 새로 저장한 건수를 센다(4.1).
- 서버는 한 대로 띄운다.

## 결정

- 즐겨찾기된 기업(회원과 상관없이 중복 없는 `corp_code`)의 정기보고서 목록을 `app.reports.polling-interval`(기본 6시간)마다 `refresh-after`와 상관없이 다시 받는다. 즐겨찾기되지 않은 기업은 ADR-0003대로 둔다. 폴링은 `favorite.service.FavoriteReportPoller`의 `@Scheduled(fixedDelay)`이고, 서버 시작 직후가 아니라 한 주기가 지난 뒤 처음 돈다.
- 목록을 다시 받을 때 새로 저장한 접수번호만 "새 보고서"로 본다. 그 기업의 목록을 처음 받는 경우(`company.reports_fetched_at`이 비어 있던 경우)는 과거 보고서를 새 공시로 보지 않고 저장만 한다. 이미 저장된 접수번호는 다시 알리지 않는다.
- 새 보고서마다 Spring 이벤트 `FavoriteReportFound(corpCode, rceptNo)`를 발행한다. 후속 기능은 이 이벤트의 리스너로 붙인다. 별도 대기 테이블은 두지 않는다.
- 한 기업이 실패하면 기록하고 다음 기업으로 넘어간다. `DART_RATE_LIMITED`면 그 회차를 멈추고 다음 주기를 기다린다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| `refreshIfStale`을 그대로 불러 ADR-0003을 지킨다 | 실제 주기가 `refresh-after`(24시간)에 묶여 폴링 주기 설정이 의미가 없다 |
| 새 보고서를 대기 테이블에 '처리 전'으로 저장하고 후속 작업이 가져간다 | 재시작해도 잃지 않지만, 받아 쓸 기능이 아직 없는데 테이블·마이그레이션·상태 관리가 먼저 생긴다. 후속 기능을 만들 때 필요하면 바꾼다 |
| 찾자마자 원문(ZIP)까지 받는다 | 6.3의 범위를 넘고, 아무도 보지 않을 원문까지 받아 호출 한도를 더 쓴다 |

## 결과

- 좋아지는 점: 즐겨찾기 기업의 새 정기공시를 최대 한 주기 늦게 찾는다. DB 변경이 없고, 후속 기능은 리스너만 더하면 된다.
- 감수하는 점: 이벤트는 메모리에서만 전달되어, 리스너 처리 중 서버가 꺼지거나 리스너가 실패하면 그 공시는 다시 전달되지 않는다(리스너 실패는 ERROR로 기록하고 나머지 공시는 계속 알린다). 폴링이 아닌 화면 조회가 먼저 목록을 다시 받아 새 보고서를 저장하면 폴링은 그 보고서를 새 공시로 보지 않는다(즐겨찾기 기업은 폴링이 24시간보다 자주 받으므로 화면 조회가 먼저 받는 일은 드물다). 즐겨찾기 기업이 N곳이면 하루 `N × 24h / polling-interval`회 목록 API를 더 부른다.
- 지켜야 할 것: 새 공시를 받아 쓰는 기능은 폴링 코드를 고치지 말고 `FavoriteReportFound` 리스너로 붙인다. 폴링 주기는 설정으로만 바꾼다.

## 다시 볼 때

- 서버를 두 대 이상 띄울 때(폴링이 겹친다)
- 후속 기능이 공시를 잃으면 안 될 때(대기 테이블로 바꾼다)
- 결정 로그의 폴링 주기·호출 한도가 정해지거나, 즐겨찾기 기업이 늘어 하루 호출 한도에 가까워질 때
