# ADR-0010: 본문·표 변경은 ai-server에서 LLM 없이 규칙으로 찾는다

- 상태: 대체됨(ADR-0021)
- 결정한 날: 2026-10-22
- 관련: [PR #102](https://github.com/ShinhanDSProject/dart-insight/pull/102)(2.5), [PR #103](https://github.com/ShinhanDSProject/dart-insight/pull/103)(2.6), `ai-server/app/compare/text_diff.py`, `ai-server/app/compare/priority.py`, 노션 결정 로그 [공시 변화 평가 규칙과 중립·판단 유보 도입 여부](https://app.notion.com/p/400b6afffc6f8139ae35e8183960af19)(미결정)

## 맥락

- 사업보고서 두 개는 섹션 수백 개, 문단·표 수천 개입니다. 해마다 목차 번호와 제목이 조금씩 바뀌고, 숫자만 바뀐 표가 많습니다.
- 찾은 변경마다 정확한 원문 위치가 있어야 하고, 같은 입력에는 같은 결과가 나와야 결과를 재사용하고 검증할 수 있습니다.
- LLM으로 비교하면 비용이 크고, 결과가 매번 다르며, 위치를 지어낼 수 있습니다.

## 결정

- 문장·표 변경 탐지는 ai-server의 `text_diff.py`(`DIFF_VERSION`, 지금 `text-diff-1`)가 `difflib` 기반 규칙으로 합니다. LLM을 쓰지 않습니다.
  - 섹션은 제목에서 번호·공백·기호를 뺀 이름을 상위부터 이은 경로로 짝짓습니다. 같은 경로가 양쪽에 다른 수만큼 있으면 짝을 확정하지 않고 '검토 필요'로 남깁니다. 경로가 없으면 같은 상위 섹션 안에서 제목이 비슷한 섹션을 짝짓고, 이름이 바뀐 상위 섹션도 하위 섹션이 많이 짝지어지면 짝짓습니다.
  - 블록은 숫자를 가린 글로 자리를 맞춥니다. 숫자만 다르면 `numbers_only` 수정입니다. 맞지 않는 구간은 비슷한 블록끼리 수정으로, 나머지는 추가·삭제로 봅니다. 긴 글은 낱말 단위로 비교하고, 구간 하나의 비교 횟수에 상한을 둬 표가 많은 섹션도 빨리 끝납니다.
- backend가 저장한 두 원문 구조를 보내면, ai-server는 변경의 위치(섹션·블록 번호)만 돌려줍니다. 글은 backend가 저장된 원문에서 붙여 저장합니다.
- 확인할 순서(우선순위)도 ai-server가 규칙 점수로 매깁니다(`PRIORITY_VERSION`, 지금 `priority-1`). 결정 로그가 정해지기 전의 잠정 규칙이고, 투자 판단이 아니며, 짝을 정하지 못한 항목은 순위를 매기지 않습니다.
- LLM은 고른 변경의 요약에만 씁니다([ADR-0012](0012-grounded-summary.md)).

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 두 문서를 LLM에 주고 차이를 찾게 하기 | 비용이 크고 결과가 매번 다르며, 근거 위치를 지어낼 수 있습니다. 문서가 길어 한 번에 넣을 수도 없습니다. |
| 임베딩 유사도(Chroma)로 블록 짝짓기 | 숫자만 바뀐 표를 구분하지 못하고, 왜 짝지었는지 설명하기 어렵습니다. 의미 검색은 확장 기능에서 검토합니다. |
| 문서 전체를 줄 단위 diff | 목차가 조금만 밀려도 섹션 전체가 바뀐 것으로 나옵니다. |
| backend(Java)에서 비교하기 | 원문 구조와 텍스트 처리 규칙을 ai-server와 두 곳에서 맞춰야 합니다. |

## 결과

- 좋아지는 점: 같은 입력에 같은 결과가 나오고, 비용이 없으며, 모든 변경에 정확한 위치가 있습니다.
- 감수하는 점: 뜻은 같고 말만 바뀐 문장도 수정으로 나옵니다. 목차가 크게 바뀌면 '검토 필요'가 많아집니다. 비슷함 기준값(제목 0.8, 블록 0.5)은 실제 원문으로 더 조정해야 합니다.
- 지켜야 할 것: 결과가 달라지게 고치면 `DIFF_VERSION`·`PRIORITY_VERSION`과 backend `Analysis.CURRENT_VERSION`을 함께 올립니다([ADR-0014](0014-analysis-reuse-and-version.md)). 한쪽에만 있는 섹션은 '문서에서 빠짐'일 뿐 사업 종료로 해석하지 않습니다.

## 다시 볼 때

- 정답 자료(7.5)로 평가한 정확도가 낮을 때
- 결정 로그 '공시 변화 평가 규칙'이 정해질 때(우선순위 규칙 교체)
