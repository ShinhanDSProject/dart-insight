# ADR-0055: 비밀번호 재설정은 Gmail SMTP로 일회용 링크를 보내고, 링크로 바꾸면 이메일 소유가 확인된 것으로 본다

- 상태: 채택
- 결정한 날: 2026-11-05
- 관련: [#696](https://github.com/ShinhanDSProject/dart-insight/issues/696), [ADR-0019](0019-user-registration.md), [ADR-0040](0040-user-role-in-app-user.md), `docs/api-spec.md`(POST /api/password-resets, /api/password-reset-confirmations), `docs/erd.md`(password_reset_token)

## 맥락

- 일반 가입 회원이 비밀번호를 잊으면 되찾을 방법이 없습니다. backend에는 메일 발송 기능이 없습니다.
- 가입할 때 이메일 소유를 확인하지 않아 `local_credential.email_verified`가 늘 false입니다(ADR-0019). ADR-0040은 소유가 확인된 이메일만 관리자 대조에 쓰고, 이메일 소유 확인을 도입하면 다시 보기로 했습니다.
- 시연까지 시간이 짧고, 외부 서비스 신청·도메인 인증을 기다릴 여유가 없습니다. 비밀값은 `.env`·서버 환경변수에만 둡니다.
- 대표가 메일 발송 방식과 소유 확인 처리를 정했습니다(2026-11-05, #696).

## 결정

- 메일은 `spring-boot-starter-mail`의 `JavaMailSender`로 Gmail SMTP를 거쳐 보냅니다. 보내는 계정·앱 비밀번호는 `MAIL_USERNAME`·`MAIL_PASSWORD` 환경변수로만 받고, 원본은 노션 '공용 키 모음'에 둡니다. 메일 설정이 비어 있으면 보내지 않습니다. 로컬 개발자가 `PASSWORD_RESET_LOG_LINK=true`(기본 false)로 켰고 링크가 로컬 화면 주소(`localhost`·`127.0.0.1`)일 때만 서버 로그에 링크를 남기고, 그 밖에는 토큰이 로그에 남지 않게 경고만 남깁니다(`MailPasswordResetMailer`).
- 재설정 토큰은 32바이트 난수(base64url)이고 DB `password_reset_token`에는 SHA-256 해시만 둡니다. 30분 동안 한 번만 쓰고, 새로 요청하면 그 회원의 쓰지 않은 이전 토큰을 못 쓰게 합니다. 같은 회원은 1분 안에 다시 만들지 않습니다.
- 요청 API는 가입 여부와 상관없이 같은 응답(204)을 주고, 메일은 응답과 따로 보내 응답 시간으로도 가입 여부를 알 수 없게 합니다.
- 링크로 비밀번호를 바꾸면 그 메일함을 연 사람이 주인이므로 `email_verified`를 true로 바꾸고, 그 회원의 모든 Refresh Token을 폐기합니다. 흐름은 backend `auth` 패키지의 `PasswordResetService`(토큰·세션 폐기·메일)에 있고, 비밀번호 검사·해시·저장은 `user` 패키지의 `CredentialAuthenticationService`에 맡깁니다(auth → user 방향 유지).

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| AWS SES | 운영에 가깝지만 도메인 인증과 샌드박스 해제 신청을 기다려야 해 시연 일정 안에 끝내기 어렵습니다 |
| 메일 없이 서버 로그에만 링크를 남김 | 배포 서버에서 사용자가 링크를 받을 수 없어 기능이 되지 않습니다. 로컬 개발용으로만 남깁니다 |
| 가입할 때 이메일 인증을 먼저 도입 | 더 안전하지만 가입 흐름·화면·기존 회원 처리까지 바뀌어 작업이 두 배 이상입니다. 재설정 링크도 메일함 소유를 같은 방식으로 증명합니다 |
| 토큰 원문을 DB에 저장 | DB가 새면 바로 비밀번호를 바꿀 수 있습니다. Refresh Token(6.2)과 같이 해시만 둡니다 |

## 결과

- 좋아지는 점: 일반 가입 회원이 스스로 비밀번호를 되찾습니다. 비밀번호를 바꾼 계정은 이메일 소유가 확인돼, `ADMIN_EMAILS`에 있으면 일반 가입 계정도 다음 로그인부터 관리자가 됩니다(ADR-0040).
- 감수하는 점: Gmail 계정의 하루 발송 한도(약 500통)와 스팸함 분류에 기댑니다. 남의 이메일로 가입한 계정은 메일함 주인이 재설정해 가져갈 수 있습니다(의도한 동작).
- 지켜야 할 것: 토큰·비밀번호 원문·이메일을 로그에 남기지 않습니다(로컬 화면 주소일 때의 로그 링크만 예외). 메일 비밀번호를 저장소에 쓰지 않습니다.

## 다시 볼 때

- 하루 발송량이 Gmail 한도에 가까워질 때, 가입할 때 이메일 인증을 도입할 때, 서버를 여러 대 띄워 1분 다시 요청 막기를 공유해야 할 때.
