# ADR-0019: 질문 답변은 동기 호출로 하고, 후보는 backend가 낱말로 찾으며, 답은 인용을 검증한 뒤 저장한다

- 상태: 채택
- 결정한 날: 2026-10-24
- 관련: #218, #219, #220, 노션 기능 기획서 FS-5 '근거로 답하는 AI 질문하기', ADR-0012·0013·0015

## 맥락

- 사용자가 결과 화면에서 두 보고서에 대해 평소 말로 묻고 싶어 한다(FS-5). 분석 하나에 문장 변경이 1,000건이 넘어 탭·필터만으로는 찾기 어렵다.
- AGENTS.md AI 규칙: LLM은 ai-server의 한 모듈로만 부르고, 계산을 맡기지 않으며, 문장에는 저장된 원문 위치의 근거 ID가 있어야 하고, 검증 실패는 2회까지 다시 만든 뒤 '검토 필요'로 끝낸다. 투자 권유·예측 표현은 내보내기 전에 검사한다(ADR-0013).
- 원문은 이미 `document_block`에 문단 단위로 있고 근거 ID(`{접수번호}#B{블록}`)가 정해져 있다(ADR-0009). 벡터 검색(#148)은 아직 없다.
- 답 하나는 LLM 한 번(재생성 포함 최대 3번) 호출로 끝나 수 초 안에 끝난다.

## 결정

- **호출 방식**: `POST /api/analyses/{analysisId}/questions`는 동기 호출이다. 분석처럼 작업 ID를 두지 않는다. 완료된 분석에만 묻는다.
- **후보 찾기(backend)**: 질문에서 2자 이상 낱말을 뽑고 조사·의문 낱말을 뺀 뒤, 두 보고서의 문단(`PARAGRAPH`)에서 낱말이 많이 나오는 순으로 최대 6개를 고른다. 질문에 이 분석의 계정 이름(또는 `AccountAliases`)이 나오면 그 계정의 변화를 코드가 만든 사실 문장으로 함께 보낸다(LLM에 계산을 맡기지 않음). 후보도 사실도 없으면 ai-server를 부르지 않고 `NOT_FOUND`다.
- **답 만들기(ai-server `POST /internal/answers`)**
  - 매수·매도·목표주가·주가 전망을 묻는 질문은 규칙으로 걸러 LLM을 부르지 않고 `OUT_OF_SCOPE`다(`app/compliance`).
  - 질문은 `<question>`, 원문은 `<disclosure id>`, 사실은 `<fact ref>` 태그로 감싸 자료로만 쓴다. 질문 안의 지시는 따르지 않는다.
  - 검증: 근거 ID·사실 ref가 보낸 것이어야 하고 하나 이상 있어야 하며, 답의 숫자·크기 표현은 인용한 원문·사실에 있어야 한다. 원인 표현은 인용한 원문에도 원인 표현이 있을 때만 쓴다. 표현 검사(5.5)에 걸리면 답을 버린다. 실패하면 2회 다시 만들고 끝내 실패하면 `REVIEW_NEEDED`다.
- **저장**: 질문·상태·답·근거 ID·사실 계정·모델·프롬프트 버전·생성 시각·추적 ID를 `analysis_question`에, 호출 기록을 `llm_call`(task `answer`)에 저장한다. 질문은 사용자와 묶지 않는다.
- **인용**: 응답은 근거 ID를 보고서(이전·현재)·섹션·블록·인용 일부로 풀어 주고, 화면은 원문 탭의 그 블록으로 이동한다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 분석처럼 비동기 작업(작업 ID·폴링) | 한 번 호출로 수 초에 끝나 상태 화면이 오히려 느리게 느껴진다. 실패해도 다시 묻기 쉽다 |
| 후보 검색을 ai-server에서 | 원문 블록·계정 사전이 backend DB에 있다. 옮기는 일은 #146에서 다룬다 |
| 원문 전체를 LLM에 넣기 | 보고서 하나가 수십만 자라 비용·지연이 크고, 근거 확인이 어려워진다 |
| 범용 챗봇처럼 근거 없이 답 | 근거 위치 규칙(AGENTS.md)과 SC-2를 어긴다 |

## 결과

- 좋아지는 점: 사용자가 탭을 오가지 않고 묻고, 답의 문장마다 원문 위치로 간다. 기존 LLM 모듈·검증·표현 검사를 그대로 쓴다.
- 감수하는 점: 낱말 검색이라 다른 말로 쓴 문단을 놓칠 수 있다(찾지 못하면 그렇다고 말한다). 질문마다 LLM 비용이 든다.
- 지켜야 할 것: 답의 숫자는 코드가 만든 사실이나 인용 원문에 있어야 한다. 근거가 없으면 답하지 않는다. 투자 판단 질문은 LLM에 보내지 않는다.

## 다시 볼 때

- 벡터 검색(#148)이 들어올 때(후보 검색 교체), 질문 수 제한이나 비용 한도가 필요해질 때, 여러 턴 대화가 필요해질 때
