# ADR-0001: 구조 결정을 ADR로 기록한다

- 상태: 채택
- 결정한 날: 2026-10-22
- 관련: [이슈 #112](https://github.com/ShinhanDSProject/dart-insight/issues/112)

## 맥락

- M0~M2 동안 구조 결정(서비스 책임, 저장 방식, LLM 호출 방식, 결과 재사용 등)을 여러 번 내렸지만, 기록이 노션 개발 기준, `AGENTS.md`, 코드 주석, PR 본문에 흩어져 있습니다.
- 개발 기준과 `AGENTS.md`에는 '지킬 규칙'만 있고, 왜 그렇게 정했는지와 검토하고 버린 방법은 없습니다.
- 노션 결정 로그는 기획·범위·판단 기준을 다룹니다. 구조 결정을 같은 곳에 두면 코드와 떨어져 PR에서 함께 검토되지 않습니다.
- 6명이 4주 동안 개발하고 AI 코딩 도구를 함께 씁니다. 이유를 모르는 사람이나 도구가 규칙을 바꾸거나, 이미 끝난 논의를 다시 할 위험이 있습니다. 발표(M3) 때도 설계 이유를 설명해야 합니다.

## 결정

- 구조에 영향을 주는 결정은 `docs/adr/`에 ADR로 남깁니다. 남길 것과 남기지 않을 것, 쓰는 법은 [`docs/adr/README.md`](README.md)가 기준입니다.
- 형식은 맥락·결정·검토한 다른 방법·결과·다시 볼 때의 짧은 문서입니다([`docs/templates/adr.md`](../templates/adr.md)).
- ADR은 결정을 구현하는 PR에 함께 넣어 코드와 같이 검토합니다.
- 채택된 ADR은 고치지 않고, 결정이 바뀌면 새 ADR로 대체합니다.
- M0~M2에서 이미 내린 구조 결정은 소급해 기록합니다(ADR-0002~0014).
- `AGENTS.md`와 PR 템플릿에 ADR 확인 항목을 둡니다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 노션 결정 로그에 구조 결정도 함께 남기기 | 코드와 떨어져 있어 PR에서 함께 검토하고 고치기 어렵습니다. 노션을 열 수 없는 AI 도구가 읽지 못합니다. |
| 개발 기준·`AGENTS.md`에 이유까지 적기 | 규칙 문서가 길어져 읽히지 않고, 버린 방법과 결정한 때를 남기기 어렵습니다. |
| 코드 주석과 PR 본문으로 충분하다고 보기 | 여러 파일·서비스에 걸친 결정은 한곳에서 찾을 수 없고, 병합된 PR 본문은 다시 찾아보지 않습니다. |

## 결과

- 좋아지는 점: 규칙의 이유를 한곳에서 찾을 수 있습니다. 새 팀원·AI 도구·발표 준비에 쓸 수 있습니다.
- 감수하는 점: 구조를 바꾸는 PR마다 문서를 하나 더 씁니다. 대상을 구조 결정으로 좁혀 부담을 줄입니다.
- 지켜야 할 것: 채택된 ADR과 다르게 만들어야 하면 먼저 새 ADR을 쓰고 사람에게 확인받습니다.

## 다시 볼 때

- ADR이 PR마다 형식적으로 붙거나 아무도 읽지 않으면, 대상 기준을 다시 좁힙니다.
