# ADR-0056: 사용자가 요청한 새 분석도 하루 한도로 세고, 한도 초과 응답의 Retry-After는 공통 예외 처리에서 붙인다

- 상태: 채택
- 결정한 날: 2026-11-05
- 관련: [ADR-0054](0054-llm-daily-quota.md)(질문·채팅 한도, 이 결정이 범위를 넓힘), [ADR-0014](0014-analysis-reuse-and-version.md)(분석 재사용), [ADR-0031](0031-favorite-report-auto-analysis-notification.md)(관심 기업 자동 분석), [ADR-0037](0037-season-change-ranking.md)(시즌 순위 분석), `backend/src/main/java/com/dartinsight/llmquota/`

## 맥락

- ADR-0054는 질문·에이전트 채팅만 셌습니다. 새 분석(`POST /api/analyses`)도 로그인 없이 부를 수 있고, 같은 조건의 결과를 다시 쓰지 못하면 OpenDART 원문 두 개를 받고 요약 LLM을 부릅니다(로컬 측정 요약 1회 평균 11.6초, 입력 약 2,300 토큰). 다른 보고서 쌍을 계속 요청하면 비용과 OpenDART 호출 한도가 함께 줄어듭니다.
- 같은 `request()`를 관심 기업 자동 분석(ADR-0031)과 시즌 순위(ADR-0037)도 부릅니다. 이 둘은 사용자 요청이 아니라 정해진 수만큼 도는 작업입니다.
- 분석은 서비스 안에서 '다시 쓸지·비교할 수 있는지'를 본 뒤에야 새로 만들지 알 수 있어, ADR-0054의 경로 인터셉터로는 '새로 만들 때만' 셀 수 없습니다. 인터셉터는 `Retry-After`를 직접 붙였지만 서비스에서 던진 예외에는 붙일 곳이 없습니다.

## 결정

- 사용자가 `POST /api/analyses`로 요청한 분석은 기존 결과를 다시 쓰지 않고 **새로 만들 때만** 저장 직전에 셉니다. 재사용(200·202 `reused: true`)과 비교 불가(422)는 세지 않습니다. 관심 기업 자동 분석·시즌 순위는 세지 않습니다(호출자를 넘기지 않음).
- 질문과 따로 셉니다(`app.llm-quota`의 `analysis-anonymous-per-day` 기본 10, `analysis-member-per-day` 30, `analysis-total-per-day` 500). 호출자 기준(회원 ID, 아니면 클라이언트 IP)과 하루 경계(한국 시간 0시), 넘으면 429 `AI_QUOTA_EXCEEDED`는 ADR-0054와 같고, 메시지만 '분석'으로 씁니다.
- `ApiException`이 다시 시도까지 남은 초를 가질 수 있게 하고, `GlobalExceptionHandler`가 그 값을 `Retry-After`로 붙입니다. 질문 인터셉터도 이 방식으로 바꿉니다(응답 모양 `{code,message,traceId,errors}`는 그대로).
- 질문이든 분석이든 서비스 전체 한도에 그날 처음 닿으면 WARN 로그를 한 번 남깁니다(운영자가 상한 도달을 알 수 있게). 4xx는 INFO 이하라는 LOG-1의 예외입니다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 분석 요청도 경로 인터셉터로 세기 | 재사용·비교 불가까지 세어, 이미 있는 결과를 여는 사람도 한도가 줄어듦 |
| 질문과 같은 횟수로 세기 | 분석 한 건이 질문보다 비싸고(원문 두 개·요약), 메시지가 '질문 n회'로 맞지 않음 |
| 새 분석을 로그인 필수로 | 비로그인 핵심 흐름(SC-1)이 막힘 |

## 결과

- 좋아지는 점: 공개 서버에서 새 분석에 드는 LLM·OpenDART 호출에도 상한이 생김. 이미 분석된 결과는 누구나 제한 없이 엶.
- 감수하는 점: ADR-0054와 같음(재시작 시 초기화, NAT 뒤 공유, 서버 한 대 전제).
- 지켜야 할 것: 사용자 요청으로 새 분석을 만드는 코드를 더하면 호출자를 넘겨 세게 한다. 시스템 작업은 넘기지 않는다.

## 다시 볼 때

- ADR-0054와 같음(서버 두 대 이상, 유료 요금제 크레딧).
