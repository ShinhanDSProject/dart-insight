# ADR-0067: 문장 변화 탭은 '이 기간에 한 일과 앞으로의 영향'을 보이고, 전체 변경 목록은 별도 탭으로 옮긴다

- 상태: 제안
- 결정한 날: 2026-11-10
- 관련: [ADR-0039](0039-company-outlook.md)(전망·계획의 동기 생성·저장 방식), [ADR-0050](0050-text-events-after-analysis.md)·[ADR-0051](0051-text-event-candidate-rules.md)(주요 사건과 후보 규칙), [ADR-0060](0060-event-signal-and-sentences.md)(신호 기준표), [ADR-0065](0065-event-future-impact-path-table.md)(앞으로의 영향), [ADR-0066](0066-event-period-disclosure-input.md)(사이 기간 공시 입력, 제안)

## 맥락

- 사용자 결정(2026-11-10): 문장 변화 탭이 바뀐 문장을 모두 보여 줘 복잡하고 보기 불편하다. 탭은 두 보고서 사이에 회사가 한 활동·사업·사건 중 유의미한 것만 보이고, 사건마다 앞으로 회사에 줄 수 있는 영향과 그 영향이 긍정적인지 부정적인지를 보여야 한다. 쓰는 사람은 투자자(주식뿐 아니라 사모펀드·재무적 투자 포함)만이 아니라 면접을 준비하는 학생, 협업·거래를 검토하는 회사도 있다. 전체 변경 목록은 없애지 않고 탭에서 따로 뺀다. 지금까지 만든 사건 카드 구조에 얽매이지 않고 처음부터 생각한다.
- 지금의 주요 사건(ADR-0050·0060)은 후보 변경을 모두 사건으로 묶으려 해서 기업마다 사건이 20~30개이고, 묶이지 않은 변경도 함께 보인다. 사건 문장은 공시의 의미·신호 이유 두 칸이고 앞으로의 영향(ADR-0065)은 아직 만들지 않았다. 기능을 켜려면 별도 실행 상태(`text_event_run`)와 긴 대기(1,200초)가 필요하다.
- 기업 화면의 전망·계획(ADR-0039)은 원문 후보를 코드가 고르고, LLM이 근거 인용과 함께 항목을 만들고, 코드가 검증해 저장하는 동기 방식이다. 같은 입력이면 다시 만들지 않는다.

## 결정

### 화면

- 결과 화면 탭 '문장 변화'(`?tab=activity`)는 새 화면 '이 기간에 한 일과 앞으로의 영향'이다. 기존 전체 변경 목록은 탭 '전체 변경'(`?tab=text`, 주소와 쿼리 그대로)으로 옮긴다. 요약·채팅·원문 탭에서 특정 변경으로 가는 링크는 지금처럼 `?tab=text`로 간다.
- 새 화면 순서: 한 문단 요약 → 숫자로 본 이 기간(재무 수치, 코드 계산) → 쓰임 고르기(전체·투자·취업·면접·협업·거래) → 유의미한 활동·사건 카드(최대 12개).
- 카드: 분야, 신호(긍정·주의·보류, 코드), 제목, 무엇을 했나(AI 요지 + 원문 인용과 근거 위치), 앞으로의 영향(아래 세 종류의 줄), '원문 비교' 링크(전체 변경 탭의 그 변경).

### 만들기

- ai-server 새 모듈 `app/activity/`(task `period_activity`, 프롬프트 `period-activity-1`), 내부 API `POST /internal/period-activities`. LLM은 `app.llm.LlmClient`로만 부른다.
- 입력은 backend가 보낸다: 회사·보고서 이름, 두 보고서의 분류된 문장 변경 중 MAIN·UNPAIRED·HEADING 묶음(ADR-0051과 같은 묶음). ai-server가 ADR-0051의 후보 규칙(`is_candidate`)과 길이 제한으로 줄이고, 변경의 이전·이번 글을 각각 근거 원문 하나로 만든다. 근거 ID는 저장된 원문 위치 `{접수번호}#B{블록 번호}`다. 사이 기간 수시공시는 ADR-0066이 채택된 뒤에 넣는다.
- LLM이 하는 일: 후보 중 투자·취업·협업에 유의미한 활동만 골라 분야(정한 값), 쓰임(정한 값, 하나 이상), 제목, 요지, 인용(원문 그대로)을 쓰고, 신호 기준표(ADR-0060)의 사건 종류·변화를 고른다. 앞으로의 영향은 줄마다 종류를 고른다.
  - `DISCLOSED` 회사가 밝힌 계획·전망: 원문 인용이 근거다.
  - `OUTLOOK` AI 전망: 조건형 한두 문장. 전제는 원문 인용(근거 ID 필수)이고, 결론은 '~이면 ~쪽으로 작용할 수 있어요'처럼 조건과 가능성 꼬리가 있어야 한다. 줄마다 좋은 면(`GOOD`)·나쁜 면(`BAD`)을 고를 수 있다(AGENTS.md 신호 이유의 좋은 면·나쁜 면과 같은 범위).
  - `CHECK` 다음에 확인할 점: 숫자 없는 한 문장.
  - ADR-0065의 경로 기준표는 검토된 틀이 아직 없어(검토 기록 없는 틀은 건너뜀) 이 화면에서 쓰지 않는다. 기준표가 생기면 `OUTLOOK`보다 먼저 쓴다.
- 코드가 하는 일:
  - 신호: AI가 고른 종류·변화를 신호 기준표로 판정한다. 근거 ID가 그 카드의 인용이 아니면 보류(`EVIDENCE_NOT_CONFIRMED`), 표에 없으면 보류(`NO_CRITERIA`), 해소·철회 같은 `explicitOnly` 변화는 이번 보고서 인용일 때만 인정한다. LLM은 신호를 정하지 않는다.
  - 검증: 근거 ID가 보낸 원문인지, 인용이 그 원문의 부분 문자열인지, AI 문장의 숫자·크기 표현이 인용에 있는지(`app.llm.grounding`), 표현 검사(`app.compliance`, `expr-1`), AI 전망의 조건형·단정 금지·주가 낱말(주가·주식 가격·시가총액·목표가) 금지. 어기면 문제를 알려 최대 2회 다시 만든다. 그래도 어긋난 카드는 빼고 뺀 수를 남긴다. 쓸 수 있는 카드가 없으면 `REVIEW_NEEDED`다.
  - 표시: 'AI 생성', 'AI 전망 · 공시 사실 아님', '투자 판단이나 추천이 아니에요' 안내를 코드가 붙인다. 숫자 영역(숫자로 본 이 기간)은 재무 비교 결과를 그대로 쓴다.
- backend: `GET /api/analyses/{analysisId}/activities`. 저장된 결과(분석·프롬프트 버전마다 하나, 새 테이블 `period_activity`, `V53`)가 있으면 그대로, 없으면 그 요청 안에서 만들어 저장한다(ADR-0039와 같은 동기 방식, 처음엔 수십 초). LLM 호출 기록은 `llm_call`(task `period_activity`)에 남긴다. 분석이 완료되지 않았으면 409 `ANALYSIS_NOT_READY`, 문장 비교를 못 했거나 후보가 없으면 `NOT_AVAILABLE`.
- fake 제공자: 입력만으로 검증을 통과하는 결과를 만든다(신호는 보류, 영향은 확인할 점만). 모델 이름 `fake-model`로 실제 결과와 구분된다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
| --- | --- |
| 주요 사건(ADR-0050·0060)에 영향 칸을 더하기 | 후보를 모두 사건으로 묶는 방식이라 카드가 많고, 사용자가 '사건끼리 묶는 방식이 아니라 유의미한 것만'을 원했습니다. 별도 실행 상태와 긴 대기도 그대로 남습니다. 기준표와 후보 규칙은 다시 씁니다. |
| 분석 작업 안에서 함께 만들기 | 분석 완료가 LLM 호출만큼 늦어지고, 이미 끝난 분석에는 생기지 않습니다. ADR-0039처럼 처음 열 때 만들고 저장합니다. |
| 비동기 작업(작업 ID·상태 조회) | 한 번의 LLM 호출이라 ADR-0039와 같은 동기로 충분합니다. 화면을 떠나면 요청만 취소하고 서버는 끝까지 만들어 저장합니다. |
| 영향 방향(긍정·부정)을 LLM이 정하기 | AGENTS.md는 신호를 코드 기준표로 정하게 합니다. 일관성과 측정이 어렵습니다. 기준표를 그대로 씁니다. |
| 전체 변경 목록을 지우기 | 원문 전체가 무엇이 바뀌었는지 보려는 사람이 있어 별도 탭으로 둡니다. |

## 결과

- 문장 변화 탭은 카드 12개 이하로 줄고, 투자·취업·협업 쓰임으로 거를 수 있다. 영향과 신호가 함께 보인다.
- 앞으로의 영향 중 일반적인 경로 문장(ADR-0065 경로 기준표)은 아직 없어서, 회사가 밝힌 계획이 없는 카드는 AI 전망과 확인할 점만 보인다. 정확도는 사람이 꼽은 사건 목록(`ai-server/tests/fixtures/events/`)으로 따로 재야 한다.
- 주요 사건 기능(`TEXT_EVENTS_ENABLED`)은 그대로 두지만 새 탭에는 보이지 않는다. 전체 변경 탭 위쪽에 남는다.
- 사이 기간 수시공시를 넣지 않아 그 기간의 활동 중 보고서에 적히지 않은 것은 빠진다(ADR-0066).
