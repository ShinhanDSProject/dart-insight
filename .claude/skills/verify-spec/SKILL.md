# 수용 기준 검증하기

노션 '개발 워크플로우'의 7단계(검증·완료)를 돕는 절차입니다. 결과는 기획서 11절 표의 **초안**이고, 화면 확인과 최종 판정은 사람이 합니다.

## 먼저 확인할 것

1. 기획서를 읽습니다([기능 기획서 DB](https://app.notion.com/p/e1f20d0ae0584b6ba85e2b80906814d1)). 6절(수용 기준), 10절(작업 쪼개기)의 이슈 목록이 필요합니다. 상태가 '개발 중'이나 '검증'이 아니면 아직 검증할 때가 아니라고 알려 줍니다.
2. 10절의 이슈와 그 이슈를 닫은 PR을 찾습니다(`gh issue view`, `gh pr list --search`). PR이 병합되지 않은 이슈가 있으면 그 이슈가 다루는 AC는 '⏳ 확인 전'으로 둡니다. 증빙으로 적는 PR 번호는 그 테스트를 실제로 더한 PR인지 `git log --follow`로 확인합니다.

## AC마다 할 일

- 그 AC를 확인하는 증빙을 찾습니다.
  - 자동 테스트: 테스트 파일과 테스트 이름. 이름이나 단언문이 정말 그 AC를 확인하는지 읽어 봅니다. 파일 이름만 보고 맞다고 하지 않습니다.
  - 직접 실행: 로컬에서 테스트를 돌릴 수 있으면 돌리고(명령은 `AGENTS.md` 서비스별 명령), 실행한 명령과 결과를 적습니다.
  - 화면·실제 원문: 사람이 해야 하는 확인이면 확인 순서(화면 경로, 쓸 기업·접수번호, 기대 결과)를 적어 줍니다.
- 결과를 적습니다.
  - `✅ 자동 테스트`: 테스트가 AC를 확인하고, CI나 로컬에서 통과한 것을 봤을 때만.
  - `✅ API 테스트(화면 확인 전)`: AC가 화면 동작인데 백엔드 API 테스트만 있을 때.
  - `✅ 화면 확인`: 사람이 확인했다고 알려 준 경우만. 누가, 언제를 함께 적습니다.
  - `❌ 실패`: 기대와 다른 결과. 무엇이 다른지와 재현 방법.
  - `⏳ 확인 전`: 증빙이 없거나 실행하지 못한 경우.
- 실제로 실행하거나 보지 않은 것을 통과로 적지 않습니다. 테스트용 자료로만 확인했으면 그렇게 적습니다.

## 내보내기

1. 11절 표 초안(AC · 결과 · 증빙 · 확인한 사람·날짜)과 '수용 기준 통과' 속성 값(예: `7/9 (자동 테스트 기준)`).
2. SC 기여: 이 기능의 AC가 어느 성공 기준(SC)을 확인하는지.
3. 판정 제안: 모든 AC가 ✅면 '완료', 아니면 남은 AC와 필요한 일. ❌가 있으면 버그 이슈 초안을 함께 제안합니다(만드는 것은 사용자가 요청할 때만).
4. 노션 도구가 있고 사용자가 원하면 기획서 11절과 속성을 채웁니다. 상태를 '완료'로 바꾸는 것은 사람이 합니다.
