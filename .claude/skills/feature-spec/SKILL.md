# 기능 기획서 초안 쓰기

노션 '개발 워크플로우'의 1~3단계(기능 기획, 사용자 흐름, 화면)를 돕는 절차입니다. 결과는 기획서 **초안**이고, 담당자가 읽고 고친 뒤 노션 '기능 기획서' DB에 둡니다. 형식은 같은 폴더의 [template.md](template.md)입니다.

## 먼저 확인할 것

1. 저장소 `AGENTS.md`를 따릅니다. 공시 용어와 OpenDART 코드·필드는 추측하지 않습니다.
2. 사용자에게 받은 것이 무엇인지 정리합니다: 누구를 위해, 무엇을, 왜. 셋 중 비어 있는 것이 있으면 초안을 쓰기 전에 묻습니다.
3. 범위를 확인합니다. 노션을 읽을 수 있으면 [성공 기준(SC)](https://app.notion.com/p/401b6afffc6f810bbb4bff6e32ec9172), [MVP 요구사항·범위](https://app.notion.com/p/3ffb6afffc6f80c0ad55ce2ffba2d7f6), [결정 로그](https://app.notion.com/p/4ce942f6c0bc4d77a490ceeda26d4a18)를 읽습니다. 읽을 수 없으면 사용자에게 근거 SC와 관련 결정을 물어봅니다.
   - 어느 성공 기준(SC)에도 기여하지 않거나 MVP 범위에서 뺀 기능(예: 로그인·회원가입, 결재·게시)이면 기획서를 쓰지 않습니다. 대신 결정 로그 항목 초안(무엇을 정해야 하나, 선택지, 영향)을 쓰고 멈춥니다.
4. 이미 있는 것을 읽습니다: 관련 코드, `docs/api-spec.md`, `docs/erd.md`, `docs/adr/`, 노션 [와이어프레임](https://app.notion.com/p/c0f540f74d92496c9c20f23867afc15a)의 화면 ID. 새로 만들 필요가 없는 것을 새로 만들지 않습니다.

## 쓰는 법

- [template.md](template.md)의 절 순서를 그대로 지킵니다. 1~8절과 9절 초안을 채우고, 10절(작업 쪼개기)과 11절(검증)은 비워 둡니다(확정 뒤에 `/spec-to-issues`, `/verify-spec`이 채움).
- **수용 기준(AC)**: 표의 '이런 상황에서 / 이렇게 하면 / 이렇게 된다'로, 사람이 화면이나 테스트로 확인할 수 있게 씁니다. 정상 흐름 하나에 예외(자료 없음, 실패, 비교 불가, 권한·제한) AC를 함께 둡니다. "잘 동작한다", "빠르다" 같은 문장은 쓰지 않고, 숫자 목표가 필요하면 '열린 질문'에 둡니다.
- **요구사항(R)**과 AC는 서로 연결합니다(각 AC의 '관련 R'). R이 하나도 AC에 걸리지 않으면 AC가 빠진 것입니다.
- **사용자 흐름**: Mermaid `flowchart LR`로 정상 흐름과 예외 흐름(점선)을 그립니다. 전체 서비스 흐름에서 어느 단계인지 적습니다.
- **화면**: 기존 화면이면 W-ID를 쓰고, 새 화면이면 'W-?? (새 화면 필요)'로 적고 구성과 로딩·빈 화면·오류·제한 상태를 말로 나열합니다. 새 화면은 사람이 [Figma 파일](https://www.figma.com/design/1LurlBehXtoSjipfsAAsUv/%EC%8B%A0%ED%95%9C-2%EC%B0%A8-%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8?node-id=5-2)에 그립니다. 화면 디자인 값(색·간격)은 쓰지 않습니다(Figma와 `frontend/design-system.md`가 기준).
- **설계·결정**: 구조 결정이 필요해 보이면 `docs/adr/README.md`의 '무엇을 ADR로 남기나'로 판단해 'ADR 필요: (무엇)'으로 적습니다. API·DB가 바뀌면 바뀔 엔드포인트·테이블을 적습니다.
- 모르는 것은 지어내지 않습니다. 사용자 조사 결과, 숫자 목표, 일정, 담당자, 공시 사실은 근거가 없으면 '열린 질문'에 둡니다.
- 문장은 짧고 평이하게, 팀 문서처럼 '~합니다/~한다'로 씁니다. 투자 권유·가치판단 표현을 쓰지 않습니다.

## 내보내기

- 기본은 마크다운 초안을 대화에 보여 주는 것입니다. 사용자가 노션에 바로 만들어 달라고 했고 노션 도구가 연결돼 있으면, [기능 기획서 DB](https://app.notion.com/p/e1f20d0ae0584b6ba85e2b80906814d1)에 새 행(상태 '기획 중')을 만들고 링크를 알려 줍니다. 템플릿 행을 고치지 않습니다.
- 마지막에 '사람이 확인할 것'을 3줄 이내로 적습니다: 근거 SC가 맞는지, AC가 확인 가능한지, 열린 질문.
- 커밋·이슈·PR은 사용자가 요청하지 않으면 만들지 않습니다.
